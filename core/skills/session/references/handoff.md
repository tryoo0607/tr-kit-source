# HandOff 규격

세션·작업을 이관할 때 이어받는 쪽이 원래 대화 없이도 바로 진행할 수 있게 하는 공통 형식이다. 제품별 session resume·clear·새 세션 생성 방법은 `SKILL.md`에 합성된 target capability가 정한다.

## 먼저 — 소비자로 구분

| 종류 | 소비자 | 정본 | 별도 문서 |
|---|---|---|---|
| 그대로 재개 | 같은 대화 | 호스트 세션 기록 | 없음 |
| 롤오버 | 새 세션의 나 | 프로젝트 `state/<slug>.md` | 없음 |
| 작업 위임 | 다른 세션·사람·환경 | configured handoff repository | 있음 |

롤오버와 위임을 같은 템플릿으로 만들지 않는다. 롤오버에는 이미 프로젝트 맥락이 있지만 위임을 받는 쪽에는 맥락이 없다.

## 롤오버

`state/<slug>.md`가 곧 인계 문서다. 다음 항목이 최신이면 별도 HandOff를 만들지 않는다.

- 현재 단계와 완료된 milestone
- 이미 확정된 결정과 근거
- 아직 열린 문제와 바로 다음 행동
- 실행한 검증과 다시 확인할 검증
- 핵심 파일 포인터

새 세션 시작 지시는 다음만 포함한다.

```text
<state 절대경로>만 먼저 읽고 이어간다.

- 이전 대화를 resume/fork할지 독립 세션을 쓸지는 target session capability를 따른다.
- 긴 roadmap·전체 transcript를 처음부터 읽지 않는다.
- 현재 단계와 바로 다음 작업을 한 문단으로 적는다.
- 실행해야 할 검증을 적는다.
```

## 작업 위임

### 필수 절

| 절 | 무엇을 답하나 |
|---|---|
| 요청 | 받는 쪽이 무엇을 해야 하나 |
| 왜 | 왜 이 작업이 생겼나 |
| 절차 | 어떤 순서로 실행하나 |
| 범위 밖 | 무엇은 이 작업이 아닌가 |
| 수용조건 | 어디까지 되면 완료인가 |

전제·주의·먼저 확인·결정·포인터는 실제 내용이 있을 때만 추가한다.

```markdown
# HandOff — <slug>

| 메타 | 값 |
|---|---|
| 종류 | 작업 위임 |
| 날짜 | <YYYY-MM-DD> |
| 보내는 머신 | <값> |
| 받는 머신 | <값 또는 무관> |
| 프로젝트 | <repo> |
| 상태 | 미착수 / 진행중 |

## 1. 요청
<첫 문단만 읽어도 할 일을 알 수 있게>

## 2. 왜
<이 일이 생긴 배경 한 문단>

## 3. 전제 *(있으면)*
<모르면 틀리는 사실만>

## 4. 절차
1. [ ] <실행 가능한 단계>
2. [ ] <다음 단계>

## 5. ⚠️ 주의 *(있으면)*
| 무엇 | 왜 |
|---|---|

## 6. ❓ 먼저 확인 *(있으면)*
- <선행 조건과 확인 방법>

## 7. ⛔ 범위 밖
| 무엇 | 왜 |
|---|---|

## 8. ✅ 수용조건
1. <관찰 가능한 완료 조건>
2. <검증 명령 또는 결과>

## 9. 결정 *(있으면)*
| 결정 | 근거 |
|---|---|

## 10. 포인터 *(있으면)*
| 자원 | 왜 |
|---|---|
```

## 작성 규칙

- 위임의 첫 절은 “무엇을 하던 중”이 아니라 “무엇을 해달라”다.
- 주의는 작업 안에서 조심할 것, 범위 밖은 작업 자체가 아닌 것이다.
- 먼저 확인에는 질문만 적지 말고 가능한 확인 방법을 붙인다.
- 되돌리기 어려운 단계에는 실행 직전 확인을 절차에 넣는다.
- 명령이 포함된 HandOff를 채팅으로 전달할 때는 바깥을 백틱 4개로 감싸 중첩 code fence가 깨지지 않게 한다.
- 실행 명령에는 장식용 이모지를 넣지 않는다.
- 모르는 값은 추측하지 않고 `확인 필요`로 적는다.
- 파일을 만들었다면 경로뿐 아니라 받는 쪽이 읽는 방법도 알린다.

## 저장 경계

- 롤오버: 프로젝트 `_local-docs/state/`
- 작업 위임: `public.repositories.handoffs` 아래 사용자가 지정한 안전한 상대경로. 미설정이면 `_local-docs/out/<slug>/`에 둔다.
- configured handoff repository에 썼으면 같은 내용을 `_local-docs/out/`에 중복 저장하지 않는다.
- 외부 repo로 push하거나 완료 파일을 이동하는 동작은 실행 전 확인한다.
