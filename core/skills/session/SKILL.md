# session

세션의 컨텍스트를 바꾸거나 작업을 다른 주체에게 넘긴다. **같은 작업의 롤오버**와 **다른 주체에 대한 위임**을 구분한다.

## 공통 판단

| 종류 | 읽는 쪽 | 정본 | 핵심 |
|---|---|---|---|
| 그대로 재개 | 같은 대화 | 호스트 세션 기록 | 압축하지 않고 이어감 |
| 롤오버 | 내가 새 세션에서 다시 | `state/<slug>.md` | 단계·결정·미결 |
| 작업 위임 | 다른 세션·사람·환경 | configured handoff repository | 범위 밖·수용조건 |

- 롤오버는 별도 handoff 문서를 만들지 않는다. 최신 state가 인계 정본이다.
- 위임만 별도 HandOff 산출물이며, 형식은 `references/handoff.md`를 따른다.
- 전체 transcript나 roadmap을 통째로 넘기지 않고 state 또는 HandOff 한 파일부터 읽게 한다.
- 종료·새 세션 생성·외부 전송처럼 호스트나 사용자 권한이 필요한 행동은 임의로 실행하지 않는다.

## 호스트 세션 제어

{{slot:session.control}}

## 롤오버 절차

1. 현재 milestone까지 마무리한다.
2. `state/<slug>.md`의 단계·결정·미결·다음 검증을 최신화한다.
3. 새 세션에서 읽을 state 한 파일과 바로 다음 행동을 지정한다.
4. 호스트별 세션 제어 방식으로 새 컨텍스트를 시작한다.
5. 새 세션은 지정된 state부터 읽고 필요한 소스만 추가로 연다.

## 위임

- 받는 쪽은 원래 대화 맥락이 없다고 가정한다.
- 요청·왜·절차·범위 밖·수용조건을 반드시 포함한다.
- 환경 간 전달은 `public.repositories.handoffs`와 안전한 상대경로로 연결한다. 미설정이면 `profile-setup`으로 연결하거나 프로젝트 local-docs에만 산출한다.
- 파일 이동과 push는 외부 변경 정책을 따른다.

## 경계

이 스킬은 인계 내용과 세션 전환 판단을 담당한다. 제품별 장애 진단·resume·clear·새 세션 조작은 위 호스트 capability의 범위다.
