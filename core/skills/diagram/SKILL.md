# diagram

코드·시스템·데이터를 **Mermaid로 시각화**한다. 분석·설계·토폴로지 전반에서 쓰며, 재편집 가능한 Mermaid 텍스트를 정본으로 유지한다.

## 타입

| 타입 | 언제 |
|---|---|
| `flowchart` | 흐름·의사결정·파이프라인 |
| `sequenceDiagram` | 시간축 상호작용·호출 순서 |
| `classDiagram` | 클래스·타입·도메인 모델 관계 |
| `erDiagram` | 데이터 모델·엔티티 관계 |
| `stateDiagram-v2` | 상태·라이프사이클 전이 |
| C4(`flowchart`) | 시스템 컨텍스트·컨테이너·컴포넌트·토폴로지 |

## 원칙

- 목적과 독자를 먼저 확인하고 알맞은 타입을 고른다.
- 한 다이어그램에는 한 수준과 목적만 담는다. 과밀하면 분리한다.
- Mermaid `.mmd` 또는 코드블록을 정본으로 남겨 git diff가 가능하게 한다.
- 구현과 구조가 달라지면 도식을 갱신하거나 최신이 아님을 표시한다.

## 작성 절차

1. 목적·독자를 확인한다.
2. 표현할 관계에 맞는 다이어그램 타입을 고른다.
3. 핵심 노드와 관계만 그린다.
4. 타깃 환경에 맞게 렌더하고 Mermaid 정본을 저장한다.

## 정본 위치

| 무엇 | 위치 |
|---|---|
| 현행 분석 | 프로젝트 로컬 문서의 `explore/` |
| 목표 구조·설계 | 프로젝트 로컬 문서의 `design/` |
| 살아있는 토폴로지 | 프로젝트 로컬 문서의 `architecture.mmd` |
| 도메인 전용 구성도 | 해당 도메인이 정한 정본 위치 |

## 경계

- 다이어그램 작성·유지는 여기서 담당한다.
- 아키텍처 결정·패턴 선택은 `architecture`가 담당한다.
- 상세 문법·스니펫·안티패턴이 필요하면 [references/diagram-types.md](references/diagram-types.md)를 읽는다.
