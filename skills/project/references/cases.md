# 검증 케이스 원장 (`_local-docs/cases/`)

*"이 입력·조건에서 이 결과여야 한다"*를 축적해 **재발을 막는다.**

## 케이스는 유닛테스트 재료보다 넓다

QA/이슈 리포트 · 버그 재현 조건 · 요구사항 검증 · 엣지/경계 입력이 전부 케이스다.
붙여넣은 리포트에서 **입력 · 조건 · 기대** 셋을 추출해 케이스화한다.

🔑 **자동화는 선택이다** — QA 케이스 다수는 수동 시나리오로 남는 게 맞다. 무리해서 자동화하면 flaky만 는다.

## 저장

```
_local-docs/cases/<group>/<slug>.md      # group = 기능·영역 (auth, monitoring …)
```

**케이스 = 파일 하나** → 기록에서 직접 링크할 수 있다(`cases/auth/role-permission.md`).

> **INDEX 파일을 두지 않는다** — 손으로 쓰는 목록은 안 갱신되면 거짓말을 한다. 추리기는 **태그 grep**으로 한다. (`_local-docs` 스키마 L9와 같은 근거)

## 파일 형식

```markdown
| 등록 | 2026-07-21 |
| 상태 | manual |
| 출처 | qa |
| 기준소스 | main@a1b2c3d |
| 태그 | auth · permission · bug |
| 관련 | issue#42 |

## 증상
## 재현      ← 입력 · 조건 · 환경
## 기대
```

- 🔑 **태그가 없으면 추릴 수 없다** = 원장이 죽는다.
- `automated`면 `관련`에 **테스트 경로를 링크**한다 — 구현체는 repo, 기록은 여기. 저장소는 하나다.
- 파생 케이스는 원 케이스를 링크한다.

## 상태

```
open ─┬─▶ automated   repo 테스트로 승격 (링크)   ─┐
      └─▶ manual      수동 회귀로 유지            ├─▶ retired  (무효화, 이력만)
```

활성 회귀 = `automated` + `manual`.

## 연산

| | |
|---|---|
| **add** | 문제·리포트를 케이스 파일로. 리포트를 붙여넣으면 입력·조건·기대를 추출한다 |
| **filter** | 태그·상태로 관련 케이스만 추린다. **전부 부르지 않는다** |
| **expand** | 한 케이스에서 파생 입력을 도출 → 새 케이스 |
| **apply** | 변경 **완료 후** 관련 케이스 + 파생을 검증 |

### expand — 무엇을 파생시키나

등가분할 · 경계값(min/max/off-by-one) · null·빈값 · 타입 변형 · **인접 엔드포인트·역할**.

> 예: `ORGANIZATION` 필드가 null이었다면 `USER`·`GROUP`도. 한 권한이 샜다면 인접 권한도.

이 목록이 그대로 **테이블 드리븐 테스트의 행**이 된다(`test` 스킬).

### apply — 기록까지가 한 벌

검증 결과를 **작업 기록에 남긴다** — 어떤 케이스를 봤고 결과가 무엇인지(pass/skip/fail), 케이스 파일 링크와 함께. 케이스 쪽 역링크는 선택.

## 연계

`review`가 리뷰 대상과 겹치는 케이스를 체크리스트에 넣고, `test`가 `open`을 `automated`로 승격시키고, 버그를 파면 새 케이스가 등록된다.
