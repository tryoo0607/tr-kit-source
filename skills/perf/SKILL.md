# perf

성능을 **측정 기반으로** 점검·최적화한다. 핵심 원칙 = **측정 먼저, 추측 최적화 금지.**

## 흐름 (report-first)
```
① 측정(프로파일·벤치) → ② 병목 특정 → ③ 최적화 제안(리포트) → 확인 → ④ 적용 → ⑤ 재측정
```
- **측정 없이 안 고친다.** 병목 아닌 곳 최적화 = 낭비(가독성만 깎임, 조기 최적화 경계).
- 제안엔 **트레이드오프**(가독성·복잡도 vs 이득) 명시. 미미한 이득이면 하지 말라고 권함.

## 다루는 것
- **측정**: CPU/메모리 프로파일, 벤치마크, 타이밍, 할당.
- **병목 유형**: 핫패스·N+1 쿼리·불필요 반복·비효율 자료구조·과도한 I/O·할당·직렬화.
- **최적화 기법**: 알고리즘/자료구조·캐싱·쿼리 개선·배치·동시성.
- 상세 = `references/profiling.md`.

## 툴 소프트의존
- 프로파일러 감지(`pprof`·`py-spy`·`perf`·flamegraph·언어 벤치) → 없으면 **권장·설치 질문**(유저 실행). repo 벤치 있으면 그것.

## 회귀 방지
- 개선을 **벤치 기준치로 `project`에 성능 케이스** 등록 → 이후 성능 회귀 감시.

## 경계
- 측정·병목분석·제안=code-perf / **최적화 구현=「수행」** / 벤치 검증=`test` / 회귀=`project`.
- 🔑 **①과 ⑤의 수치를 작업 기록에 남긴다** — 목표 · before · after · delta 표로. 안 남기면 *"빨라진 것 같다"*로 끝난다.
