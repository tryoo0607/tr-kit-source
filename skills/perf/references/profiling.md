# 성능 측정·최적화 (방법 지침)

**측정 → 병목 → (제안·확인) → 적용 → 재측정.** 추측으로 고치지 않는다.

## 1. 목표 설정
- 무엇이 느린가·기준(목표 지연/처리량)·측정 환경(현실적 데이터/부하). "빠르게"만으론 부족 → 수치 목표.

## 2. 측정
- **프로파일**: CPU(어디서 시간 쓰나)·메모리(할당·누수). 툴 감지(`pprof`·`py-spy`·`perf`·flamegraph) → 없으면 권장·설치 질문(유저 실행).
- **벤치마크**: repo 벤치 프레임워크로 재현 가능한 수치. before 수치 확보(비교 기준).
- 실제와 가까운 입력·규모로. 마이크로벤치 함정 주의.

## 3. 병목 특정
- 프로파일 상위(핫패스)부터. 흔한 것: N+1 쿼리·불필요 반복·O(n²)·비효율 자료구조·과도 I/O·직렬화·락 경합·할당.
- **80/20**: 가장 큰 병목 하나부터. 나머지는 이득 확인 후.

## 4. 최적화 (제안 → 확인 → 적용)
- 기법: 알고리즘/자료구조 개선·캐싱(무효화 주의)·쿼리 인덱스/배치·지연/스트리밍·동시성.
- **트레이드오프 명시**: 이득 vs 가독성·복잡도·메모리. 미미하면 **하지 않기**.
- 적용은 「수행」(작은 단위·동작보존은 refactor 규율).

## 5. 재측정
- 같은 벤치로 after 수치 → **실제 개선 확인**(안 되면 되돌림).
- 개선을 `project`에 **성능 케이스(벤치 기준치)** 로 → 회귀 감시.

## 원칙
- 조기 최적화·과최적화 경계. 가독성 희생은 측정된 이득이 클 때만.
