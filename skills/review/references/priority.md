# 리뷰 우선순위 (WATCHDOG)

> 구 `advisor`에서. 「판정하기」 profile의 점검이 쓴다.

## 1. `WATCHDOG.md` — 이 repo에서 특히 볼 것

리뷰어가 **미리 읽고 갈 우선순위**를 프로젝트가 적어두는 파일. repo 루트나 `_local-docs/`에.

```markdown
# WATCHDOG — <프로젝트> 리뷰 우선순위
## 특히 볼 것
- <이 코드베이스의 흔한 함정·회귀 지점>
## 위험 API / 패턴
- <오용 잦은 함수·안티패턴>
## 완료 기준 (성급한 done 방지)
- <"완료"라 하려면 반드시: 테스트 X · 검증 Y>
```

**있으면 우선 참조**한다. 없으면 일반 렌즈만으로 본다.

> 값어치는 **세 번째 절**에 있다 — *"무엇을 해야 완료인가"*를 프로젝트가 미리 못박아두면 성급한 done을 사람이 매번 잡지 않아도 된다.

## 2. 온디맨드 (기본)

*"비판적으로 봐줘"* → 「점검」의 `ask(N)` 서브에게 **reviewer + devil's advocate 렌즈 + 위 우선순위**를 주고 최근 diff·작업을 입력 → **severity별 조언**(nit / concern / blocker).

on-track이면 **"이상 없음"이라고 말한다** — 없는 지적을 지어내지 않는다.

## 3. 옵션: 상시 Stop 훅 (기본 OFF)

매 턴 종료 시 **self-review 리마인더**를 주입한다. 2차 모델을 부르지 않는 경량판이다.

```bash
export TR_ADVISOR=on     # 미설정 = off. 등록돼 있어도 조용히 exit 0
```
+ `{{HOST_SETTINGS}}`의 `Stop` 훅에 `scripts/advisor-nudge.sh`를 등록한다(설치 경로에 맞게).

- **자동 배선하지 않는다** — 모든 세션에 매 턴 훅을 강요하지 않는다.
- ⚠️ **노이즈**: 큰 작업엔 유용하지만 잡담엔 성가시다. **평소 off, 집중 작업 세션에만 on.** 대부분은 온디맨드로 충분하다.
- **비차단** — 응답을 막지 않는다. (기록 강제 `Stop` 훅과는 별개다. 그건 막는다)

## 왜 경량인가

원형(omp Advisor)은 **별도 모델이 매 턴 트랜스크립트를 리뷰하며 라이브로 개입**한다. {{PRODUCT}}에선 스트림을 끊을 수 없고 비용도 크다. 그래서 셋으로 나눠 이식했다:

| 원형 | 여기 |
|---|---|
| 유저 옹호 · 성급완료 견제 · 안 본 각도 | **렌즈로** (`backbone/references/ask-n.md`) |
| 매 턴 트리거 | **Stop 훅**으로 근사 (경량 self-review) |
| 진짜 2차 관점 | **온디맨드 서브** — 비용을 낼 때만 |
