# 리뷰 차원 · severity · 출력

odin:review가 없을 때의 fallback 체크리스트 + 공통 출력 규격.

## 리뷰 차원 (우선순위 순)
| 차원 | 뭘 보나 |
|---|---|
| **correctness** | 버그·엣지케이스·널/경계·경쟁조건·오류처리 누락. 의도대로 동작하나 |
| **보안** | secret/자격증명 하드코딩, 입력검증, injection, 권한, 민감정보 로깅 |
| **설계/구조** | 책임분리·결합도·중복(DRY)·추상화 적정·인터페이스 |
| **테스트** | 커버리지·엣지케이스 테스트·회귀 방지(→ case-registry 연계) |
| **가독성** | 네이밍·복잡도·주석 필요/과다·매직넘버 |
| **성능** | 불필요 반복·N+1·자료구조 선택·핫패스 (과최적화 경계) |
| **컨벤션** | 프로젝트 스타일·커밋/PR 규약·린트 준수 (code-git 참조) |

## severity
| 등급 | 뜻 | 처리 |
|---|---|---|
| **blocker** | 머지 불가 (버그·secret·데이터손실) | 반드시 수정 |
| **major** | 곧 문제 (설계결함·미처리 케이스) | 수정 강권 |
| **minor** | 개선 권장 | 재량 |
| **nit** | 취향·사소 | 선택 |

## 출력 형식
severity 높은 순으로:
```
[blocker] path/file.go:42 — <문제>
  근거: <왜 문제인지, 재현/영향>
  제안: <어떻게 고칠지>
```
- **근거 없는 지적 금지.** 재현/영향 또는 규칙 위반을 명시.
- 좋은 점도 한두 줄(과도한 칭찬 X).
- 확신 낮으면 "확인 필요"로 표시(단정 금지).

## 원칙
- 문제 없으면 "없음"이라 말한다(억지 findings 금지).
- 수정 **적용은 안 함**(제안까지). 사용자/「수행」가 반영.
