# convention

**"우리는 이렇게 쓴다"의 홈.** 이름 · 코드 스타일 · 문서 형식 — 셋 다 *"어떻게 쓸까"*라는 같은 질문이다.

> **repo 관례가 항상 이긴다.** 여기 있는 건 repo에 관례가 없을 때의 기본값이다.

## 이름

**후보 여러 개 + 근거 + 추천 1개**로 낸다. 최종 선택은 사용자.

| | |
|---|---|
| 원칙 | **명확 > 간결 > 일관.** 애매하면 길어도 명확 우선 |
| 피할 것 | 헷갈리는 축약(`tmp2`) · 모호어(`data`·`manager`) · 중복 접두 |
| 쓸 것 | **도메인 용어** (팀·코드베이스가 쓰는 말) |

| 대상 | 관례 |
|---|---|
| 코드 식별자 | **언어 관례**(camel/snake/Pascal) |
| 파일 · 스킬 | **kebab-case**, 소문자 |
| repo · 플러그인 | 그 repo의 관례 |
| 커밋 | **Conventional** (`feat:` `fix:` …) — 상세는 `git` |
| 프로젝트 | `~/projects/<repo>` |

**출력:** 후보 3~5개(각각 한 줄 근거 + 트레이드오프) → **⭐ 추천 1개를 맨 위에**.
기존 이름 검토 요청이면: 문제(모호·비관례·오해) → 대안.

## 코드 스타일 규칙

> ⬜ **정의된 언어별 규칙이 없다.** 규칙이 쌓일 자리이지, 지어내는 곳이 아니다.

규칙은 **내가 정하거나 repo 관례에서 발견될 때** 추가한다.

### 어디 두나 — 3층

| 층 | 성격 | 어디 |
|---|---|---|
| **전역 항상참** | 매번 참인 한 줄 (커밋 형식 · 응답 언어) | 플러그인 `{{AGENT_FILE}}` |
| **언어/도메인별** | Go 에러처리 · React 훅 등 | 🔑 **여기 `references/<lang>.md`** (필요 시 생성) |
| **프로젝트 특정** | 이 repo만의 규칙 | repo `AGENTS.md` |

추가할 때 **출처를 명시한다** — 내가 정한 건지, repo 관례에서 관찰한 건지.

## 문서 작성 관례

> 🔑 **산출물 문서는 요청 있을 때만 만든다** (전역 정책). 여기 있는 건 *만들 때 어떻게 쓰나*이다.

상세 = `references/docs.md`

| 대상 | 요지 |
|---|---|
| docstring · 주석 | 공개 API · 복잡 로직 · 비직관 결정에만. **왜/제약** 위주 |
| README | 무엇인지 한 줄 · 설치/실행 · 기본 사용 · 링크. **실행 가능한 예제** 우선 |
| API 문서 | 가능하면 코드·스키마에서 **생성**(OpenAPI·godoc) |

## 경계

| 일 | 어디 |
|---|---|
| 커밋 컨벤션 상세 | `git` |
| 강제(자동 검사) | 린트 · `secrets` |
| 아키텍처 개요 문서 | `architecture` · 도식은 `diagram` |
| 설계·이력 문서 | `_local-docs` (여긴 **repo에 커밋되는 문서**) |
