# 문서 작성 관례

> 🔑 **요청 있을 때만 만든다**(전역 정책). 여기는 *만들 때 어떻게 쓰나*.

repo 기존 문서 스타일·툴을 먼저 보고 맞춘다.

## docstring / 코드 주석
- **대상**: 공개 API·복잡 로직·비직관 결정. private·자명한 코드는 최소.
- **내용**: 무엇(요약) + **왜/제약/주의**(의도·엣지·부작용). 시그니처가 말하는 걸 반복 X.
- **툴 관례**: 언어 표준(godoc·JSDoc·docstring(PEP257)·KDoc 등) 형식 따름.
- 코드와 **함께 갱신**(변경 시 주석도).

## README / 사용 가이드
- 구성(있는 것 위주, 억지 X): 무엇인지 한 줄 · 설치/실행 · 기본 사용 · 설정 · 링크(상세).
- **실행 가능한 예제** 우선. 최신성 유지(명령·경로 실제와 일치).

## API 문서
- 엔드포인트/함수: 목적 · 입력(파라미터·타입) · 출력 · 에러 · 예시.
- 가능하면 코드/스키마에서 **생성**(OpenAPI·godoc 등) → 수기 중복 최소.

## 아키텍처 개요 (요청 시)
- 고수준 컴포넌트·흐름. 다이어그램은 `diagram`와 연계(Mermaid 정본=git).

## 갱신·부채
- 코드 변경 PR에서 관련 문서 동반 갱신. 낡은 문서 발견 시 표시.
- 자동 대량 생성 지양 — 필요한 곳에만.
