# 유닛·통합 테스트 (인프로세스)

방침이지 정답 코드가 아니다. **구체 문법은 repo의 기존 테스트를 보고 맞춘다.**

## 종류

| 종류 | 언제 | 요지 |
|---|---|---|
| **유닛** | 함수/모듈 하나 | 빠르고 격리. 의존은 대역(mock/stub) |
| **통합** | 여러 부분 연동 | 실제 경계(DB·API) 포함. **계약**을 검증한다 |

## 여러 입력 한 번에

같은 검증을 **입력·기대만 바꿔 표로** 만든다 (파라미터화 / 테이블 드리븐).

```
[ (ORGANIZATION, 채워짐), (USER, 채워짐), (GROUP, 채워짐), (빈그룹, 채워짐) ]
```

케이스 원장의 **expand**(등가분할 · 경계 · 인접 타입/역할)를 그대로 표의 행으로 옮긴다.

## 실행

**관련 테스트만 좁혀 실행**해 빠른 피드백을 받고, 그 다음 전체를 돌린다.

실패하면 먼저 가른다 — **테스트가 틀렸나, 코드가 틀렸나.**

## 케이스 승격

`_local-docs/cases/`의 `open` 케이스를 테스트로 만들면:

1. 케이스 항목 `상태: automated`
2. `관련`에 테스트 경로 링크

자동화 부담이 큰 것은 `manual`로 남겨둔다. **무리해서 자동화하면 flaky만 는다.**
