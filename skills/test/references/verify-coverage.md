# 검증 커버리지 추적 — "무엇을 봤고 무엇이 남았나"

기능 개발·리팩터 후 **어떤 케이스가 있었고 그게 검증됐는지**를 한 화면에서 추적한다.
자동으로 커버되는 것과 **사람 눈으로 볼 것**을 한 자리에 합치는 게 요점이다.

> 출처: 회사 세션(o11y-manager)이 실제 대형 리팩터 검증에서 굴려보고 보낸 패턴 명세
> 과거 리팩터 검증에서 **방법론만 흡수했다** — 구/신 대조 러너는 **폐기**했다(아래 §도구는 만들지 않는다).

## 언제 쓰나

- 리팩터로 **구/신 응답이 같아야 하는데** 케이스가 많을 때
- *"다 봤나?"* 에 답을 못 하겠을 때 — 세어야 하는데 셀 기준이 없을 때
- 자동 테스트가 **못 덮는 부분**을 사람이 봐야 하는데, 그 목록이 흩어져 있을 때

⛔ 테스트 몇 개 짜면 끝나는 규모엔 쓰지 않는다. **추적할 게 많을 때만** 값이 있다.

## 🔑 ① 정본에 앵커한다 — 완전성이 구조적으로 보장되게

체크리스트를 **손으로 적지 않는다.** 권위 있는 **서빙 표면**에서 뽑는다.

| 대상 | 정본 |
|---|---|
| HTTP API | OpenAPI 스펙 · 라우터 정의 |
| 스키마 | 마이그레이션 · 모델 정의 |
| 화면 | 라우트 테이블 |

**정본에서 항목을 빼면 체크리스트에서도 사라진다** → 누락이 구조적으로 불가능해진다.
⚠️ **프론트만 보고 만들면 구멍이 남는다** — 화면에 안 걸린 엔드포인트가 빠진다.

## ② 화면 우선으로 묶는다

그룹핑 축은 **내부 전략이 아니라 실제 UI 메뉴 계층**이다.

```
행 제목  = method + path
부제     = 화면명
그룹     = 메뉴 계층 (프론트 소스에서 도출)
```

사람이 눈으로 볼 목록이라 **사람이 아는 순서**여야 한다. 내부 모듈 구조로 묶으면 못 읽는다.

## 🔑 ③ `verify` / `locked` — 그룹핑과 **독립된 축**

각 항목은 둘 중 하나다.

| 값 | 뜻 |
|---|---|
| `verify` | 체크 대상 |
| `locked` | **의도적 제외** — 쓰기 작업 · 외부 의존 · 화면 없음 |

⚠️ **제외를 목록에서 지우지 않는다.** 지우면 *"안 본 것"* 과 *"안 보기로 한 것"* 이 구분되지 않는다.
축을 분리해 **배지로 남긴다** — 왜 제외인지가 같이 보여야 한다.

## ④ 2층으로 검증한다

| 층 | 무엇 | 덮는 것 |
|---|---|---|
| **L1 골든마스터** | 쿼리문자열·변환기 출력 **스냅샷** (유닛, DB 무관) | 로직 · 변환 규칙 |
| **L2 런타임 대조** | 구/신 인스턴스에 **같은 동결 백엔드**로 동일 요청 → **응답 바이트 비교** | 골든이 못 덮는 **실데이터·변환 계층** |

L1만으론 부족하다 — 실데이터가 들어와야 드러나는 게 있다.
L2를 하려면 **양쪽이 같은 백엔드를 봐야** 한다. 백엔드가 다르면 차이가 회귀인지 데이터인지 못 가른다.

### 대조할 때 고정할 것

바이트 비교라 **매번 달라지는 값이 있으면 전부 실패**한다.

- **시간 파라미터는 절대값으로 고정** — 상대시간(`now-1h`)을 쓰면 매 호출 달라진다
- **변동 키는 scrub** — timestamp · requestId · 세션ID 등
- 인증은 **형식만** 맞춘다

> 🔑 **양쪽이 똑같이 실패하면 회귀가 아니다.** 환경 탓 500 은 구/신 동일 여부로 자동 판별된다.

## 산출 — 한 파일로 남긴다

**검증은 증적이다.** 무엇을 봤고 무엇이 남았는지가 **파일로** 남아야 한다.

만드는 방법은 이미 kit 에 있다 — **작도·발행은 도식 규칙({{VIZ}})**, 자체완결 HTML 은 `prototype`.
여기선 **그것만으로는 안 나오는 세 가지**를 규율로 박는다.

### ① 체크 상태는 남아야 한다 — `localStorage`

사람이 손으로 체크한 것이 **다시 열었을 때 남아 있어야** 한다. 안 남으면 두 번 본다.

### 🔑 ② 저장 키에 **버전을 박는다**

```
KEY = "<검사이름>:v3"      ← 체크리스트가 바뀌면 v4
```

⚠️ **이게 없으면 조용히 거짓말을 한다.** 항목이 추가·삭제·재정렬되면
**옛 체크가 엉뚱한 행에 붙어** *"봤다"* 고 표시된다 — 안 본 것을 봤다고 하는 게 제일 나쁜 실패다.
정본이 바뀌면 **키를 올려 옛 체크를 버린다.**

### ③ **"미확인"을 뽑아낼 수 있어야** 한다

진행률만 보이면 *"뭘 봐야 하지"* 에 답이 안 된다. **남은 항목을 목록으로** 낼 수 있어야
그걸 들고 다음 작업을 한다.

> 🔻 **생성기는 만들지 않았다** (2026-08-16). 위 셋은 **만들 때 지킬 규율**이지 도구가 아니다.
> 실제 생성기가 필요해지면 `remote-flow` 의 뷰어와 **호스팅·렌더 인프라가 같으므로**
> 거기서 같이 본다 — 따로 만들면 비슷한 뷰어가 둘이 된다.

## 케이스 원장과 이어진다

`_local-docs/cases/` 의 수동(`open`) 케이스가 **이 체크리스트의 `verify` 행**이 된다.
테스트로 승격되면 `automated` 로 바뀌고, 여기선 자동 커버 항목으로 표시된다.
→ 원장 관리 자체는 `project`.

## ⛔ 런타임 대조 **도구는 만들지 않는다** (2026-08-16 폐기)

원 제안엔 구/신 서버에 같은 요청을 던져 **응답 바이트를 비교하는 러너**가 있었다.
**폐기했다** — 위 ④의 L2 는 *"이렇게 대조한다"* 는 **방법**으로만 남는다.

| 왜 | |
|---|---|
| **적용처 0** | 실측 — 개인 프로젝트에 OpenAPI **0건**, 구/신 인스턴스를 동시에 띄울 대상이 없다 |
| 실물이 없다 | 구현은 회사 로컬에만 있고 반출 안 함 — **처음부터 다시 만들어야 한다** |

🔑 **쓰지 않을 도구를 만들지 않는다.** 손으로 유지해야 하는 것은 결국 안 유지된다(`dist/` 사례).
실제로 대조가 필요해지면 **그때 ④를 보고 만든다.**
