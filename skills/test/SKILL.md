# test

코드가 제대로 도는지 **자동으로 확인한다.**

## 🔑 먼저 — 갈림선은 "앱을 띄우나"

| | 무엇 | 상세 |
|---|---|---|
| **유닛·통합** | 인프로세스. 빠르고 격리 | `references/unit.md` |
| **E2E** | **앱을 실제로 띄워** 사용자 흐름 검증. 느리고 flaky하니 **규율이 다르다** | `references/e2e.md` |

앱을 안 띄우면 유닛·통합이다. 이 한 문장이 전부다.

## repo 관례가 이긴다

어떤 프레임워크·러너·디렉토리·네이밍을 쓰는지 **먼저 확인하고 같은 결로** 작성한다. 새 도구 도입은 근거 있을 때만.

감지 힌트: `playwright.config.*` · `cypress.config.*` · `.maestro/` · `androidTest/` · `wdio.conf.*` · `package.json`의 `test:e2e`.

## 공통 원칙

- **하나의 동작**을 검증한다 — 테스트명이 무엇을 보장하는지 드러나게.
- **엣지·실패 경로**를 넣는다 — null·경계값·에러·권한. 「정의」에서 짚은 것들.
- **결정적으로** — 시간·랜덤·순서 의존 제거. flaky 금지.
- 과도한 mock·구현 세부 결합 지양 — 리팩터에 안 깨지게.
- **여러 입력은 파라미터화**(테이블 드리븐)로 한 번에.

## 실데이터로 돌려봐야 하면

**원본을 건드리지 않는 절차** = `references/real-data.md`.
read-only 로 뜨고 → **throwaway 에 적재** → 거기서 놀고 → 버린다. 복제본도 운영 데이터 취급.

## 케이스가 많아 "다 봤나"에 답을 못 하겠으면

**검증 커버리지 추적** = `references/verify-coverage.md`.
정본(OpenAPI·라우터)에 앵커해 **누락을 구조적으로 막고**, 자동 커버분과 **사람이 볼 것**을 한 자리에 둔다.
리팩터 구/신 대조(골든마스터 + 응답 바이트 비교)도 거기 있다.

⛔ 테스트 몇 개로 끝나는 규모엔 안 쓴다 — **추적할 게 많을 때만**.

## 케이스 원장과의 관계

`_local-docs/cases/`의 수동(`open`) 케이스를 **자동으로 승격**하는 손이다.
테스트로 만들면 케이스 상태를 `automated`로 바꾸고 테스트 경로를 링크한다.
자동화 부담이 큰 것(복잡한 수동 시나리오)은 무리하지 말고 `manual`로 둔다.

> 케이스 원장 관리 자체 = `project`

## 경계

| 일 | 어디 |
|---|---|
| 구현 · 실패 원인 추적 | **「수행」** — 테스트가 틀렸나 코드가 틀렸나부터 가른다 |
| 테스트 방법론 (TDD·타입 주도·계약) | `architecture` |
| 케이스 원장 | `project` |
| CI 레인 구성 | `ci` (E2E는 **별도 레인**) |
| 커밋 | `git` · 리뷰 = `review` |
| FE 프로토타입 | `frontend` — **E2E 대상이 아니다**(throwaway) |

**소프트위임:** `odin:tests-adversarial`(실패경로·경계 하드닝) · `odin:tests-purge-unneeded`(무용 테스트 정리)가 있으면 활용, 없으면 references 기본.
