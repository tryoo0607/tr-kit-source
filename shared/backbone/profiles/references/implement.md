# 구현 지침

> `make.md`·`fix.md`의 「수행」.


요구가 명확해진 뒤(`requirements.md`) 코드를 작성한다.

## 원칙
- **기존 패턴 존중**: 주변 코드의 네이밍·구조·에러처리·컨벤션을 먼저 읽고 **같은 결로** 작성. 새 스타일 도입은 근거 있을 때만.
- **작은 단위**: 한 번에 한 논리 변경. 커밋 단위와 맞춤(`git` atomic).
- **엣지 처리**: `requirements`에서 짚은 null·경계·실패 경로를 코드에 반영.
- **읽히는 코드**: 주변 코드 밀도에 맞춘 주석·네이밍. 과한 추상화·조기 최적화 지양.

## 접근 (강제 X — 상황별)
- 기본은 상황·기존 코드에 맞춤. 방법론은 **odin 소프트의존**:
  - test-first가 맞는 곳 → test-driven(먼저 `test` 소환).
  - 타입/계약이 중요한 곳 → type-driven / design-by-contract.
- 확신 없으면 작은 단위로 만들고 **`review`·`test`로 검증**.

## 마무리
- 변경이 요구·수용기준을 만족하는지 자기점검.
- 결과·결정은 project `exec`에 기록, 검증한 케이스는 `project`에 반영(상태 갱신).
- 커밋은 `git`(커밋 전 secret 등 점검), 리뷰는 `review`.
