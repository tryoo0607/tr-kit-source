## 확장 5축 (질문 넓히기 — "옆"이 최우선)
| 축 | 방향 | N+1 예 |
|---|---|---|
| 아래(기저) | 왜 존재하나 | 지연로딩 → 프록시 → 바이트코드 조작 |
| **옆(동형)** ⭐ | 같은 구조 다른 데 | GraphQL N+1(DataLoader) · MSA fan-out · REST chatty API |
| 위(일반원리) | 한 단계 추상 | "지연 평가 = 편의 대신 비용을 예측 불가능하게" |
| 반대 | 저긴 왜 덜? | Go+sqlc는 쿼리 명시라 N+1 덜 생김 |
| 역사 | 왜 이 설계 | JPA = EJB 엔티티빈에 대한 반작용 |

**"옆"이 최우선** — 전이 가능한 패턴을 만드는 축 = "개발 이해"의 실체에 가장 가깝다.

## 재현 실험 (선택 — 심화 끝단, 30분 이내)
정의: **성공을 재현하는 게 아니라, 문제를 일부러 터뜨리고 예측과 어긋난 지점을 찾는 것.**
1. **예측을 숫자로** 적는다.
2. **실제로 돌려서 센다.**
3. **어긋난 지점**을 본다.
- {{AGENT}}가 만들어 줄 것: **예측 질문 3개 + 최소 셋업(코드/설정) + 세는 법.**
- 튜토리얼 따라하기·토이프로젝트와 구분 — 둘 다 **예측이 없어서** 안 남는다.

## 3줄 기록 (실측 있을 때만)
```
2026-08-09 · N+1
예측: EAGER로 바꾸면 1번 나올 것
실측: 11번 (EAGER여도 N+1). batch_fetch_size 켜니 2번
어긋난 지점: JPQL이 글로벌 페치 전략을 무시한다는 걸 몰랐음
```
**실측 숫자 없으면 기록하지 않는다** — 기록이 또 "생성된 문서"가 되면 원래 병(안 팜)으로 회귀.
