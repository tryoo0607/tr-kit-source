# 되살리기

**깨진 걸 복구한다** — 장애대응 · 서비스 다운 · 데이터 접근 불가.

| | |
|---|---|
| **단계** | 진입 → 정의(진단) → **[수행 ⇄ 점검]** → 마무리(포스트모템) (**계획 스킵**) |
| **임계** | **매우 높음** — 급하니 거의 안 묻는다 |
| **점검 관점 (N=2)** | 복구됐나 · 재발 방지 |
| **수행 `runner`** | `inline` |

## 독트린

**단계가 다르면 기준도 달라야 한다.** 둘은 서로 다른 자리에 걸린다.

### ① 넘겨짚지 말고 **판정 트리거로 확정한다** — 「정의」

증상 하나로 단정하지 않는다. **여러 신호가 동시에** 맞아야 그 장애다. 그리고 **물리 계층이 무죄인지부터 배제**한다.

> 예(스토리지 세션 장애): *"전송 오류 반복 + export 대상 비어 있음 + 물리 저장소 용량 정상"* 같은 **복수 신호가 동시에** 맞아야 전송 계층으로 좁힌다.

이건 **게이트와 짝을 이룬다** — 「정의」의 `human` 게이트가 *"물어봐"*라면, 이 독트린은 ***"뭘 가지고 물어봐"***다. 독트린이 없으면 게이트가 근거 없는 확인이 된다.

### ② 복구 순서는 **load-bearing이다. 바꾸지 않는다** — 「수행」

**순서 자체가 결과를 결정한다**(내력벽 — 빼면 무너진다). 더 빠른 길이 보여도 **즉흥적으로 최적화하지 않는다.**

> 예: `cinder_volume 재시작 → 세션 재로그인 → 오프라인 fsck → nova 기동`.
> ③④를 뒤집으면 **VM이 켜진 채 fsck → 파일시스템 파괴**. ①②를 건너뛰면 디바이스가 없어 **hang**.

*(실제 인프라별 신호와 복구 순서는 해당 domain runbook이 소유한다.)*

> 🔻 **폐기한 후보: *"복구 우선, 원인 규명은 그 다음."*** 뒷줄은 자명해서 독트린 가치가 없고(장애 중에 원인 논문 쓰는 사람은 없다), 앞줄은 ***"확정도 건너뛰라"*로 오독**된다. 실물엔 그 문장이 없었다 — **근거 없이 지어낸 것**이었다.

## 🔑 임계가 높아도 정책은 그대로다

*"급하니 안 묻는다"*는 **게이트** 이야기다. **되돌릴 수 없는 액션**(볼륨 삭제·force · 데이터 덮어쓰기)은 **정책(L3)이 별도로 막는다.**

> 급할수록 되돌릴 수 없는 실수가 나온다. 임계를 높인 건 *"어느 경로로 갈까"*를 안 묻겠다는 뜻이지, *"지워도 되나"*를 안 묻겠다는 뜻이 아니다.

**「정의」의 `human` 게이트도 별개로 살아 있다** — 장애 판정을 AI가 혼자 하고 파괴적 복구에 들어가면 안 된다. 임계는 *경로 선택*에 걸리지 *진단 확정*에 걸리지 않는다.

| 단계 | 게이트 | 독트린 |
|---|---|---|
| 「정의」 | **사람 확인** | ① 3신호로 확정 |
| 「수행」 | `self` (자율) | ② 순서 불변 |
| — | **정책(L3)** — 데이터 쓰기(`fsck`·`mkfs`·`dd`)는 임계와 무관하게 사람 확인 | |

## 왜 계획을 스킵하나

급하다. 그리고 장애는 **진단이 곧 계획**이다 — 원인이 보이면 조치가 정해진다.

대신 **점검은 스킵하지 않는다.** 복구됐다고 착각하는 게 장애대응의 주요 실패 모드다.

## 「마무리」 = 포스트모템
