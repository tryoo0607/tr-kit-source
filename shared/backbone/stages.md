# 백본 — 6단계

**백본은 하나다.** profile은 그 위의 설정일 뿐 별도 프로세스가 아니다. (지하철 노선 = 백본 / 어느 역에 서나 = profile)

```
진입 → 정의 → 계획 → ┌─ 수행 → 점검 ─┐ → 마무리
                      └── 되돌림 ──────┘
                         (상한 3 · 도달 시 human 에스컬레이션)
```

## 단계 descriptor — 3필드

| 필드 | 값 |
|---|---|
| **`runner`** | `inline`(내가 직접) · `delegate`(서브 1개에 위임) · `ask(N)`(서브 N개에게 **묻고 답만 받음**) |
| **`gate`** | `none` · `self`(내가 판정) · `human`(사람에게) + `when: before\|after` (기본 `after`) |
| **`returns`** | 결과 + **가정** + **확신 없는 것** (고정 스키마) |

> `ask(N)`은 서브가 **파일을 안 고친다.** 말만 돌려받으므로 충돌이 없다. N은 숫자로 정하지 않고 **profile의 점검 관점 목록 길이**다.
>
> **게이트는 단계 진입을 막는다. 액션을 막는 건 정책(L3)이다.** 이 구분이 없으면 게이트가 모든 위험을 떠안으려다 실패한다.

## 단계별 기본값

| 단계 | `runner` | `gate` | `returns` |
|---|---|---|---|
| **진입** | `inline` | `none` | 고른 profile + **왜 골랐나** |
| **정의** | `inline` | 🔑 **`human`** | 확정된 요구 + **결정 출처 태그** `[사람]`/`[AI]` |
| **계획** | `inline` | `human`(중요) / `self` | 계획 + **버린 대안** |
| **수행** | profile이 정함 | `self` | 한 것 + **가정** + **확신 없는 것** |
| **점검** | **`ask(N)` 허용** | `self` → 실패 시 **수행으로 되돌림** | 지적 목록 + 판정 |
| **마무리** | `inline` | `none` | **회고** + 다음 |

**「정의」의 `human` 게이트가 가장 중요하다** — AI가 정한 요구가 하나라도 있으면(`[AI]` 태그) 차단한다. 다 사람이 정했으면 그냥 통과.

**게이트 발동 = 되돌리기 비용 임계값.** *"되돌리는 데 N분 이상 드나?"* — profile이 임계를 정한다. 형용사(촘촘/성김)로 조절하지 않는다.

| 묻는다 | 안 묻는다 |
|---|---|
| 진짜 갈림길(방어 가능한 경로 2개 이상) · 취향 선택 | 순수 기계적(문법·자명한 버그픽스·레포 관례) |

> ⚠️ **rubber-stamping 감지 시 임계를 올린다** — 추천안을 생각 없이 두 번 연속 수락하면 *더 적고 더 큰 것만* 묻는다.

## 단계별 상세

### 진입
```
⓪ 백본을 탈 일인가?   휘발("이 파일 뭐야", "오타 고쳐")이면 안 탄다
                       애매하면 가볍게 시작하고, 무거워지면 그때 상태 파일을 만든다 (lazy)
① 어느 profile인가?    애매하면 묻는다 — profile 오판은 절차 전체를 틀리게 한다
② 어느 skill을 소환하나?
```

## 🔑 응답 규약 — `returns` 를 **사람에게 보인다**

각 단계의 `returns`는 기록에만 쓰는 게 아니라 **그 턴 응답에 드러낸다**(결정 #22).

```
「수행」 · 고치기 · 루프 1/3
가정 — {{HOST_SETTINGS}} 이 사본이라 덮으면 안 된다고 전제 (확인 안 함)
확신 없음 — install.sh --inno 가 회사 config 도 건드리는지
```

**결과는 어차피 보인다. 안 보이는 건 가정과 불확실이고, 그게 사람이 끼어들 지점이다.**
사후에 기록으로만 보면 이미 늦다.

형식은 자유, **항목은 필수**. 휘발성 턴이면 생략하고, 가정도 불확실도 없으면 단계 한 줄이면 된다.

> 이건 `UserPromptSubmit` 훅이 매 턴 상기시킨다 — {{AGENT_FILE}} 에만 두면 세션 시작에 한 번 읽고 잊힌다(2026-08-06 실사용에서 확인).

### 정의
요구를 확정한다. **각 항목에 `[사람]`/`[AI]` 태그.**

> 💡 **버그수정의 "재현"은 여기의 완료 조건**이다 — 재현되면 정의가 끝난 것. 게이트 판정 기준도 *"재현 절차가 기록됐나"*.

### 계획
결정 + 근거 + **버린 대안**. 작업을 넘는 결정이면 `decisions.md`에 `D-nnn`으로. 상세 = `references/plan.md`.

### 수행 ⇄ 점검 (루프, 상한 3)

**단계 크기 = "한 번에 검토 가능한 크기."** 숫자로 박지 않는다(3~10은 코드 기준이라 노션·홈랩엔 안 맞는다).
**넘으면 쪼개는 게 아니라 루프를 한 번 더 돈다.**

`ask(N)`의 관점은 **격리한다** — 한 서브에게 *"보안·성능·누락 다 봐줘"* 하면 관점이 서로 오염된다.

```
점검 · ask(3)
  ├─ 서브1: 보안 관점으로만
  ├─ 서브2: 성능 관점으로만
  └─ 서브3: 요구 대비 누락 관점으로만
       ↓ 세 목록 → 리뷰어 게이트가 가정 대조
```

**상한 3의 근거:** CMA `max_iterations` 기본 3 · R2 Factor 9(연속 ~3회면 에스컬레이션) · R6(*"보통 2~3 라운드"*) · **상한 도달 = 실패가 아니라 human 에스컬레이션**.

### 마무리
`state/<slug>.md` → `exec/<slug>.md`로 **옮긴다**(복사 아님 — 정본은 하나).
**회고를 여기서 같이 한다** — 별도 행위로 두면 실행되지 않는다(JOURNAL 기록 0건이 증거).
분류 태그를 붙이고, 같은 태그가 **3건** 쌓였으면 넛지한다(알림이지 게이트가 아니다).

## 규약 몇 줄

- **독립적인 조회는 한 번에 묶어라** (툴 병렬 호출)
- **단계 수준 분리는 OK**(수행≠점검), **액션 수준 분리는 피한다**(한 액션을 둘로 쪼개지 마라)
- 필요하면 단계 진입 시 미리 읽을 것을 스킬 본문에 적는다 (prefetch — 새 장치 불필요)

## 차용 vs 전환 — "A 하다가 B"

| | 무엇 | 파일 |
|---|---|---|
| **차용(borrow)** | A의 요구에서 파생 · **돌아온다** | **한 파일.** 헤더에 `차용:X`, 진행에 `[차용:X]` 접두어 |
| **전환(switch)** | 별개 요구 | **파일 2개** |

진행 섹션은 중첩하지 않는다 — **접두어 + 시간순**. (헤더 = 포함관계 / 진행 = 시간순)
→ push/suspend/resume 같은 스택 기계는 **불필요하다.**
