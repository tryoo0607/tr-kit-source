# 「정의」 — 요구 명확화


구현 **전에** "무엇을 만드는지"를 확실히 한다. **모호하면 짜기 전에 질문.**

## 절차
1. **파싱** — 요청/리포트에서 뽑는다: 무엇을·왜·**수용기준**(뭘 만족하면 완료).
2. **모호/누락 → 질문** — 추정 금지. **AskUserQuestion으로 확인**:
   - 범위 경계("A만? B도?"), 대상("어느 역할/타입까지?"), 위치("UI/API 어디?"), 기대 동작·에러 처리.
3. **엣지·경계·비기능** — null/빈값·경계값·동시성·실패 경로, 성능/보안 요구 짚기.
4. **범위 확정** — in / out of scope 명시(이번에 안 하는 것도 적음).
5. **연결**:
   - 확정 요구 → 필요 시 project `plan`의 배경/목표에 기록.
   - 검증할 시나리오 → **`project`에 케이스 등록**(+ expand로 유사·인접 입력까지).

## 원칙
- **불확실 > 추정.** 애매한 채로 구현 시작하지 않는다.
- 리포트(QA/이슈)로 오면 입력·조건·기대를 구조화해 확인 → 그대로 케이스화.
- 요구가 큰데 설계가 필요하면 `architecture` / `design/`으로 넘겨 "어떻게"를 먼저 잡는다.
