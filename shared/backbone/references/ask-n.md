# `ask(N)` — 관점 격리 상세

> `stages.md`의 `ask(N)` 정의에 딸린 상세. **서브는 파일을 안 고친다 — 말만 돌려받는다.**


패턴은 필요 시 추가. 각 패턴 = 언제·어떻게·종합.

## 판단 기준 (쓰기 전)
- **독립성**: 하위 작업이 서로 독립인가? (의존 강하면 순차가 나음)
- **규모**: 한 컨텍스트에 안 담기나? 커버리지가 넓나?
- **이득 > 오버헤드**: 에이전트 띄우는 비용 대비 값어치. 간단한 건 직접.

## 팬아웃 (병렬 탐색)
- 여러 파일·주제·검색각을 **동시에** 조사 → 각자 결론만 회수(원본 덤프 X).
- 서로 blind → 한 각도로 못 찾는 걸 다른 각도가 커버(multi-modal sweep).
- 종합: 결과 flatten → 중복 제거 → 통합.

## 역할분담 (perspective-diverse)
- 같은 대상에 **다른 렌즈**(리뷰: correctness/보안/성능/가독성)로 병렬.
- redundancy보다 diversity — 각 렌즈가 다른 실패모드 잡음.

## 파이프라인 (staged, barrier 없음)
- 각 항목을 여러 스테이지에 **독립 통과**(항목 A가 3단계일 때 B는 1단계 가능).
- barrier(전부 모으기)는 **정말 필요할 때만**(dedup·early-exit·cross-item 비교).

## 적대적 검증 (verify)
- 발견을 **N개 스켑틱**이 반증 시도(REFUTE 지향) → 다수결. 그럴듯하지만 틀린 것 제거.
- 관점 다양화: 실패모드 여럿이면 스켑틱마다 다른 렌즈.

## 종합 (synthesis)
- 서브에이전트 출력은 **컨텍스트 밖**(요약/결론만 회수).
- 상충 결과는 근거로 판정. 완결성 비판("무엇이 빠졌나") 한 번.

## 실행 (odin 소프트위임 / Agent fallback)
- odin parallel-launch/workflow 있으면 그걸로. 없으면 Agent 툴로 팬아웃(결과 filter(Boolean) 후 사용).
- 규모는 요청에 맞춤 — 과한 팬아웃은 낭비, 침묵 truncation은 로그로 알림.


이름 붙은 역할 렌즈 — 역할분담·council·advisor가 공유하는 자산. 각자 **다른 각도**에서 본다. **원본 작성**(외부 라이브러리는 참고만 = `kit`의 INTEGRATIONS 발췌차용/참고 항목). 한 역할 = 한 관점, 서로 안 겹치게.

> 쓰는 법: 이 렌즈들을 서브에게 **병렬 배정**한다. 상시 견제가 필요하면 **reviewer + devil's advocate** 둘이 기본 조합이다.

## 역할 렌즈

| 역할 | 보는 것 | 태도 |
|---|---|---|
| **architect** | 구조·경계·결합도·확장성 — "이 설계가 요구와 미래 변경을 견디나" | 큰 그림, 과설계도 경계 |
| **security** | 위협·입력검증·authn/authz·secret·공급망 (STRIDE/OWASP 렌즈) | 적대적, 최악 가정 |
| **performance** | 병목·복잡도·자원·핫패스 — **측정 먼저**, 추측 최적화 금지 | 데이터 기반 |
| **reviewer** | 정확성·가독성·규약·엣지케이스 (post-write) | severity 순, 구체적 |
| **tester** | 실패경로·경계·회귀·**검증 가능성** — "어떻게 깨지나" | 부수기 지향 |
| **devil's advocate** | 전제 반박·"진짜 필요한가"·대안·숨은 리스크 | **합의 편향 견제**, 반대 위한 반대 X |
| **moderator/decider** ⭐ | 위 관점들 **종합·수렴·결정** — 충돌 조정, 근거 무게 판단 | 결정+근거, 미결은 미결로 |

## 각 렌즈 지침 (프롬프트 씨앗)
- **architect**: 요구를 구조로. 경계·책임·데이터흐름. 결합도↑·응집도↓ 신호. 확장점 vs YAGNI.
- **security**: 신뢰경계 넘는 입력, 인증·권한 우회, secret 노출, 의존성 취약. "공격자라면 어디를."
- **performance**: 핫패스·알고리즘 복잡도·N+1·할당. **측정 근거 없으면 "확인 필요"**(추측 최적화 금지).
- **reviewer**: 버그·가독성·규약 위반·놓친 엣지. severity(blocker→nit) 순, 파일:라인.
- **tester**: 이 변경이 **틀리려면** 무슨 입력? 경계·null·동시성·회귀. 검증 어려우면 그것도 지적.
- **devil's advocate**: "이거 왜 함?", "더 단순한 길?", "이 전제 틀리면?". 성급한 합의·"완료"를 흔든다.
- **moderator**: 각 관점 요약 → 충돌 지점 명시 → **근거 무게로 결정**(동급 이상 판단력). 못 정하면 "결정 필요"로 남긴다(억지 수렴 X).

## 확장
- 도메인 역할 추가 가능(예: db·frontend·devops) — 한 렌즈 = 한 관점 규율만 지키면.
- 페르소나는 **관점 배정**이고, 실제 일은 그 관점으로 소환된 스킬이 한다(예: 보안 렌즈 → `secrets`·`review`).


여러 **페르소나**(`personas.md`)가 한 사안을 각도별로 보고 → **중재자(moderator)가 수렴·결정**하는 패턴. 역할분담(병렬 관점)에 **상호 비평 + 결정**을 얹은 것. 설계·아키텍처·되돌리기 힘든 결정처럼 **관점이 여럿이고 수렴이 필요할 때**.

> 벤치마크(참고, `INTEGRATIONS.md`): hex/claude-council(synthesis·confidence), richiethomas/claude-devils-advocate(라운드상한+조기종료), AutoGen GroupChatManager(max_round).

## 흐름
```
1. 소집   — 사안에 맞는 페르소나 N 선정 (personas.md). 항상 devil's advocate 1 포함 권장.
2. R1     — 각 페르소나 독립 의견 (병렬 팬아웃). 서로 안 봄.
3. R2..   — 상호 비평: 다른 의견 보고 반박·보완. (수렴 라운드)
4. 수렴   — moderator가 종합 → 충돌 지점 명시 → 근거 무게로 결정(+근거). 미결은 미결로.
```

## 라운드 상한 (무한 방지 — 필수)
- **기본 상한 = 2~3 라운드.** R1(독립) + R2(상호비평) 이면 대개 충분(토론은 R2쯤 수렴).
- **조기 종료**: 라운드 전에 **합의 도달**하면 즉시 수렴으로(낭비 라운드 skip).
- **상한 도달해도 미합의**면 → moderator가 "**결정 필요**(미결 쟁점 X·Y)"로 사용자에게 올린다. 억지 수렴 금지.
- 고정 상한(안전 하한) + 조기종료(효율)를 **둘 다** — 고정만이면 낭비, 조기만이면 무한 위험.

## 중재자(moderator) 규율
- 각 관점 **요약** → **충돌 지점** 콕 → **근거 무게로 결정**. 다수결 아님(근거가 이긴다).
- **decider는 토론자와 동급 이상 판단력** — 약한 중재자는 결과를 떨어뜨린다(judge<debater면 저하, 학술 근거).
- 결정은 **근거와 함께**. 못 정하면 정직하게 "결정 필요".

## 규모 (비처방)
- 작은 사안: 페르소나 2~3 + R1만 + 간단 수렴.
- 큰/위험 결정: 페르소나 4~5 + devil's advocate + R2 상호비평 + 정식 수렴.
- **오버헤드 > 이득이면 council 쓰지 마** (단일 관점으로 충분한 걸 소집 X).

## 실행 (§9)
- 팬아웃 **실행**은 Agent 툴(또는 `odin:parallel-launch` 있으면 그것). 여긴 그 위의 **관점 선정 + 수렴 규율**이다.
- 상시 단일 리뷰어(매 턴 훈수)가 필요하면 = `review`(같은 personas.md 공유, reviewer+devil's advocate 렌즈).
