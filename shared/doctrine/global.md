# 전역 독트린

**정책 = 하면 안 되는 것**(사고 방지, `../{{AGENT_FILE}}`) / **독트린 = 무엇이 좋은 결과인가**(품질 기준, 여기).

독트린은 `gate: self`가 **무엇을 기준으로 판정할지**를 준다. 기준이 없으면 자기점검은 형식이 된다.

## 🔑 여기에 뭘 넣을 수 있나 — 판별 규칙 둘

| | |
|---|---|
| **① 한 profile이라도 반례가 있으면 전역이 아니다** | → `profiles/`로 내린다 |
| **② 추출원(기존 스킬·결정)이 있어야 쓴다** | profile 독트린과 같은 규율. 전역은 *"추출원 없으면 비워둔다"*는 압력이 자동으로 안 걸리므로 **명시해야** 겉멋이 막힌다 |

> 개수로 통제하지 않는다("전역은 2문장" 같은 숫자엔 근거가 없다). **판별 규칙으로** 통제한다.

---

## 실측 > 추측

확인한 것과 추측한 것을 **섞지 않는다.** 추측은 **"확인 필요"로 명시**한다. 1차 출처를 우선한다.

*추출원: 전역 정책 「사실·근거 중시」 — 유저 최우선 가치.*

**반례 검사:** 만들기·고치기·알아내기·되살리기·판정하기 — 다섯 다 참. ✅

> 알아내기 profile의 *"실측 없으면 기록하지 않는다"*는 이것의 강화판이다(그 profile에선 이게 산출 그 자체라서).

## 완전성은 **정본에서 도출한다**

*"다 챙겼나"* 를 사람이 세거나 눈으로 훑어서 답하지 않는다.
**권위 있는 원본에서 목록을 뽑아내면**, 원본에서 빠진 것이 목록에서도 빠지므로
**누락이 구조적으로 불가능**해진다. 손으로 적은 목록은 언제나 조용히 뒤처진다.

같은 이유로 **성공 신호는 계산된 값이어야 한다.** *"커밋이 생겼다"* 는 성공의 증거가 아니다 —
**담으려던 것이 남아 있지 않은 것**이 증거다.

*추출원: 2026-08-10~11 사고 4건.*

| 사고 | 무엇을 지어냈나 |
|---|---|
| `kit-audit` | 문자열(`✅ 군살 없음`)로 판정 → 지적 2건을 삼킴 |
| local-docs 백업 | 커밋 생성만 성공으로 봄 → **4일간 실제 변경이 push되지 않음** |
| `format-drift` | 형식을 안내문으로만 둠 → 장세션에서 조용히 무너짐 |
| `require-record` | **cwd** 로 프로젝트 판정 → 오탐 차단 + 미탐(강제 무효화) 동시 |

**반례 검사:** 만들기·고치기·알아내기·되살리기·판정하기 — 다섯 다 참. ✅

> 별도 대형 리팩터 검증에서도 같은 결론이 나왔다. OpenAPI 같은 기계 판독 가능한 정본에서 체크리스트를 도출해야 한다.

## 원문은 줄이고, 결정은 공유한다

컨텍스트를 아끼는 것과 맥락을 공유하는 것은 **충돌하지 않는다** — 무엇을 줄이느냐가 다르다.

| 줄인다 | 공유한다 |
|---|---|
| 원문 · 로그 · 파일 덤프 | **확정된 요구 · 내린 결정 · 버린 대안 · 가정** |

서브에게 브리핑할 때도 같다 — 원문을 통째로 넘기지 말고 **요구 + 결정**을 넘긴다.

*추출원: R4(Cognition, "컨텍스트를 최대한 공유하라") ↔ 컨텍스트 절약 레버의 충돌 해소.*

**반례 검사:** 다섯 profile 다 참. ✅

## 여기 없는 것 — 의도적이다

| 후보 | 왜 뺐나 |
|---|---|
| *"변경 비용이 큰 부분에 집중하라"* | **채점이 안 된다** — *"비싼 부분에 집중했나?"*에 예/아니오로 답할 수 없다. 방향으로만 쓰고 게이트엔 걸지 않는다 |
| *"1차 출처 우선"* | 「실측 > 추측」의 문서판일 뿐. **같은 말**이라 따로 두면 층만 늘어난다 |
| 도메인별 독트린 층 | 위 이유로 **독트린은 2층(전역 + profile)이면 충분**하다 |
