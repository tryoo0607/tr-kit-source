# 7번 Android·Wear OS source 이관

## 요청과 범위

6번 완료 후 Android·Wear OS 이관 진행 승인을 받아 scratch에 자체 연결을 작성했다. 외부 저작 방식은 plugin-authoring·공식 skill-creator에서 이미 확인한 기준을 재사용한다. 운영 plugin 설치·배포, 앱/SDK/기기/의존성 설치, 실제 앱 변경·빌드·테스트는 이번 대상이 아니다.

위 pin은 기존 checkout의 정적 비교 근거다. 세 checkout에서 tracked 변경 없음을 확인했으며 설치·현재 최신 버전·API 호환·기기 실행의 증거로 쓰지 않는다. host 경로·파일 hash·기존 치환 수는 로컬 original-comparison.local.json에 있다.

기존6개 binding에 원문 치환78개가 있었고 이를 새 source에 가져오지 않았다. 원문 상대 링크·버전/API 예제·검증 절차는 공식 설치본에서 해석한다. 공식 절차가 현 요청/승인/필수 자료와 충돌하면 해당 수행을 보류하며 원문 변경·사본·묵시적 필수 단계 생략으로 해결하지 않는다. 지침의 존재를 모든 기능의 실사용 호환 증거로 간주하지 않는다.

```text
common/base/
├── skills/
│   ├── android-architecture/SKILL.md
│   ├── wear-compose-m3/SKILL.md
│   ├── testing-setup/SKILL.md
│   ├── structuring-a-compose-test/SKILL.md
│   ├── running-instrumented-tests-with-androidjunit4/SKILL.md
│   ├── running-instrumented-tests-via-adb/SKILL.md
│   └── bmad-build/SKILL.md  (조건부 연결 보강)
└── references/
    ├── android-work.md  (자체 공통 경계·역할 선택·완료 기준)
    └── external-connection.md  (기존 공식 provider 연결 재사용)
```

기존47개에 자체6개를 추가해53개다. 공통 경계는 android-work.md 한 곳에서 소유하며 각 본문은 업무 입력/기대 결과·선택 provider를 소유한다. 제품별 실행 차이가 확인되지 않은 동일 본문을 adapter에 복제하지 않았다. 선언 파일의 제품 지원·실제 공식 기능 지원은 이후 통합에서 확인해야 한다.

## 읽기·실행 흐름

```text
명시 전문 요청 → 해당 자체 SKILL.md → android-work 공통 기준
                              └→ 기존 external-connection
                                  → 명시 provider 확인
                                  → 공식 SKILL.md·필요 reference
                                  → 승인 범위의 실제 수행/검증
                                  → 관측·미확인·실패·미실행

BMAD build → Android 전문 판단이 필요할 때만 android-work의 요청별 분기
           → 필요한 전문 wrapper 하나 (별도 요청은 각각)
           → 읽은 공통 기준 재사용 (재귀 선택/일괄6개 로드 없음)
```

위 화살표의 기준 문서는 별도 실행 주체가 아니다. 전문 결과는 기존 BMAD 작업 정본에 연결하며 별도 티켓/진행 상태를 만들지 않는다. 전문 연결 부재로 공식 build를 대체했다고 주장하지 않는다.

## 검수와 잔여 작업

- 자체 skill/kit 저작·감사와 조건부 읽기/행동 시험 기준을 적용해 기존 보존 조건·역할·경로·외부 의존·결과 주장을 대조한다. 정적 대조와 모델 결과는 별도 근거다.
- 실제 provider 설치 연결, 공식 절차의 버전/필수 reference closure, Android 빌드·테스트/장치 효과, Codex/Claude native 및 실제 압축/재개는 source 조립으로 완료 처리하지 않는다.
- 별도 parser/CI gate를 만들지 않았다. 기존 parser/실행 증거의 범위에서 결과를 확인하고 불충분하면 미검증으로 남긴다.
- 기존 공통 skill 디렉토리와 대조했을 때 구 skill-authoring만 새 이름 그대로 존재하지 않는다. 이 역할은 새 plugin-authoring과 skill 작성/감사 reference로 재구성한 상태다. 이는 전체 runtime/운영 기능 이관 완료를 뜻하지 않는다. private 기능 이관과 기존 미이관 실행기·제품 통합 검증은 남아 있다.

실제 검증 결과·실패와 수정·한계는 [verification](../verification.md)의 7번 항목에 연결한다.
