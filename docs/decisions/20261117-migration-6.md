# 6번 자료·기록·지식 연결 source 이관

## 요청과 범위

5번 다음 작업 승인에 따라 scratch에서 자료 보관·검색·작업 기록·경험·지식 연결을 이관한다. 기존 자체 구현과 과거 외부 원문을 구분하고 plugin-authoring·공식 skill-creator의 저작 절차를 적용했다. 운영 설치·실자료 이동/추출/색인·NAS·동기화·자동 수집·원격 배포는 제외한다.

## 파일 구조

```text
common/base/
├── skills/
│   ├── document/
│   │   ├── SKILL.md
│   │   └── references/
│   │       ├── types/{files,history,handoff,knowledge,context}.md
│   │       └── implementations/{local-markdown,tool-connections}.md
│   ├── mem-search/SKILL.md
│   ├── wiki/SKILL.md
│   └── profile-setup/references/git-excludes.md
└── scripts/
    ├── assets.py
    ├── git-excludes.py
    └── profile_config.py
adapters/{codex,claude}/skills/wiki/references/external.md
tests/{test_assets,test_asset_boundaries}.py
```

기존44개에 자체3개를 추가해 SKILL.md는47개다. profile-setup의 기존 본문·규격도 연결을 보강했다. common의 원칙·reference를 제품별 복제하지 않으며 adapter는 공식 entry 선택 차이만 소유한다.

## 읽기·실행 흐름

```text
원본/기록/지식 요청
→ document/SKILL.md
→ 처음 일치하는 type reference (별도 요청은 각각)
→ 위치가 불명확/변경될 때만 local-markdown
→ 실제 도구 연결이 필요할 때 tool-connections의 해당 절
→ 자체 경로/최신성 helper 또는 공식 업무 entry
→ 실제 경로·원문 근거·실행 상태·미확인 반환

명시 Wiki 요청 → wiki/SKILL.md → 실제 제품 provider reference 하나
  ├─ 조회만 → 공식 wiki-query (index/log 변경 없음)
  └─ 명시 관리 → Codex wiki / Claude wiki-manager (추가 효과는 승인과 대조)

경험 검색 → mem-search → 공식 설치본과 실제 native schema
현재 작업 상태 → 기존 BMAD/작업 정본 (경험/Wiki로 대체하지 않음)
```

위 화살표의 reference는 수행자가 읽는 기준이고 독립 실행 주체가 아니다. 공식 entry의 부재·pin 실패는 그 동작만 미실행으로 남긴다. 전체 source bundle은 선택 제품 adapter만 포함하며 다른 제품 파일을 병합하지 않는다.

## 검증과 한계

검증 범위·증거·발견 보완은 [verification](../verification.md)의 6번 항목을 따른다. 원본 관리의 실 CLI 정확성/성능·동시 작업자/적대적 경로 경쟁, 공식 설치본/native MCP·Claude 행동·실제 압축/재개·자동 hook 연결은 이번 fixture 통과로 인증하지 않는다. 기존 승인과 실자료 범위를 확인한 이후 통합 단계가 필요하다.
