# 저작·감사 기준 작성과 시험 중 보완

## 작업 근거와 범위

사용자는 기존 skill 감사에서 이어 hook·kit 저작/감사를 각각 작성하고 검수·반복 시험·보완하는 절차의 계속 진행을 승인했다. 작업은 scratch의 자체 지침과 추적 문서에 한정하며 설치·활성화·배포·기존 설치본 교체를 수행하지 않는다.

본문은 공통 판단·분기를, shared는 조건부 상세 방법을, 대상별 authoring은 저작 기준을, audit은 근거·검사·판정을 소유한다. 이 책임 배치를 유지한 채 필요한 reference 4개를 추가했다. 새로운 실행 서비스·상시 가드를 만든 변경은 아니다.

## 관측에 따른 작성자 보완

- 첫 kit 작성 시험에서 fixture가 제외한 실제 호스트 설정을 읽거나 읽으려는 동작이 3회 관측됐다. 제공 요구와 제외 범위를 먼저 읽고 불필요한 실호스트 설정 탐색으로 확대하지 않도록 본문을 보완했다. 필수 호스트 가드·보안 검사를 생략하는 예외는 추가하지 않았다.
- 첫 hook 작성 평가의 도표 항목은 대상 runtime과 저작 도구의 내부 지침 읽기 절차를 모호하게 결합했다. 독립 범위 검토 후 두 설명 대상을 구분하도록 source와 후속 rubric을 명확히 했다. 실제 지침/reference 관계 검사는 별도 회귀 사례로 유지했다.
- 이는 승인된 작성·시험 범위에서 관측을 근거로 수행한 보완이다. 새로운 사용자 합의나 과거 결과의 재판정으로 기록하지 않는다. 기존 source·rubric·실행·grading을 보존하고 보완 버전의 실행을 분리했다.

실제 결과·한계는 [검증 상태](../verification.md)에 기록한다. 상세 실행 증거는 로컬 `_bmad-output`에 보관한다.
