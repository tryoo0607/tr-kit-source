## 요청과 판정

2026-11-20 사용자의 후속 ‘3번 ㄱㄱ’는 앞서 구분한 보고 신뢰성·불필요한 재승인 보완과 검증에 적용한다. 공통 지침2파일을 수정하고 실제 Codex·Claude 격리 시험을 수행했다. **구현·해당 시험은 완료했으나 A-03 전체 해결이나 운영 적합을 선언하지 않는다.** 최종 Claude 원인 미확인 사례에서 요청한 네 문장을 넘어 다섯 문장으로 답한 실패가 남았다.

## 시험 대상과 절차

기존 native 실행기·Orca CLI·공식 Gitleaks·공통 CI와 읽기량 측정기를 재사용했다. 기존 `plugin-authoring`의 kit 작성/감사와 조건부 행동·읽기·구성 기준을 적용했다. 별도 분석 skill이나 새 차단기는 만들지 않았다. 동일 작성자의 검수이며 독립 감사가 아니다.

- 실제 Codex0.167.2의 `gpt-6.2-sol`, Claude Code2.1.329의 `claude-opus-5-5`를 사용했다. 각 입력은 합성 기록/무해한 fixture이며 실제 개인·회사 자료를 읽지 않았다.
- 검증한 기존 공통 native 설치본의 보안 hook/시작 처리를 유지하고 이전/후보 지침과 필요한 workflow 절을 명시적으로 전달했다. **변경 후보를 새 native 패키지로 설치한 시험은 아니다.** 제품별 도구 노출·권한 방식도 다르다.
- 초기에는 제품별 이전 지침4사례·후보8사례·후보 반복3사례를 실행했다. 원인 미확인, 정확한 허용 명령, 환경 미확인, 승인된 실행, 제품 거부, 새 효과, 단계 대기, 근거 있는 추론을 구분했다.
- 이후 Claude 승인 실행3회 재검증, 실제 unittest 권한 거부→동일 세션 재개 시험2쌍, 두 보완본 각각 제품별4사례를 추가했다. 초기·중간 실패와 원본 출력은 보존했다. 선택된 소규모 사례이며 통계적 효과·재현율 측정은 아니다.

## 회귀·읽기량·계약 영향

- 최종 지침2파일의 SHA256을 고정한 뒤 원래 공통 scratch에서 pinned Gitleaks8.30.1을 연결한 `scripts/ci-check.py`를 실행했다. **516개 통과·skip0**, 실행 뒤 고정 hash와 일치했다. 앞선 중간 검사는 최종 고정본의 증거로 중복 계산하지 않는다.
- 선언된 읽기 문자 수는 상시 원칙1500→1580(+80), 원칙+승인 절2281→2622(+341), 원칙+검수 절2013→2702(+689)다. skill metadata는5249자로 유지됐다. 실제 token·모든 외부 지침·native 주입·실제 읽기 비용의 측정은 아니다.
- 자체 skill53개와 기존 hook/adapter 경로를 유지했다. source 묶음은 제품별150파일이며 내용이 달라지는 경로는 원본 지침2개와 생성되는 제품 지침/작업 흐름2개다.
- **새 공통 source는 기존 private exact pin과 일치하지 않는다.** 이 단계에서 pin을 완화하거나 갱신하지 않았다. 이전 검증 설치본은 그대로이며5번에서 새 source/native 패키지와 pin을 함께 검증·정렬해야 한다. private 역할 파일 hash `95c37580931280b604b79e54f37b659756d8474770c1d5b74be6534ac6568d21`은 유지한다.

## 보존·감사와 남은 범위

로컬 증거 정본은 `/data/projects/_scratch/tr-kit-reporting-policy-20261120/`이다. 이전/후보 지침, 각 버전 입력·모델 응답/실제 도구 결과, 권한 불일치 실패, 최종 `v3/`와 `claude-v3-evidence/`, `stable-v3-regression/`, 읽기량과 pin 영향 기록을 보존한다. 세부 실행 로그·임시 시험기는 kit 배포 구성요소에 추가하지 않는다.

원격은 소유한 inno-desktop 임시 terminal만 사용했고, 선택한 합성 증거를 전송 전 비밀 검사한 뒤 파일 hash를 대조했다. 마지막 공통 native payload의 bytes/목록과 사례 폴더 보존·시험 프로세스 잔존0을 확인하고 그 terminal을 종료했다. 로컬 Codex 시험의 같은 호스트 인증 참조는 정리했으며 실행기가 인증 bytes를 읽거나 복사하지 않았다.

마지막 파일/프로세스 대조를 묶은 명령은 기존 운영 PreToolUse에서 `whole environment disclosure blocked`로 실행 전 거부됐다. 명령에 환경값 출력은 없었으나 오분류 원인은 재현·확정하지 않았고 운영 hook을 수정하거나 우회하지 않았다. 프로세스 조회는 재시도하지 않았다. 별도의 파일-only 대조는 통과했다. 첫 파일 대조기는 기존5개 디렉토리 baseline에 과거 fixture/Git 파일까지 포함해 범위를 잘못 비교했으므로 실패로 보존하고 동일5개 디렉토리 범위로 정정했다. 이들 검사기 문제를 kit 구현 실패나 소스 변경으로 바꾸어 설명하지 않는다.

kit 감사 범위에서 역할/단방향 의존·조건부 읽기·기준 중복·원문/설치본 보존·요구와 결과를 대조했다. skill/hook 자체를 추가·수정하지 않아 개별 저작 기준은 비대상이며 기존 실행·보호 경로를516개 회귀로 확인했다. 자연 발동·신규 native 설치·전체 skill 의미·실자료·최종본 압축/재개·장기 반복에서의 준수는 미검증이다.

남은 분량 위반과 제한된 사례 수 때문에 A-03의 완전 해소는 보류한다. 다음4번 문서·목차 교정으로 넘어갈 수 있지만,5번 제품 연결 검증과 전체 적합 판정에서 이 잔여 발견을 계속 대조해야 한다.
