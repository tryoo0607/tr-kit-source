# 5번 — 문서 작성·시각화·게시 연결 이관

## 범위와 근거

사용자의 “5번 ㄱㄱ” 요청에 따라 scratch의 자체 연결·제품 adapter·검사 진입점·시험과 추적 문서를 작성한다. 계획은 로컬 `_bmad-output/migration-5-20261117/plan.md`다. 실제 문서 서비스 게시·도구 설치/업데이트·운영 배포·사용자 세션 조작은 이번 범위가 아니다.

## 역할과 구조

| 담당 | 소유 책임·보존 조건 |
| --- | --- |
| doc-coauthoring | 공동 작성 과정과 독자 이해 보완. 기존 BMAD 등 업무 담당의 분석·산출 형식·검증 소유권 유지. 자료 보관·검색·README·게시를 공통 관문으로 묶지 않음 |
| github-readme-generator | README 작성/갱신/감사와 실제 구현 근거 연결. entrypoint뿐 아니라 호출 함수·제품 설정까지 확인. 문서에 맞추려 코드/설정/시험을 변경하지 않음 |
| archify | 일반 구조·관계·흐름 시각화 기본. 공식 runtime/root·cwd·출력·검사/복구 계약 연결 |
| diagram-design | 수치와 일정·칸반·여정 등 업무 시각화. 명시한 도구 선택·원본 데이터/단위·스타일 gate·형식/시각 검증 구분 |
| artifact-publish | 요청한 계정 전용 게시/갱신. 내용 owner·최소 payload·계정/audience·제품별 수단·실제 배포/접근/렌더 구분 |

네 외부 기능의 원문·사본·runtime·bindings는 새 kit에 포함하지 않는다. 기존 선택 공식 checkout의 origin·revision·clean 상태를 대조하고 정적 원문 검사 자료로만 썼다. 자체 고유 입력/정책과 provider 계약을 작성했고 공식 설치·사용 조건·제품 지원은 별도 확인 대상이다. 기존 runtime_note append와 문구 치환 규칙을 가져오지 않는다.

공식 doc-coauthoring의 단계별 질문·선택·독자 검토를 임의 삭제하지 않는다. 공식 지원 경로와 실제 승인 범위를 대조하고 충돌하면 해당 동작만 보류한다. 개별 사용 조건의 미확인을 wrapping만으로 허용됐다고 단정하지 않는다. Diagram의 설치 원문/style-guide 변형이나 임의 프로젝트 사본/profile 생성도 자동 대안으로 삼지 않는다. 원문을 그대로 읽는 공식 설정 경로가 실제 지원되는지 확인해야 한다.

## 제품별 게시 연결

공통 artifact-publish는 실제 제품에 따라 `<kit-root>/adapters/<product>/skills/artifact-publish/references/provider.md`를 선택한다. 공통 reference 경로로 자동 합성/덮어쓰기하지 않는다. 조립기는 **선택 제품의 자체 adapter/skills만** 같은 경로로 포함한다.

- Codex는 공식 Sites SKILL.md와 native 도구에 연결한다. 정적 결과의 공식 buildless 경로와 선택 Site source/credential/패키징 절차를 재사용한다. 별도 업로더·Git 인증·서버를 만들지 않는다. 원래 프로젝트 전체를 Site source로 사용하지 않는다.
- Claude Code는 현재 세션 native Artifact schema로만 연결한다. 기존 URL/식별자·실제 도구/권한이 필요하며 API 필드나 계정 상태를 추측하지 않는다. 파일 수정과 게시가 한 동작에 포함되면 두 효과를 승인 범위에 대조한다. 현재 Codex에서 Claude schema/실행을 관측하지 않았다.
- 단순 로컬 HTML/Markdown 작성은 게시가 아니다. 명시된 아티팩트/계정 링크 요청 범위는 반복 승인 없이 수행하되 계정·내용·audience 확대는 구분한다. 제품 실패를 다른 제품·공개 링크로 우회하지 않는다.

근거: 호스트 관리 Sites1.1.6 SKILL.md를 읽고 현재 native 도구 metadata만 확인했다. 실제 계정/사이트는 조회하지 않았다. Claude 측은 [공식 Artifact 문서](https://code.claude.com/docs/en/artifacts)를2026-11-17에 확인했다. 문서의 기본 비공개·기존 페이지 갱신·형식/CSP·계정/조직 조건 설명은 현재 세션의 실행 증거와 다르다. 게시·로그인 화면·계정 보호·렌더를 각각 검증해야 한다.

## 실제 payload 검사

기존 Git index/outgoing CLI는 추적되지 않은 HTML/파일 묶음을 검사하는 도구가 아니었다. 기존 `secret_guard.scan`·신뢰된 Gitleaks를 재사용하는 `scripts/check-artifact-secrets.py`와 security-scan의 조건부 `references/artifacts.md`를 추가했다. 탐지 엔진·원문 규칙·업로더를 새로 만들지 않았다.

- 명시 expanded 폴더의 실제 bytes·파일명·hidden/ignored 파일을 검사한다. symlink·특수 파일·압축 컨테이너·비어 있는/불완전 payload는 인증하지 않는다.
- 최대4096노드·총16MiB와 기존 scanner timeout을 적용한다. 오류·부재·크기/수량 한도·검사 중 변경은 unavailable, 탐지는 finding이며 모두 exit2다. 원문·경로를 발견 출력에 싣지 않는다.
- 검사 전후 inventory/bytes를 대조하며 scanner가 사용하는 자체 임시 자료만 생성/정리한다. 대상/원본은 변경하지 않는다. 이 과정은 원자적 OS 격리나 모든 binary/인코딩 비밀의 탐지 보증이 아니다.
- 실제 전송 파일/패키지가 바뀌면 전송 전에 다시 검사한다. 과거 fingerprint나 pass를 공유 허가·완료 인증서로 재사용하지 않는다. 패키징 후 payload 변화도 대조해야 한다.
- kit 원문 보호 catalog를 일반 문서 보관/게시의 금지 기준으로 확대하지 않는다. 원문 보호 gate는 이 kit source 조립/전송의 별도 검사다.

## 파일 배치

```text
common/base/skills/
├── doc-coauthoring/SKILL.md
├── github-readme-generator/SKILL.md
├── archify/SKILL.md
├── diagram-design/SKILL.md
├── artifact-publish/SKILL.md
└── security-scan/references/artifacts.md
adapters/
├── codex/skills/artifact-publish/references/provider.md
└── claude/skills/artifact-publish/references/provider.md
scripts/check-artifact-secrets.py
tests/test_artifact_payload.py
```

위 트리는 이번 추가 파일의 발췌다. 기존 common/base 지침·공통 외부 연결·security-scan 본문·기존 adapter 및 조립/시험 구조는 유지한다. 생성된 제품별 bundle은 native 설치 가능한 plugin이 아니라 자체 source 묶음이다.

## 읽기·수행 흐름

```text
문서/도표 요청 → 수행자가 해당 업무 wrapper와 필요한 공식 SKILL.md 읽기
             → 공식 절차·고유 입력/제약 적용 → 산출물·근거·검증 대조

게시가 요청됨 → 공통 artifact-publish → 현재 제품의 실제 adapter 읽기
             → 최소 실제 payload 검사와 계정/audience·권한 대조
               ├─ 오류/발견/부재: 게시 보류, 파일·미결 보존
               └─ 충족: 공식 제품 수단으로 수행
                        → URL·배포·접근·렌더를 별도 확인
```

기준/지침의 존재가 hook 강제나 native 성공을 뜻하지 않는다. source 역할/연결 대조는 동일 작성자, 모델 출력은 별도 grader가 확인했다. 실제 결과·반복 범위·미실행은 [검증](../verification.md)의5번 항목을 참조한다.
