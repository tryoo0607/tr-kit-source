# 커밋과 문서의 문장 검토

공통 지침의 문자 기준은 초안과 편집에 적용한다. 글의 기존 담당이 초안을 만들고 사실, 형식, 범위를 검증한다.

| 요청 | Humanizer 호출 |
| --- | --- |
| 커밋 제목 작성 | 기존 Conventional Commits 한 줄 형식으로 작성한다. 사용자가 문구를 다듬어 달라고 요청한 경우 호출한다. |
| README 또는 문서 초안 작성이나 개편 | 담당 기능이 만든 초안을 최종 검토할 때 한 번 호출한다. |
| 오타, 링크, 버전만 수정 | 요청한 부분을 수정하고 호출을 생략한다. |
| 사람 말투, 자연스러운 문체 등 편집을 명시 요청 | 편집할 문장이 있으면 바로 호출한다. 위의 일상적인 검토 조건보다 명시 요청이 우선한다. |

호출할 때는 [명시한 공식 외부 기능 연결](./external-connection.md)을 따라 현재 제품의 `humanizer` (종류 `skill`, 업스트림 `blader/humanizer`)를 선택하고 검수된 설치본의 SKILL.md로 진입한다. 해당 문장을 제공하고 글의 용도와 독자, 편집 범위, 공통 문자 기준, 사용자 말투 샘플을 전달한다. 샘플의 말투를 따르되 이 작업의 문자 기준과 보존 범위를 함께 지킨다.

편집안을 반영하기 전에 원래 사실, 수치, 불확실성과 요구를 대조한다. 인용문, 코드, 명령, 경로, 링크 대상과 고유 표기를 보존한다. 커밋 제목의 기존 형식을 확인하고, 기술 문서는 처음 보는 독자가 필요한 정보를 먼저 찾을 수 있게 한다. 자연스러운 어투를 위해 사용자의 경험이나 의견을 추가하지 않는다.

설치본이나 검수 근거가 없으면 Humanizer 검토를 미실행으로 남기고, 기존 담당이 적용한 문자 기준과 원래 초안을 보존한다.
