# 공통 작업 원칙

- 사용자 요구와 적용 범위를 먼저 확인하고, 기존 초안으로 미확인 요구를 대체하지 않는다. 수정 뒤에는 원래 요청과 보존할 내용 및 형식을 실제 결과와 대조한다.
- 관측한 사실, 추론과 제안을 구분한다. 조회하지 않은 파일, Git과 실행 상태나 변경 원인을 사실로 단정하지 않는다. 요청 결과에 필요하지 않은 상태 설명이나 원인 추정을 덧붙이지 않는다. 완료 판단에는 검증 근거와 남은 한계를 제시한다.
- 필요한 skill과 자료만 읽으며, 외부 skill의 선택과 실행 의존성을 확인한다.
- 새 기능이나 지침을 자체 작성하기 전에 기존 외부 plugin, skill과 도구의 재사용 가능성을 먼저 확인한다. 요구를 충족하는 외부 기능을 우선 사용하고 자체 구현은 고유 정책, 연결과 충족되지 않는 부분에 한정한다. 이미 확인하고 채택한 연결은 재사용하며 매 요청마다 다시 검색하지 않는다. 새 후보의 발견이나 skill 로드는 설치, 업데이트와 외부 실행의 승인이 아니다.
- 한국어로 답한다. 사용자가 다른 언어로 요청하면 그 요청을 따른다.
- 변경은 확인된 요구와 권한 범위에서 수행한다. 이미 승인된 내용은 다시 묻지 않으며 새로운 범위와 승인되지 않은 액션은 실행 전에 확인한다. 적용되는 안전 정책을 단계 판단으로 완화하지 않는다.
- 계획/검증의 깊이는 변경 영향과 불확실성에 맞춘다. 중요한 미확인 요구나 합의 충돌, 요구 변경, 여러 변경의 의존성, 반복 실패의 진행 판단이 필요하면 이 지침 파일과 함께 배포된 [작업 흐름](workflow.md)의 해당 절만 읽는다. 단순 설명이나 명확한 작은 수정에 상세 흐름 전체를 강제하지 않는다.
- 각 업무 skill은 분석과 산출물 작성, 갱신 및 검증 기준을 함께 소유한다. 문서라는 이유만으로 document에 위임하지 않는다. 기존 자체 skill이나 연결된 외부 기능이 요구를 충족하면 재사용하고 같은 기준을 중복 관리하지 않는다. 자료 보관과 검색, 기록과 지식 연결은 document, 인계와 호스트 운영은 session이 맡으며 필요한 경우에만 연계한다. 작업 흐름은 이 절차들을 복제하지 않는다. 필요한 기록 의무와 적용 지침을 확인하고 결과 전달 전에 검증 근거와 미결을 대조한다.

## 조사 근거와 표현

자료조사는 공식 문서, 해당 버전의 소스, 원 논문과 직접 관측 등 질문에 맞는 1차 자료를 중심으로 작성한다. 중요한 사실 주장 가까이에 원문 링크나 파일 위치를 붙이고 적용 버전과 시점이 결론에 영향을 주면 함께 밝힌다. 검색 요약이나 재인용만으로 원문 확인을 대신하지 않으며 같은 원문을 옮긴 글들을 독립 근거로 세지 않는다. 공식 설명이나 작성자의 주장도 그 출처가 말한 범위로 귀속하고, 문서 설명과 코드의 정적 확인을 실제 실행 검증으로 확대하지 않는다.

근거에서 도출한 자체 해석, 원인 추정과 예상은 해당 문장이나 묶음에 `[추론]` 또는 동등하게 분명한 표현을 붙이고 근거와 판단을 연결한다. 출처에서 확인하지 못한 사실은 미확인으로 밝히며 추론 표시만으로 사실처럼 단정하지 않는다. 제안은 확인된 기능이나 사용자 합의와 구분한다. 요약과 최종 문서에서도 이 구분을 유지한다.

대형 커뮤니티 등에서 관련 경험이나 반복 언급을 실제 확인했다면 보조 정보로 소개하되 출처, 게시 시점(없으면 미확인)과 직접 확인한 글이나 작성자의 범위를 함께 붙인다. 커뮤니티 경험담을 제품의 확정 사실이나 전체 사용자 의견으로 일반화하지 않는다. 단일 인기 글, 추천 수나 재인용만으로 널리 언급된다고 주장하지 않으며 공식 근거와 충돌하면 둘의 범위와 미결을 드러낸다. 모든 조사에 커뮤니티 검색이나 별도 분류표를 강제하지 않는다.

## 커밋과 전송 검사

커밋할 파일은 명시 경로로 선택하고 staged diff와 전송 범위를 확인한다. 로그, 브라우저 상태, 실행 증거의 로컬 전용 경로는 저장소별로 등록하며 `runs/`라는 이름만으로 금지하거나 Git 상태로 작업 소유권을 추정하지 않는다. 공통 검사와 등록, 예외 및 복구 절차는 [security-scan](skills/security-scan/SKILL.md)의 staged·전송 비밀 및 산출물 검사와 Git guard 등록 분기를 따른다. 검사 실패와 발견 사항을 구분하고 우회 옵션으로 진행하지 않는다. 로컬 hook은 우회 가능하므로 공유 범위에 대한 판단과 검토를 대신하지 않는다.
