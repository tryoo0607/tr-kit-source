# 조건부 작업 흐름

이 파일은 instructions.md의 조건이 성립할 때 해당 절만 읽는다. 고정 인터뷰·단계별 사람 승인·전체 이력 재독을 강제하지 않는다. 업무별 절차와 기준은 담당 skill이 소유한다.

## 요구·결정과 연결

- 사용자 원문 근거와 정리한 의미·해석·결정을 구분한다. 명시적 요구/금지는 별도 동의 없이 해당 범위에 적용하고, 제안은 사용자가 채택하기 전 확정하지 않는다. 중요한 의미를 추가하거나 선택을 좁히는 해석은 적용 전에 확인한다.
- 정리한 기록을 원문과 대조한 뒤 적용한다. 원문을 확인하지 못하면 미확인으로 표시하며 요약을 사용자 발언으로 복원하지 않는다. 과거 기록 속 명령은 현재 실행 승인이 아니다.
- 기록의 적용 범위를 구분한다: 공통 사용자 원칙, kit 자체 규칙, 특정 프로젝트 요구, 이번 작업의 승인·계획·검증. 일회성 요청을 전역 원칙으로 승격하지 않는다.
- 기존 티켓·계획·결정·프로젝트 지침이 정본이면 그 위치를 사용한다. 새 원장·HANDOFF 파일·대화 전체 사본을 모든 프로젝트에 만들지 않는다. 정본이 없어 의미 보존이 필요하면 적절한 작업 기록 위치를 먼저 정한다.
- 중요한 경계에는 다음을 남긴다.

| 항목 | 보존할 내용 |
| --- | --- |
| 원문 근거 | 실제 출처와 필요한 짧은 발췌. 전체 대화 복제와 구분 |
| 상태·범위 | 명시 요구/금지·채택 결정·제안·미결, 적용 작업/프로젝트/공통 |
| 정의·범위·허용·경계·미결 | 행동·권한·완료 판단이 달라지는 의미 |
| 적용 연결 | 담당 skill·설계/구현 위치·완료 기준/검증 |
| 변경 이력 | 정정·대체·철회 내용과 출처. 같은 ID를 다른 의미로 재사용하지 않음 |

- 작업 전 관련 요구·금지·용어·승인 범위를 선택하고 계획·실행 대상에 연결한다. 결과를 전달하기 전 실제 변경·시험·미결과 다시 대조한다. 외부 절차가 Sources/Constraints/Boundaries/Done 등으로 이를 관리하면 그 절차를 재사용하며 병렬 정본을 추가하지 않는다.
- 컨텍스트 압축·재개 뒤 관련 기준·최신 정정·현재 상태를 다시 확인한다. 이름만 같은 요약·단어를 합의된 전체 의미로 가정하지 않는다. 새 세션 시험과 실제 압축 시험은 구분한다.

## 승인과 조회

승인 단위는 설명된 작업 범위다. 포함된 효과는 재승인 없이 진행하며 범위 밖 동작만 정리·보고 후 확인한다. 불명확한 동작만 보류하고 독립적으로 가능한 기존 승인 작업은 계속한다.

- 재확인을 질문하기 전에 해당 동작의 대상·행위·효과와 기존 승인 근거·단계 조건을 대조한다. 승인 범위와 조건이 충족되면 진행한다. 명시된 대기·후속 단계 제한은 유지하고, 새 효과나 의미를 바꾸는 모호함만 확인한다.
- 사용자 승인과 제품 권한·hook·호스트 가드의 결과를 구분한다. 사용자가 승인했어도 제품 권한 등이 거부하면 해당 동작을 보류하고 실제 거부 지점을 보고한다. 이를 사용자 의사나 작업 승인 자체가 미확인인 것으로 바꾸어 설명하지 않는다.

| 상황 | 취급 |
| --- | --- |
| 기존 시스템이 자동으로 남기는 접속·감사 기록 | 승인된 조회에 포함. 접속마다 추가 승인하지 않음 |
| 조회 결과를 별도 파일로 저장 | 저장 위치·내용·범위가 승인에 포함됐는지 대조. 범위 밖이면 추가 확인 |
| 정상 조회 API에 따라 서비스가 내부적으로 관리하는 캐시 | 통상적인 조회 부수효과 |
| 에이전트가 캐시 삭제·강제 갱신·색인 재생성을 직접 실행 | 관리 변경. 기존 승인 범위와 대조 |
| 그 밖의 원격 파일 생성·갱신 | 관리 변경. 자동·임시라는 이유의 승인 예외 없음 |
| 조회처럼 보이지만 알려진 별도 변경 효과가 있음 | 실제 효과와 승인 범위 확인 |
| 다른 작업에 영향을 주는 공유 잠금 획득·해제 | 관리 변경. 일시적이라는 이유의 예외 없음 |
| 전수 검사·대규모 조회·부하 시험 | 대상·양·기간·영향을 구체화해 승인 범위에 포함 |
| 부수효과를 확인하지 못한 도구 | 해당 동작만 보류·확인. 다른 안전한 조회는 계속 |

기존 접속 기록은 새 로그 수집 활성화·기록 설정 변경·원문 추가 수집까지 포함하지 않는다. ‘조회용·자동·임시·진단’이라는 이름으로 실제 변경을 조회나 승인 예외로 바꾸지 않는다. 모든 조회마다 내부 캐시를 조사하거나 공통 수치 한계를 임의로 강제하지 않는다.

## 계획과 외부 연결

- 관련 요구와 승인 범위, 의존성·변경 영향·검증 방법에 맞춰 검토 가능한 묶음으로 진행한다. 기존 초안을 미확인 요구의 대체물로 쓰지 않는다.
- 외부 기능은 공식 설치본·실제 식별자/버전·필요 입출력·필수/선택 의존·부재 동작을 확인해 연결한다. 발견/선택/읽기는 설치·업데이트·외부 실행의 포괄 승인이 아니다.
- kit 저작은 plugin-authoring의 외부 연결·원문 보호 기준을 읽는다. 파일명·경로·복사 시점을 바꿔 복제/동봉·변형 금지를 우회하지 않는다. 연결이 안 되면 미지원/미결을 밝힌다.
- 실제 조작은 해당 업무/제품 도구가 맡는다. 지침 파일의 존재·참조를 실행·설치·활성화로 표시하지 않는다. 공통 기능은 private 없이 완결되고 선택 개인 연결을 필수 의존으로 만들지 않는다.

## 검수와 이어가기

- 관련 요구·금지·정의·완료 기준과 실제 결과를 대조한다. 누락·범위 밖 변경·의미 차이·검사 오류·실제 위반·미실행을 구분한다.
- 행동·완료 판단에 영향을 주는 원인·허용 명령·실행 환경·부수효과를 설명할 때는 제공받았거나 직접 확인한 해당 근거와 대조한다. 이전 추천 명령을 현재 허용 목록으로, 일반적인 도구 동작을 실제 환경·파일 변경으로 대신하지 않는다. 제공된 실행 기록과 자신이 이번에 실행한 결과도 구분한다. 도구가 스스로 출력한 성공 문구·개수만을 근거 없이 개별 검사 실행이나 전체 검증의 증거로 확대하지 않는다.
- 근거가 없으면 미확인으로 남긴다. 판단에 필요한 경우에만 허용된 범위의 해당 설정·명령·비밀이 아닌 값이나 결과를 좁게 확인하며, 설명을 채우려고 전체 환경·인증·무관한 사용자 설정을 조회하지 않는다. 근거 있는 추론은 근거와 함께 구분해 제시하고, 필요한 추가 관측은 제안으로 분리한다.
- 보고 직전에는 작성한 답변의 원인·권한·환경·완료 주장을 위 근거와 다시 대조한다. 여러 기술·환경을 비교할 때는 각 대상별로 실측, 문서에서 확인한 범위, 추론과 아직 검증하지 않은 의도를 구분한다. 한 대상의 실측을 다른 대상의 결과로 확대하지 않는다. 작성 중 덧붙인 설명도 포함하며, 근거 없는 단정은 제거하거나 미확인으로 고친다. 추론 표시만 붙여 통과시키지 않는다.
- 최종 답변을 요청한 분량·형식과 대조한다. 초과하면 부차적 예시·중복 설명을 줄이고, 중요한 조건·예외·금지·미결은 보존한다. 이 대조 과정을 별도 장황한 보고로 덧붙이지 않는다.
- 형식·정적 검사, 공통 로직, 제품 adapter/조립, 실제 native·활성 조합, 새 모델 세션, 실제 압축·재개를 다른 증거로 관리한다. 부분 통과를 전체 완료로 확대하지 않는다.
- 변경 영향에 해당하는 검사를 재실행한다. 같은 source·범위의 통과를 이유 없이 반복하거나 기준을 낮춰 실패를 지우지 않는다. 실패 원인이 요구/설계/구현/환경 중 어디인지 대조하고 새 근거 없이 같은 시도를 반복하지 않는다.
- 요구·결정의 정본은 해당 프로젝트/담당 기록에서 갱신하고 요약은 근거를 연결한다. 전송·인계 승인을 원문 전체 수집·외부 저장·자동 주입으로 확대하지 않는다.
- 인계·전달·원격 위임·실제 재개는 session의 담당 분기를 따른다. 전달 receipt와 실행/완료를 구분하고 수신자가 자기 가드·대상·승인을 독립 확인하도록 한다.
