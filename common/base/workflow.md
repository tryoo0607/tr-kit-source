# 작업 흐름

여러 변경의 계획, 요구 변경의 영향 또는 반복 실패의 판단이 필요할 때 해당 절만 적용한다. 고정된 여섯 단계, 단계별 사람 게이트, 횟수 상한이나 응답 형식을 강제하지 않는다. 실제 도구 권한과 적용 정책은 별도로 유지한다.

## 선택 기준

| 현재 필요한 판단 | 읽을 절 |
|---|---|
| 여러 대상/의존성이 바뀌거나 대안의 영향이 큼 | 계획과 수행 |
| 중요한 요구/합의가 미확인 또는 충돌하거나 요구/범위가 바뀜 | 요구 변경과 전환 |
| 검증 실패가 반복되거나 원인이 불명확함 | 검증과 실패 |
| 진행 중 질문, 중단 또는 인계가 들어옴 | 중간 요청과 중단 |

여러 조건이면 필요한 절을 함께 적용한다. 이미 확인된 조건과 변경 없는 자료를 다시 읽지 않는다. 작업 중 새로운 조건이 생겼을 때만 추가 지침을 읽는다.

## 계획과 수행

1. 목표, 적용 요구/제약, 변경 대상과 권한을 확인한다. 부족한 정보가 다음 행동에 영향을 주면 확인하고, 자명한 구현 선택을 새로운 사용자 요구로 만들지 않는다.
2. 의존성, 되돌리기 비용과 검증 방법을 기준으로 검토 가능한 변경 묶음을 정한다. 중요한 대안의 결과가 달라지면 이유와 영향을 제시한다. 기존 승인·요청으로 범위가 충분하면 수행한다.
3. 해당 skill의 업무 절차를 적용한다. 승인되지 않은 외부/파괴 액션과 새로운 요구 확대는 해당 액션 전 확인한다. 계획 승인을 모든 액션의 포괄 승인으로 해석하지 않는다.
4. 결과와 검증, 미결을 대조한다. 산출물과 작업 정본의 갱신 및 완료 판단은 담당 skill의 계약을 따르고, 자료 보관과 기록 연결이 필요할 때 document를 적용하며 작업 흐름에 별도 단계 상태 파일을 만들지 않는다.

담당 기능은 현재 필요한 결과로 선택한다. 모든 단계를 순서대로 거치지 않는다.

| 필요한 결과 | 담당과 전달할 입력 |
|---|---|
| 열린 목표, 사용 상황과 가치 정리 | bmad-product-brief에 목적, 제약과 기존 자료 |
| PRD 작성 또는 검증 | bmad-prd에 해당 PRD, 요구와 최신 정정 |
| 실행 가능한 요구 정리 또는 갱신 | bmad-agent-po의 해당 동작에 기존 입력, 합의와 출처 |
| 범위가 정해진 개발 | bmad-build에 ticket 또는 기존 계획과 필요한 companion |
| 모듈 간 책임, 불변 조건과 설계 선택 | bmad-architecture에 기존 ticket과 설계 제약 |

담당 skill의 SKILL.md로 진입해 해당 동작을 적용하고 기존 결과가 충분하면 재사용한다. 필요한 담당을 사용할 수 없으면 가능한 조회와 미실행 범위를 밝히며 절차를 추측하지 않는다. 명확한 설명, 조회와 작은 수정은 해당 기능에서 바로 처리하고 새 인터뷰나 요구 원장을 만들지 않는다. Build에 Brief, PRD 또는 PO 선행을 일괄 강제하지 않는다.

## 요구 변경과 전환

사용자의 새 메시지가 기존 목표를 보완하면 유효 요구와 영향을 갱신하고 바뀐 부분의 계획/구현/검증만 재검토한다. 질문이나 상태 요청이면 답한 뒤 승인된 원래 작업을 계속한다. 명시적 취소/목표 교체는 중단 경계와 현재 변경을 확인하고 새 범위로 전환한다.

대상·승인이 불명확하면 그 정보에 의존하는 행동만 보류한다. 독립적으로 진행 가능한 조회는 계속할 수 있다. 기록 저장과 승인 판정은 동일한 동작이 아니다.

목적과 사용 상황, 범위와 권한, 보존 조건과 기존 연결, 대안과 부담, 예외와 실패, 완료 기준 중 이번 결과를 바꾸는 관점만 확인한다. 순서, 분기, 책임과 입출력이 요구를 바꾸는 경우 함께 대조한다. 이미 답한 내용은 재사용하며 고정 설문이나 확정된 순서의 재승인으로 만들지 않는다.

이미 확정된 요구와 제약은 상충하는 새 사용자 발언이나 관측 근거가 없는 한 유지한다. 문서 표현 차이나 에이전트 제안만으로 이를 가정이나 미결로 낮추지 않는다. 방향 수용, 실제 실행 승인과 기록할 위치의 선택을 구별하고, 기록 방법의 미정 때문에 수용한 방향을 다시 선택하게 하지 않는다.

관측된 문서 불일치와 변경 경위의 확인은 구분한다. 자료의 이름이나 표현 차이만으로 변경 원인이나 저장 목적지를 정하지 않는다. 가능한 시나리오를 설명할 필요가 있으면 성립 조건을 명시하고, 가능성만으로 실제 정책 위반이라고 판정하지 않는다.

질문하기 전에 그 답이 지금 요청한 결과나 다음 허용된 행동을 어떻게 바꾸는지 확인한다. 이미 답한 항목은 출처를 재사용하고, 지금 결정하지 않아도 되는 기술, 수치와 새 기능을 추가 승인 질문으로 만들지 않는다. 원본 절차가 요구하는 가정과 미결 목록은 보존하되 현재 필요한 확인과 이후 선택을 구분한다. 중요한 새 해석이나 범위 또는 권한 변경에 필요한 질문은 생략하지 않는다. 요청 결과와 필요한 미결을 먼저 짧게 전달한다.

명시된 사용자 요구와 승인은 출처와 함께 소비한다. 중요한 의미를 추가하거나 선택을 좁히는 해석은 차이와 영향을 제시하고 확인 전에는 가정, 제안 또는 미결로 둔다. 설명 이해, 정리 동의와 일부 단계 승인을 실행, 전송 또는 배포 승인으로 확대하지 않는다. 최신 사용자 정정과 실제 원문을 과거 에이전트 요약보다 우선하고 기존 요구 ID와 결정 중 영향받는 항목만 담당 기능에서 갱신한다.

원문 위치와 필요한 짧은 발췌는 해석 및 결정과 구분해 기존 source 또는 수용 가능한 companion에 연결한다. 출처 부재나 접근 실패는 미확인이며 요약으로 원문을 복원하지 않는다. 새 상시 대화 원장이나 대화 전체 사본을 만들지 않는다. 실행과 설계 담당은 ticket/계획의 Constraints, Boundaries, Done when과 필요한 companion을 실제 소비해 변경 범위와 미결을 대조한다. 중요한 충돌은 영향받는 동작 전에 요구 정본을 소유한 기능에 연결한다. Build의 의도 인터뷰 금지와 ticket sources 재독 금지 계약은 유지한다.

## 검증과 실패

검증은 요청 결과에 필요한 실제 근거로 수행하고 형식 검사, 정적 대조와 실제 실행을 구별한다. 이미 통과한 검사는 새 변경/실패/미결이 없는 한 불필요하게 반복하지 않는다.

완료 검수에서는 요구 ID와 완료 기준을 변경 결과 및 검증 증거와 대조해 누락, 범위 밖 추가, 의미 변경과 미실행 검증을 확인한다. 원문 역대조가 필요하면 요구 정본을 소유한 PO 또는 해당 검수자가 sources와 사용자 정정을 대조하고 요구를 정정한다. 구현 담당에게 모든 대화의 재독을 강제하지 않는다.

담당 절차가 요구하는 기록을 먼저 저장하고 그 결과에 의존하는 문서를 갱신한다. 기록 명령 실패 시 원인과 부분 변경을 확인하고 복구한 뒤 의존 갱신을 진행한다. 이미 갱신된 문서는 담당 기능에서 기록 순서와 내용을 복구한다. 마지막 명령 성공이나 exit 0으로 앞선 실패를 숨기지 않으며 기록, 문서와 검증의 미완료 범위를 밝힌다.

내용의 적합성과 절차 수행, 검사 오류와 발견 사항을 구분한다. 원본 절차가 독립 검수를 요구하면 실제 실행과 함께 검수자, 검수 대상과 해당 회신을 연결하는 증거를 확인한다. 대기 호출의 성공이나 빈 결과만으로 검수 완료를 주장하지 않으며 회신이 없으면 미실행 또는 미확인으로 보고한다. 환경상 불가능하면 원본이 허용한 대안을 확인하고 미실행을 밝힌다. 사후 평가나 내용 검사 통과로 요구된 독립 검수 실행을 대신하지 않는다.

실패 시 요구/설계/구현/환경 중 어느 판단이 필요한지 확인하고 해당 부분으로 돌아간다. 같은 시도를 새 근거 없이 반복하지 않는다. 추가 시도에 새 근거와 의미 있는 검증 방법이 있으면 진행하고, 외부 조건/권한/사용자 선택이 필요하거나 진전이 없으면 현재 증거와 다음 선택을 알린다. 횟수만으로 일괄 종료하지 않되 호스트의 강제 한계는 따른다.

검증 실패를 더 강한 권한, 종료/삭제 또는 범위 확대의 승인으로 취급하지 않는다.

## 중간 요청과 중단

사용자가 설명을 요청하면 현재 작업의 상태와 연결해 답하고 작업 범위를 임의 교체하지 않는다. 중단/인계가 필요하면 완료와 미완료, 미반영 요구, 다음 행동을 담당 skill의 기존 작업 정본에 남기고 기록 조회와 연결이 필요할 때 document를 적용하며 실제 전달과 재개는 session에 맡긴다. 인계 준비 완료와 전체 목표 완료를 구별한다.

BMAD 기록의 요구와 상태 갱신은 담당 BMAD 기능이 소유한다. session은 기존 기록 포인터, 저장 이후 정정과 검증 결과, 실제 checkout을 대조해 최신 합의, 미결과 첫 행동을 담당 기능에 전달한다. 기록 접근, 전달 접수와 실제 재개 성공을 구분하고 접근 실패를 재개 완료로 보고하지 않는다. 사용자 세션의 clear나 종료를 임의 실행하지 않는다.

## 역할 경계와 적용

공통 원칙은 상시 판단, 이 파일은 필요한 작업 조정, skill은 업무 절차와 산출물 작성 및 검증, document는 자료 보관과 검색 및 기록과 지식 연결, session은 호스트 운영, hook은 관측 가능한 이벤트 감지/검사를 담당한다. 이 파일은 hook 등록, 상태 주입이나 권한 시스템이 아니다.

Codex/Claude는 같은 원본을 사용하고 호스트 도구 차이는 각 adapter/skill 연결이 소유한다. 생성된 지침과 이 파일은 함께 접근 가능한 위치에 배치해야 한다. plugin 루트 파일 생성만으로 자동 로드됐다고 판단하지 않는다.
