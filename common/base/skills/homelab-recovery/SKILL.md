# homelab-recovery

## 목적과 역할 경계

복구 준비와 검증 근거를 관리한다. 기존 백업 도구, 복원 실행기와 런북을 재사용하고 새 백업 엔진이나 실행 상태 DB를 만들지 않는다. 실제 관측은 homelab-audit, 관계와 장애 의존성은 homelab-architecture, 작업 이력은 homelab-record에 맡긴다. 단독 호출할 수 있으며 homelab 진입점을 요구하지 않는다.

## 입력과 전제

보호 대상과 장애 가정, 요청 범위, 기존 작업과 런북, 백업 후보 및 승인된 실행점을 확인한다. 연결이 불명확할 때만 [저장소 연결](../homelab/references/repository.md)을 읽는다. 이미 확인한 자산과 권한, 관측 결과는 재사용한다.

| 요청 범위 | 수행 경계 |
|---|---|
| 준비 점검과 계획 | 접근 가능한 기록과 절차를 읽어 필요한 백업, 의존성과 검증 단계를 정리한다. 복호화, 설치나 복원은 실행하지 않는다. |
| 백업 검사 | 승인된 후보와 검사 범위만 기존 도구로 확인한다. 복호화, 임시 쓰기와 lock이 필요한 검사는 부작용과 실행 권한을 먼저 확인한다. |
| 격리 복원 시험 | 승인된 격리 실행점과 백업만 사용한다. 운영 대상으로 전환하지 않으며 실제 독립 복구 성공과 구분한다. |
| 실제 복구 | 대상과 장애 범위, 중단과 데이터 교체 영향이 승인된 경우에만 기존 런북으로 실행하고 검증한다. 준비 점검이나 격리 시험 승인을 확대하지 않는다. |

기존 승인은 대상과 부작용 범위가 같으면 재사용한다. 범위가 부족한 행동만 보류하고 필요한 계획은 계속한다. 자료가 없다는 것과 백업이 없다는 것은 구분한다.

## 수행 방법과 절차

1. record 연결로 기존 작업과 미확인, 취소된 훈련 및 이전 결과를 확인한다. 설정 source, 실행기와 writer의 현행 여부를 읽고 폐기된 도구의 과거 절차를 실행 후보로 되살리지 않는다. 요청에 필요한 자료나 실행기가 없으면 그 단계만 보류하고 없는 원인을 남긴다.
2. 보호 범위를 설정과 코드, 데이터와 일관된 복구 시점, 암호화 및 인증 참조, 외부 의존성으로 구분한다. 복구 가능한 source revision과 도구 버전의 호환 조건, 보존 주기와 별도 장애 영역의 사본을 확인한다. 허용 데이터 손실 시간과 목표 복구 시간인 RPO와 RTO는 기존 목표를 찾고 없으면 미정으로 남긴다. 임의의 수치로 요구를 만들지 않는다.
3. 장애가 난 관리 서버 없이 백업, 정본, 키와 인증, 네트워크 및 필요한 실행기를 회수할 수 있는지 확인한다. 같은 물리 호스트나 스토리지에 의존하거나 순환 의존성이 의심되면 architecture 연결로 필요한 관계만 점검한다. 문서상 독립 실행점이 있다는 것과 그 실행점에서 접근 및 복원에 성공한 것은 구분한다.
4. 현재 백업이나 접근 상태가 필요하면 audit 연결로 대상과 필요한 관측만 확인한다. 생성 시각, 실제 회수 가능 여부, 검사 시각과 신뢰한 manifest의 출처를 구분한다. 파일과 checksum sidecar가 함께 있다는 것만으로 진위, 복호화 가능성이나 데이터 일관성을 보장하지 않는다. 최신성 판단에는 장애 기준 시각과 복구 지점을 사용하고 파일 수정 시각만 신뢰하지 않는다.
5. 실행 전 실제 script와 런북의 입력, 대상 기본값, 임시 파일, lock, 복호화, 네트워크와 서비스 영향을 읽는다. verify, check, dry-run 이름으로 읽기 전용이라 판단하지 않는다. 호스트의 해당 검사 또는 복구 가드와 승인, 필요한 자격증명 접근 및 기록 가능 여부를 확인한다. 비밀 원문을 수집하거나 설정의 기존 잠금 상태를 바꾸지 않는다. 도구나 키가 없으면 승인 없는 설치, 발급 또는 권한 확대로 보완하지 않는다.
6. 격리 시험은 실제 대상 identity와 실행기 인자, Compose project나 VM 이름, 경로와 mount, DB, 포트, 네트워크 및 인증 경계가 운영과 분리됐는지 대조한다. 운영 기본 경로가 남거나 분리가 불명확하면 시작하지 않는다. 복원된 scheduler, webhook이나 job이 운영 대상으로 자동 실행될 위험을 시험 환경에서 차단한다. 차단을 위해 정상 운영 설정을 바꾸지 않는다. 격리 자원 생성과 정리도 승인 범위와 기존 도구를 따른다.
7. 승인된 검사는 백업 도구가 지원하는 암호문 무결성, 제한된 임시 복호화, archive 경로와 payload, DB 무결성과 source 호환성을 필요한 순서로 수행한다. 실패하면 복원으로 진행하지 않는다. 복원 실행이 포함된 경우만 보존할 기존 데이터와 실패 시 복귀 경로, 중단 조건을 대조한 후 같은 대상의 기존 실행기로 처리한다. 복귀도 승인된 범위만 실행하며 결과를 재확인한다. lock 충돌이나 권한 거부를 강제로 해제하거나 다른 실행점으로 우회하지 않는다.
8. 실행 결과와 작업 ID를 audit 연결로 검증한다. HTTP 정상이나 프로세스 기동 외에 대표 데이터와 설정, 권한 및 서비스 기능을 확인한다. 자동화 서비스라면 project, template과 inventory 등 복원된 의미를 확인하되 임의 운영 job 실행으로 시험하지 않는다. 백업 파일 검사, 격리 앱 복원, 장애 가정 아래 독립 복구, 실제 운영 정상화는 각각 별도 결과로 남긴다. RPO와 RTO 충족은 측정한 복구 지점과 소요 범위가 있을 때만 판단한다.
9. 임시 평문, 시험 자원과 자격증명 참조는 기존 절차와 승인된 수명 범위대로 정리하고 잔여 여부를 확인한다. 필요한 실패 증거와 기존 백업, 정상 운영 자원은 보존한다. 정리 실패나 접근 불가는 숨기지 않고 추가 실행을 멈춰 후속을 남긴다. record 연결로 검사 및 복원 결과, 확인 시각과 revision, 회수 경로, 실패와 복귀 결과, 미확인 및 다음 조건을 기존 작업에 연결한다. secret과 백업 payload 원문은 기록하지 않는다.

## 연계와 의존

| 대상 | 활용 조건과 입력 | 결과와 부재 시 동작 |
|---|---|---|
| [homelab-audit](../homelab-audit/SKILL.md) | 현재 백업 및 접근, 복원 결과의 관측이 필요할 때 대상과 장애 가정, 후보 revision, 승인된 실행점, 관측 범위와 의미 검증 기준 전달 | 관측 시각과 성공 범위, 일치, 불일치, 미확인. 해당 관측에 필수이며 없으면 관련 성공 판정을 보류한다. 기록 기반 계획은 계속할 수 있다. |
| [homelab-architecture](../homelab-architecture/SKILL.md) | 장애 영역과 독립 실행점 또는 순환 의존 점검에 기존 관계 정본, 장애 대상, 회수 및 복구 경로와 근거 전달 | 의존 관계와 근거 및 미확인. 관계 점검에 필수이며 없으면 독립성 판정을 보류한다. 이미 받은 결과는 재사용하고 점검만 할 때 작도를 요구하지 않는다. |
| [homelab-record](../homelab-record/SKILL.md) | 기존 후속 조회와 결과 기록에 대상, 작업 포인터, 검사 및 복구 범위, 실행 ID, source와 백업 식별자, 관측과 정리 결과 전달 | 기존 미확인과 실제 저장 위치. 해당 조회와 기록에 필수이며 읽지 못하면 미확인이 없다고 하지 않는다. 기록이 불가하면 추가 실행을 보류하고 이미 수행한 범위와 미기록을 보고한다. |
| [session](../session/SKILL.md) | 사용자가 승인한 다른 실행 주체에게 맡길 때 확인된 수신자, 장애와 대상, 자산 및 인증 참조, 승인과 가드 범위 및 회신 위치 전달 | 전달 receipt와 실제 회신 근거. 해당 위임에 필수이며 없으면 전달을 보류한다. 거부된 작업의 우회 실행점을 찾지 않으며 receipt만으로 복구 성공을 판정하지 않는다. |

대상의 SKILL.md에서 해당 절차와 공통 제약을 적용한다. 외부 제공자나 실행기가 자체 검사를 했으면 충분한 결과를 재사용한다. 위임하지 않는 요청에서 session을 읽지 않는다.

## 제약과 주의점

- 홈랩의 실제 보호 자산과 도구는 private repo의 안내를 소비한다. 특정 OS, 가상화 플랫폼이나 Semaphore를 모든 대상의 필수 실행기로 강제하지 않는다. 공개 지침에 개인 주소, 키 위치나 topology를 복제하지 않는다.
- 복구 도구의 존재, 합성 자료 시험과 과거 실행 결과를 오늘의 복구 가능성으로 승격하지 않는다. 백업을 만든 호스트와 같은 장애 영역의 사본만으로 독립성을 확정하지 않는다.
- 실행 지침 작성과 source 저장은 훈련 실행, 운영 데이터 교체, 서비스 중단, commit이나 push 승인이 아니다. 실패 시 새 백업으로 기존 검증 후보를 덮거나 정상 운영 데이터를 시험용으로 복사하지 않는다.

## 결과와 완료 판단

대상과 장애 가정, 수행 범위, 백업과 source 식별자 및 확인 시각, 회수와 키 접근의 근거, 검사와 복원 및 서비스 검증, 정리와 기록 결과 및 남은 미확인을 반환한다. 계획 요청은 계획과 미확인 정리로 완료할 수 있다. 실행 요청은 그 범위의 복원, 의미 검증과 정리 증거가 있어야 완료하며 부족한 단계는 분명히 남긴다.
