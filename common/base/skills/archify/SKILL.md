# archify

## 목적과 역할 경계

- 확인된 구조·관계·근거와 독자·출력 형식을 공식 시각화 기능에 전달한다. 새 설계 결정을 그림 생성 과정에서 확정하지 않는다.
- 일반 구조/흐름의 기본 선택이다. 수치 차트·일정·칸반·사용자 여정은 diagram-design이 맡으며 사용자가 도구를 명시하면 그 선택을 우선한다. 같은 결과물에 두 도구를 기본으로 연속 적용하지 않는다.

## 입력과 전제

- 실제 대상·관계·source 근거·미확인, 독자·상세도와 요청 형식·저장 위치를 받는다. 기존 산출물과 요청 경로를 재사용하고 새 전역 자료 위치를 만들지 않는다.
- 공식 설치본의 Node·browser/resources·출력 경로와 네트워크 부수효과를 확인한다. 공식 finalize/deliver의 업데이트 확인·cache 효과도 실행 범위와 대조하며 생성 요청을 설치·업데이트·게시로 확대하지 않는다.

## 수행 방법과 절차

1. 아래 공통 연결로 공식 SKILL.md에 진입하고 해당 요청의 type·reference·schema·검증 절차를 적용한다. 공식 root·실제 cwd·meta.output 계약을 구분하고 kit 안의 복제 runtime을 실행하지 않는다.
2. 내용·관계와 근거는 업무 담당이 소유한다. 파일/줄/commit 형식 검사가 관계 의미까지 증명한다고 보지 않는다. 공식 예시를 실제 프로젝트 사실로 사용하지 않는다.
3. 공식 실패·복구·업데이트 안내 계약을 유지한다. 자동/브라우저 검사·capture·실제 시각 검수를 구분하고 하지 않은 검사를 통과로 보고하지 않는다. 실패를 다른 시각화 도구로 조용히 대체하지 않는다.

- 실제 산출물과 원래 관계/근거 대조, 공식 검사의 범위와 실패·미실행을 반환한다. 로컬 HTML을 게시 URL이나 실제 사람이 확인한 화면으로 보고하지 않는다.
