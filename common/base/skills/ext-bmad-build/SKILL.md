# ext-bmad-build

## 목적과 역할 경계

- 기능·버그·의미 있는 코드 변경의 구현과 검증을 공식 build에 연결한다. 단순 오탈자·형식 정리·기존 변경의 Git 기록은 제외한다.
- 이 파일은 자체 연결이다. 공식 절차·template·runtime을 포함하거나 재작성하지 않는다.

## 입력과 전제

- 기존 티켓/계획의 Constraints·Boundaries·Done when, companion·현재 코드·승인 범위.
- 현재 제품·실제 프로젝트 cwd·kit root와 명시 외부 연결 선언을 확인한다. 이미 확인한 요구·설치 근거는 재사용한다.

## 수행 방법과 절차

- 변경 전에 요청이 적용될 버전이나 리비전을 확인하고, 그 버전에서 요청한 동작의 진입점과 관련 코드·설정을 대조한다. 정적 확인만으로 작업 범위를 정하기 어려우면 승인 범위에서 기존 테스트나 작은 재현으로 확인한다.
- 이미 충족하는 동작은 재사용한다. 조건부로 지원하면 필요한 조건과 요청에서 빠진 부분을 확인하고, 동작이 없거나 일부만 충족하면 그 차이만 구현 범위에 넣는다. 확인하지 못한 조건이나 동작은 미확인으로 남긴다. 이 판단과 근거를 공식 build에 전달한다.
- [BMAD 공통 연결](../ext-bmad/references/connection.md)을 적용해 아래 ID의 공식 설치본으로 진입한다. 공통 절차와 조건에 맞는 추가 절만 읽는다.
- 공식 기능이 만든 산출물과 실제 결과를 아래 필요한 결과·원래 요구와 대조한다. 지침 참조·렌더·실제 실행·완료를 구분한다.
- Android·Wear OS의 전문 판단이 필요한 경우만 [Android 작업 기준](../../references/android-work.md)의 입력·범위·결과 조건과 요청별 분기로 필요한 연결을 선택한다. 기존 공식 build의 수행·작업 정본을 대체하거나 모든 전문 skill을 순서대로 실행하지 않는다.

## 연계와 의존

| 대상 | 전달 입력·필요 결과 | 필수 여부·부재 처리 |
| --- | --- | --- |
| 외부 연결 `bmad-build` · 종류 `skill` | 위 입력. 필요한 결과: 구현·리뷰·실행 검증과 완료 기준 대조, 실패·미실행·미결 | 해당 공식 수행에 필수. 부재·미지원·pin drift는 수행 보류. 원문 복제·동명 wrapper·다른 공급자로 대체하지 않음 |

## 결과와 완료 판단

- 구현·리뷰·실행 검증과 완료 기준 대조, 실패·미실행·미결. 적용한 실제 공식 기능·검증 범위·미결을 함께 반환한다.
- 공식 기능 부재 상태의 계획·입력 확인을 실제 외부 수행 완료로 보고하지 않는다.
