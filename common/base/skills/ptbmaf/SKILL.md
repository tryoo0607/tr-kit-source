# PTBMAF

## 목적과 역할 경계

- 제안에 시간과 비용을 들일 이유가 있는지, 어떤 관측이 판단을 바꿀 수 있는지 정리한다. 규모나 기간과 무관하게 현재 판단에 필요한 항목만 사용한다.
- 여기서 나온 판단을 구현 계획, 작업 상태, 사용자 승인과 구분한다.

## 입력과 전제

- 판단할 제안이나 문제, 실제 영향과 근거, 알려진 대안과 제약, 이미 합의한 내용.
- 다시 검토하는 건이면 대상 작업의 기존 문서와 새로 확인한 근거. 작업 이름이나 연결된 문서가 있으면 그 자료부터 확인한다.

## 수행 방법과 절차

1. 결정할 질문을 한 문장으로 잡는다. 문제의 영향과 현재 방식, 지금까지 확인한 사실을 대조한다. 기존 조사나 출처를 재사용하고 가정과 확인되지 않은 사항은 구분한다.
2. 판단이 달라질 만한 대안과 감수할 비용을 비교한다. 기존 방식이나 현 상태를 유지하는 경우도 비교에 의미가 있으면 포함한다. 작은 실험이 필요한 경우에만 성공 지표, 계속하거나 멈출 기준, 결과를 반영할 방법까지 정리한다.
3. 현재 근거로 가능한 판단과 핵심 이유를 제시한다. 근거가 부족해서 결론이 달라질 수 있으면 무엇을 관측할 때 다시 판단할지 구체적으로 적는다.
4. 그 자리에서 판단이 끝나고 다시 쓸 이유가 적으면 대화에 남긴다. 후속 판단에 재사용할 근거라면 쓰기가 허용된 기존 조사·제안 문서에 **검토한 질문, 판단 근거와 출처, 현재 판단, 해당하는 경우 다시 볼 조건**을 남긴다. 판단을 독립적으로 찾아 볼 필요가 있을 때만 허용된 위치에 별도 문서를 만들고 기존 기록에서는 그 문서를 링크한다.
5. 다시 검토할 때는 먼저 기존 문서를 찾고 새 근거를 대조해 같은 기록을 갱신한다. 결론이 달라졌으면 새 판단과 함께 무엇이 판단을 바꿨는지 남긴다. 다음 행동과 진행 상태는 프로젝트에서 이미 관리하는 작업 기록을 사용한다.

## 연계와 의존

| 대상 | 전달 입력·필요 결과 | 적용 조건 |
| --- | --- | --- |
| [document](../document/SKILL.md) | 작업 이름과 기존 포인터를 전달해 관련 문서의 정본 위치를 확인한다. | 기존 기록의 위치나 소속을 찾아야 할 때 사용한다. 저장할 위치가 확인되지 않으면 대화에 판단을 남긴다. |
| [Ask me](../../references/ask-me.md) | 사용자와 방향이나 시나리오를 정해야 할 때 현재까지 확인한 근거와 결정할 질문을 전달한다. | 현재 판단에 필요한 사용자 선택이 있는 경우에만 연결한다. |
| [ext-agentops-plan](../ext-agentops-plan/SKILL.md) | 착수가 정해졌을 때 합의한 목적, 범위와 검토 근거를 전달한다. | 구현 계획이 요청된 경우에 연결한다. |

프로젝트 제안에 쓰인 항목은 [PTBMAF 사용 사례](https://kimstar.kr/10675/#1-Pager_PTBMAF_framework)를 참고했다. 위의 보관과 갱신은 킷의 적용 기준이다.

## 결과와 완료 판단

- 판단과 근거, 판단을 바꿀 수 있는 조건이 필요한 경우 그 조건을 반환한다. 문서를 갱신했다면 실제 위치를 알려준다.
- 새 기록이나 갱신본은 확인한 사실과 가정을 구분하고, 출처를 따라가거나 현재 판단을 다시 검토할 수 있어야 한다.
