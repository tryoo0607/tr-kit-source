# ext-frontend-design

## 목적과 역할 경계

- 실제 brief·기존 화면·디자인 체계와 승인된 범위를 공식 디자인 기능에 전달한다. 공식 미학·제작 절차를 자체 본문으로 복제하지 않는다.
- 작은 수정에 전면 재설계·새 stack·별도 작업 계획을 자동 추가하지 않는다.

## 입력과 전제

- 요청한 화면·사용 목적·실제 콘텐츠, 기존 디자인 시스템·접근성·스타일과 보존/변경 범위를 받는다. 기존 BMAD 계획·UX 결과를 재사용한다.
- 입력에 없는 고객의 이력·거절한 시안·선호를 사실로 만들지 않는다. 공식 지침의 역할극/예시도 실제 사용자 사실의 근거가 아니다.

## 수행 방법과 절차

1. 아래 외부 연결 계약으로 `frontend-design`, 종류 skill의 공식 설치본을 확인하고 그 SKILL.md로 진입한다.
2. 실제 brief·보존할 요구·허용 범위·필요 결과를 전달해 공식 절차를 적용한다. 사실/제안·권한/자료 경계는 단계 전환 뒤에도 유지한다. 필수 원문 절차와 충돌해 원문 변경이 필요하면 해당 부분을 보류·보고한다.
3. 결과를 원래 brief와 실제 코드/산출물에 대조한다. 별도 UI 동작 검증이 요청되거나 완료 기준에 필요하면 아래 playwright 연결을 적용한다. 화면 캡처·렌더 관측·기능 통과를 구분한다.

## 연계와 의존

| 대상 | 전달 입력·필요 결과 | 필수 여부·부재 처리 |
| --- | --- | --- |
| 외부 연결 `frontend-design` · 종류 skill. [공통 외부 연결](../../references/external-connection.md) | 실제 brief·기존 체계·제약·승인 범위. 필요한 결과는 UI/설계 산출물·디자인 근거·검토와 미결 | 공식 디자인 수행에 필수. 부재 시 자체 원문 사본·다른 공급자로 대체하지 않고 입력 정리/계획 가능한 부분과 수행 미실행을 구분 |
| [ext-playwright-cli](../ext-playwright-cli/SKILL.md) | 실제 URL·시나리오·viewport·허용 저장 범위. 필요한 결과는 assertion·렌더 관측·오류·산출물 위치 | 동작/렌더 검증에 선택. 부재 시 정적 검토와 실행 미실행을 보고하며 브라우저 설치로 확대하지 않음 |

## 결과와 완료 판단

- 실제 변경/산출물, brief·보존 요구와의 대조, 디자인 판단과 실행 검증·미실행을 구분한다. 스타일 설명을 실제 UI 구현이나 기능 통과로 보고하지 않는다.
