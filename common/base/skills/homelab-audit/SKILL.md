# homelab-audit

## 목적과 역할 경계

조회에 성공한 범위만 비교하고 증거를 반환한다. 실제 상태를 repo로 자동 채택하거나 서버를 정본으로 덮지 않는다. 홈랩 진입점을 거치지 않고 단독 실행할 수 있다.

## 입력과 전제

대상 ID, 설정 source와 소유자, 관측 범위 및 기존 기록을 받는다. 연결이 없거나 불명확하면 [저장소 연결](../homelab/references/repository.md)을 읽는다. 이미 확인된 연결과 출처는 재사용한다.

## 수행 방법과 절차

1. 대상 identity와 관리 경계, 현재 호스트 역할과 허용된 조회 경로를 확인한다. 가드가 거부하면 우회하지 않는다. 로컬 snapshot 비교와 실제 서버 조회를 구별한다.
2. README가 안내한 대상별 조회법을 읽고 필요한 부작용과 권한을 확인한다. Ansible check, shell의 --check 또는 --verify라는 이름만으로 무변경을 보장하지 않는다. 실행이 불가하면 이유와 확인할 실행점을 반환한다.
3. 의도 source와 실제 관측의 시각, 범위, 조회 성공 여부를 확보한다. 접속 실패, 권한 부족, 일부 조회, 오래된 관측은 미확인으로 남긴다. 조회 실패가 빈 출력 파일로 보이지 않게 한다.
4. secret과 개인 데이터는 수집 전에 제외한다. 생성된 파일, 기본값, 동적 값과 환경별 override는 저장소가 정한 기준으로 정규화한다. 값과 소유자가 불명확하면 임의로 제외해 차이를 없애지 않는다.
5. 정규화가 끝난 비밀값 없는 일반 파일 snapshot 두 개의 제한된 비교에는 이 스킬 루트의 scripts/compare-snapshots.py를 사용할 수 있다. 명령은 python3 <skill-root>/scripts/compare-snapshots.py EXPECTED OBSERVED이며 실행 위치는 어느 곳이든 가능하다. 종료값 0은 match, 1은 drift, 2는 unknown이다. JSON의 scope는 file_snapshot이며 live 시스템 확인을 의미하지 않는다. 디렉터리, symlink, 같은 inode, 누락/읽기 실패는 unknown이다. 스크립트는 네트워크 조회, 정규화나 snapshot 수집을 하지 않는다.
6. 파일이 일치해도 서비스가 해당 설정을 읽었는지, 재시작 여부와 실효 설정/대표 기능은 대상별 증거로 별도 확인한다. 모든 비교 항목과 의미가 확인돼야 요청 범위의 적용 여부를 판정한다.

## 제약과 주의점

사용자 승인 범위를 넘어 조회 범위를 늘리지 않는다. raw diff나 credential을 출력하지 않는다. snapshot은 허용된 임시 위치에 두고 보관/정리는 해당 자료 정책을 따른다. 비교 도구의 결과만으로 실서버 적용 완료나 복구 성공을 선언하지 않는다.

## 결과와 완료 판단

대상, source revision, 관측 시각과 조회 경로, 비교 범위와 제외 기준, 항목별 일치/불일치/미확인, 실효 설정 확인 여부와 다음 확인을 반환한다. 파일 비교와 실제 적용 판정은 별도로 표시한다. 기록 변경은 요청된 경우 homelab-record가 맡도록 결과를 전달하며 여기서 별도 로그나 상태 DB를 만들지 않는다.
