# Git 전역 제외와 백업 예외

Git 제외 설정 변경이나 추적 예외를 요청받은 경우만 읽는다. 원본/문서 보관 자체의 필수 실행 단계가 아니다.

## 입력과 전제

- 실제 호스트·선택 전역 제외 파일·현재 core.excludesFile·기존 규칙을 확인한다. 백업 예외가 필요하면 명시된 tr-local-docs의 실제 저장소 루트를 받는다. 다른 저장소/비슷한 이름으로 추정하지 않는다.
- 변경 전 계획과 보존할 기존 규칙, 설정/파일 쓰기 범위를 승인과 대조한다. 이미 승인된 범위를 다시 묻지 않는다.

## 수행 방법과 절차

1. 자체 [git-excludes.py](../../../scripts/git-excludes.py)에 `--excludes <확인한 파일>`과 필요 시 `--backup <tr-local-docs 루트>`를 전달한다. 기본 실행은 계획만 반환한다. 생략한 excludes는 현재 Git 전역 설정 또는 XDG_CONFIG_HOME/기본 .config의 git/ignore를 선택한다.
2. 명시적 적용만 `--apply`를 사용한다. 정확히 `_bmad/`, `_bmad-output/`, `_tr-assets/`를 추가하고 기존 규칙은 유지한다. `_bmad*` 같은 광범위 패턴을 만들지 않는다. tr-local-docs의 .gitignore에만 `!_bmad-output/`를 추가한다.
3. 일반 프로젝트와 백업 저장소 각각의 `git check-ignore`·상태·staged diff를 확인한다. 제외는 이미 추적된 파일을 untrack하지 않는다. 예외는 다른 secret/금지 경로 규칙을 무효화하지 않는다. 예외 파일 커밋과 push는 별도 승인/보안 검사 범위를 따른다.

## 제약과 주의점

- helper는 symlink 경유 쓰기를 거부하고 일반 파일/설정을 갱신한다. 여러 파일과 Git 설정의 원자적 transaction은 아니다. 실패 시 일부 반영 가능성을 알리고 실제 제외 파일·전역 설정·backup .gitignore를 대조한 뒤 보완한다. 통과시키기 위한 검사/신뢰 우회는 하지 않는다.
- 전역 설정 적용은 이관·백업 실행이나 수집 허용을 뜻하지 않는다. 실제 백업 설치/실행은 해당 담당이 소유한다.

## 결과와 완료 판단

- 선택 파일·추가 규칙·백업 예외·실제 Git 판정·미반영/부분 변경을 보고한다. 계획 출력을 실제 활성화로 보고하지 않는다.
