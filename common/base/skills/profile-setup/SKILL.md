# profile-setup

## 목적과 역할 경계

코드·문서·assets 경로와 공유 정책의 설정 작성 및 검증을 맡는다. 코드 공간의 등록/조작은 project, 문서 내부 구조와 내용은 document가 소유한다. 외부 skill include와 배포 조립 선언은 해당 조립 계약이 소유하며 이 skill의 런타임 설정과 구분한다. 소비자는 일상 작업에 필요한 규격만 조회한다.

## 입력과 전제

대상 호스트, 요청한 설정과 값, 실제 설정 파일과 소비하는 도구를 확인한다. 설정을 작성하거나 해석할 때 [config-schema.md](references/config-schema.md)의 필드, 기본값과 검증 규칙을 사용한다. 새 규격 초안이며 실행 도구의 지원 여부는 별도로 확인한다.

| 설정 범위 | 확인할 내용 |
|---|---|
| 경로와 연결 | 코드, 문서, assets 루트와 소속별 예외 위치. 개인 knowledge의 독립 경로 |
| project/group 식별 연결 | 기존 등록과의 연결. Orca 등 정본의 소속 명부를 별도 사본으로 만들지 않음 |
| 공유 정책 | 동기화 여부, 허용 대상 식별자, 원격 연결과 제외 범위. common과 개인 knowledge 정책을 독립 확인 |

이 표는 관리 범위이며 필드 정본은 설정 규격이다. 문서 본문, 작업 상태와 학습 기록은 설정에 넣지 않는다.

## 요청별 분기

| 요청 | 선택 조건 | 읽을 reference |
|---|---|---|
| 초기화, 변경 | 해당 요청이 포함됨 | [생성과 변경](references/operations.md#생성과-변경), 입력과 전제·검사 범위·완료/실패 기준 |
| 조회, 점검, 적용 전 계획 | 해당 요청이 포함됨 | [읽기 전용 점검과 계획](references/operations.md#읽기-전용-점검과-계획), 입력과 전제, 검사 범위, 완료/실패 기준 |
| 미지원 설정 설계 | 해당 요청이 포함됨 | [미지원 설정 설계](references/operations.md#미지원-설정-설계), 입력과 전제, 완료/실패 기준 |

같은 요청은 위에서부터 처음 일치한 하나만 선택한다. 별도 추가 요청은 각각 선택하고 동일 자료는 다시 읽지 않는다. 설정 규격은 관련 필드만 공통 확인한다.

## 제약과 주의점

- secret과 credential 원문은 설정, 변경 계획이나 출력에 넣지 않는다. 인증 연결이 필요하면 설정 계약이 지원하는 비밀값 참조를 사용한다. 참조 방식이 없으면 설계가 필요한 조건으로 알린다.
- 공유 설정은 실제 Git 추적 범위와 실행 도구가 이를 지킬 수 있어야 한다. 설정 저장은 동기화 실행이나 반출 승인이 아니며, 이미 추적된 자료를 config만으로 부분 push에서 제외한다고 가정하지 않는다.
- profile이 없더라도 경로에 의존하지 않는 작업은 계속한다. 필요한 설정이 없는 소비자 작업만 부족한 조건을 알린다.

## 결과와 완료 판단

선택한 reference의 완료 기준으로 변경 경로, 검사 결과와 소비자 실행 미검증을 구분해 전달한다.
