# homelab-architecture

## 목적과 역할 경계

구성 관계의 의미와 근거, 정본 변경을 관리한다. 도식 표현은 diagram-design, 필요한 실제 관측은 homelab-audit, 기록과 미확인 후속은 homelab-record를 재사용한다. 단독 호출할 수 있으며 homelab 진입점을 요구하지 않는다. 설정 배포와 복구 실행, 새로운 inventory DB나 렌더러를 만들지 않는다.

## 입력과 전제

대상과 관계 범위, 요청이 점검인지 정본 갱신인지 작도인지, 기존 정본과 작업 포인터를 확인한다. 연결이 불명확할 때만 [저장소 연결](../homelab/references/repository.md)을 읽는다. 이미 확인된 연결과 변경 결과는 재사용한다. 특정 파일명이나 작도 형식을 새로운 저장소 규격으로 강제하지 않는다.

## 수행 방법과 절차

1. README가 안내하는 inventory, 편집 가능한 구성 정본, 관련 설정과 기존 작업 기록의 필요한 부분을 읽는다. 파일별 revision과 기록 시점, 계획 또는 운영 기록인지 확인한다. 관련 자료에 접근하지 못하면 구성에 해당 대상이 없다고 판단하지 않는다. 갱신 대상 원본이 읽히지 않으면 덮어쓰기를 보류하고 새 구성도 작성 요청과 구분한다.
2. 물리 수용 관계, 가상화와 서비스 배치, 네트워크 경로, 데이터와 저장소, 관리 및 복구 의존성을 구분한다. 기존 ID와 별칭이 같은 대상을 뜻하는지 확인하고, 화살표의 방향과 범례를 읽는다. 관리 권한이 있다는 것과 서비스가 그 호스트에서 실행된다는 것을 혼동하지 않는다.
3. 관계마다 근거를 구분한다. source에 선언된 구조, 과거 관측, 사용자가 현재 운영 사실로 확인한 내용, 미래 계획과 미확인을 섞지 않는다. 설계 승인이나 source 저장만으로 실제 배치를 확정하지 않는다. 자료 간 불일치와 실제 관측 불일치도 나눈다. 시각화에서 생략됐다는 이유로 서비스 제거를 판단하지 않는다.
4. 현재 운영 사실이 필요한 관계만 audit 연결로 관측한다. 이미 받은 충분한 관측은 재사용하고 조회 실패나 범위 밖은 미확인으로 남긴다. 사용자 확정이나 최신 기록도 근거 종류와 적용 범위를 표시한다. 한 관계의 관측 날짜를 전체 구성의 최신 검증일로 확대하지 않는다.
5. 변경안은 추가, 이동, 삭제 또는 상태 변경한 관계와 근거로 좁힌다. 계획은 계획 보기로, 실제 배치는 확인된 범위만 반영한다. 사용 중단 정책과 잔존 프로세스나 데이터의 실제 정리 완료를 구분한다. 관리 실행점과 백업이 같은 장애 영역에 의존하거나 복구 순환 의존성이 있으면 위험과 미확인을 표시하고 record에 후속을 전달한다. 독립 복구가 성공했다고 추정하거나 여기서 복구 절차를 실행하지 않는다.
6. 정본 갱신이 요청됐으면 기존 노드 ID와 관계 의미, 계층과 관련 없는 변경을 보존한 최소 델타 초안을 만든다. 공유 파일의 기존 병행 편집과 통합 규칙을 따른다. ID 충돌, 다른 작업의 변경이나 모호한 관계는 임의 병합하지 않는다. 불확실한 부분은 기존 표기나 연결된 작업 기록에 명시한다.
7. 작도가 요청된 경우만 diagram 연결을 사용한다. 현재 정본과 확정된 델타, 보기 범위 및 미확인을 전달하고 표현과 사실 변경을 분리한다. 개요를 위해 합치거나 생략한 대상은 정본에서 삭제하지 않으며 상세 보기나 생략 내역으로 연결한다. 작도가 필요 없는 관계 점검에 provider 전체와 gallery를 로드하지 않는다.
8. 정본 쓰기 전 현재 파일을 다시 읽고 해당 호스트의 문서 변경 가드와 승인 범위를 확인한다. 초안 기준 이후 다른 변경이 있으면 델타를 다시 대조하며 덮어쓰지 않는다. 검토한 델타만 저장한다. 변경 후 ID와 링크 대상, 관계 방향, 범례와 상태 표기, 관련 없는 변경 보존을 대조하고 지원되는 형식 검사를 수행한다. source의 구문 검사나 그림 렌더 성공을 실제 관계 검증으로 보고하지 않는다.
9. record 연결에 source 변경 범위와 근거, 작도 결과 및 미확인을 전달한다. 기존 운영 변경과 같은 작업이면 결과 포인터를 연결하고 같은 사실을 중복 기록하지 않는다. 점검만 했으면 정본을 갱신했다고 하지 않는다. 실제 조회나 작도를 수행하지 않은 범위도 남긴다.

## 연계와 의존

| 대상 | 활용 조건과 입력 | 결과와 부재 시 동작 |
|---|---|---|
| [homelab-audit](../homelab-audit/SKILL.md) | 현재 배치나 연결을 관측해야 할 때 대상 ID, 확인할 관계와 source, 관리 경계, 관측 범위와 기존 근거 전달 | 관측 시각과 성공 범위, 일치, 불일치, 미확인. 해당 관측에 필수이며 없으면 운영 사실 판정을 보류한다. 기록 관계 점검과 계획 정리는 계속할 수 있다. |
| [diagram-design](../diagram-design/SKILL.md) | 작도 요청 시 기존 편집 원본, 관계와 그룹, 근거 상태와 미확인, 변경 델타, 보기 범위, 독자와 출력 위치 전달 | HTML과 요청한 출력, 원본 대비 병합과 생략 내역, 실행한 검사 및 화면 검수 한계. 작도에 필수이며 없으면 그림 생성을 보류하고 관계 점검 결과를 전달한다. |
| [homelab-record](../homelab-record/SKILL.md) | 기존 미확인 조회나 점검 및 갱신 결과 기록에 대상, 작업 포인터, 변경 이유와 source revision, 관계 근거, 관측/작도 결과와 남은 확인 전달 | 기존 후속, 저장 위치와 기록 결과. 해당 조회와 기록에 필수이며 없으면 미확인이나 기록 완료를 만들지 않고 이미 수행한 범위와 미기록을 보고한다. |

대상의 SKILL.md에서 요청에 필요한 절차와 공통 제약을 적용한다. 충분한 결과가 있으면 다시 읽거나 실행하지 않는다. record가 아키텍처 갱신 필요를 남겼다는 이유만으로 이 스킬을 재귀 호출하지 않는다.

## 제약과 주의점

- 편집 가능한 source를 정본으로 유지하고 HTML 등 렌더 산출물은 연결한다. 그림만 원본으로 덮어쓰거나 전체 관계를 레이아웃 취향에 맞춰 재작성하지 않는다.
- 원본 provider의 style 선택, import와 export 및 검수 절차를 따른다. 설치된 provider를 개인화하거나 자체 작도 절차를 복사하지 않는다. Mermaid를 제공할 때는 사용자가 확대해 볼 수 있는 HTML도 함께 제공한다. 외부 폰트와 렌더 서비스를 사용하지 않는 로컬 출력으로 개인 자료의 외부 요청을 피한다.
- 범위 밖 오버레이, 워크스테이션이나 복구 경로를 조용히 제거하지 않는다. 보기에서 제외한 범위와 관계의 의미를 밝힌다. 과거 계획과 폐기된 구성을 현행으로 되살리지 않는다.
- 개인 주소와 관계 상세는 허용된 private 자료 범위에만 보관한다. 비밀값과 credential을 읽거나 도식에 복사하지 않고 공개 링크로 게시하지 않는다. 정본 변경은 commit, push, 설치나 인프라 적용 승인이 아니다.

## 결과와 완료 판단

읽은 정본과 revision, 대상 및 보기 범위, 근거가 확인된 관계와 불일치 또는 미확인, 저장한 델타, 작도/검사 결과와 실제 기록 위치를 구분해 반환한다. source 정리, 시각화, 실제 운영 확인과 복구 가능성 검증은 각각 별도 상태다. 원본 보존이나 형식 검사에 실패하면 추가 덮어쓰기를 멈추고 이미 발생한 변경과 필요한 후속을 남긴다.
