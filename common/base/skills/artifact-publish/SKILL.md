# 아티팩트 게시

## 목적과 역할 경계

기존 분석과 문서를 브라우저에서 읽고 탐색할 계정 전용 페이지로 제공한다. 업무 skill이 내용과 근거를, 이 skill이 표현과 게시를 소유한다.

## 입력과 전제

확정된 내용, 제목, 기존 URL과 공유 범위를 재사용한다. 새 페이지는 본인 전용, 기존 페이지는 소유권과 현재 audience를 확인하고 불명확한 수정 권한이나 공유 범위만 사용자에게 묻는다.

## 요청별 분기

| 요청 | 선택 조건 | 읽을 reference |
|---|---|---|
| 새 페이지 게시 또는 기존 페이지 갱신 | 해당 제품 게시 도구가 있음 | [제품별 게시](references/provider.md) |
| 게시 수단 부재 또는 거부 | 위 경로를 사용할 수 없음 | 원본과 미게시 사유를 전달 |

처음 일치하는 행만 적용한다. 제품별 reference는 조립 시 adapter가 제공한다.

## 수행 방법과 절차

1. 완성본을 재사용하거나 필요한 내용만 HTML로 다듬는다. 여러 도표는 각각의 의미와 탐색을 유지하며 확인되지 않은 연결 관계로 합치지 않는다. 구조 시각화는 archify, 수치와 업무 차트는 diagram-design의 SKILL.md에 요청과 근거를 전달해 산출물을 받는다.
2. 제품별 reference의 연계와 의존 계약으로 게시한다. 비밀, 로그와 불필요한 로컬 정보를 점검하며 전송 검사는 security-scan의 SKILL.md에 요청한다. 필요한 파일만 올린다.
3. 반환 URL, 배포 상태와 접근 범위를 확인하고 가능한 렌더와 핵심 탐색을 검사한다.

## 제약과 주의점

본인 전용 게시와 공개 공유 및 초대는 별도 승인이다. 단순 파일 생성 요청을 게시 승인으로 확대하지 않는다. 제품의 로그인, 조직 정책이나 비밀 검사 실패를 우회하지 않고, 다른 제품이나 Orca 공개 링크로 자동 대체하지 않는다.

private 가드가 있으면 현재 고정 지침을 따른다. docs.sync로 게시를 구분하도록 갱신된 세션은 해당 검사를 쓰고, 구 지침의 DENY는 승인된 갱신 후 새 세션에서 확인하기 전까지 유지한다. 호스팅 인프라 변경은 별도 범위다.

## 결과와 완료 판단

실제 URL과 공유 범위를 짧게 전달한다. 파일 생성, 게시 성공, 계정 보호 및 로그인한 화면의 렌더 확인을 구분한다. 인증 안내나 배포 대기는 본문 확인 성공이 아니며 미확인을 남긴다.
