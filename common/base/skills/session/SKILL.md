# session

## 목적과 역할 경계

작업의 연속성과 실행 중인 세션의 운영을 담당한다. 작업 진행 방식은 작업 흐름과 업무 도구, 기록과 지식의 연결 및 인계 자료 준비는 document가 소유한다. 플러그인 설치와 캐시 갱신은 제품의 설치 관리 수단으로 별도 수행한다.

## 입력과 전제

작업 기록의 식별자와 실제 호스트 세션 ID를 구분한다. 같은 작업을 clear 이후 새 세션에서 잇는 것은 인계, 별도 수신자에게 범위를 맡기는 것은 위임이다. 저장 구조는 해당 기록 도구를 따르고 실제 호스트 기능/권한은 현재 환경에서 확인한다.

## 요청별 분기

| 요청 | 선택 조건 | 읽을 reference |
|---|---|---|
| 같은 작업의 세션 전환, 인계 준비 또는 재개 | 진단을 요청한 재개 실패가 아님 | [continuity.md](references/continuity.md) |
| 다른 세션, 에이전트, 사람에게 작업 위임 | 해당 요청이 포함됨 | [delegation.md](references/delegation.md) |
| 설치된 새 skill과 hook을 실행 중 세션에 반영 | 해당 요청이 포함됨 | [runtime-refresh.md](references/runtime-refresh.md) |
| 세션 무응답, 연결 이상, 재개 실패 | 해당 요청이 포함됨 | [recovery.md](references/recovery.md) |
| Orca의 기존 공간에서 에이전트 시작, 조회 또는 입력 전달 | 위 인계/위임/진단 절차 없이 해당 조작만 요청됨 | [orca-cli wrapper](../orca-cli/SKILL.md), 확인한 호스트/기존 공간/수신자와 승인 범위를 전달 |

같은 요청의 행은 위에서부터 평가해 처음 일치한 하나만 읽는다. 별도 추가 요청이 함께 있으면 각 요청에서 선택한다. 선택하지 않은 reference는 읽지 않는다. 다른 skill 연결은 해당 reference의 `연계와 의존`에서 요청, 입력과 필요한 결과를 확인한다. 대상은 현재 환경에서 확인한 식별자로 찾고 그 SKILL.md의 요청별 분기와 공통 제약을 적용한다. 대상 내부 reference 경로를 추측하거나 직접 고정하지 않는다. 이미 확인한 규칙과 결과는 변경되거나 불명확할 때 다시 조회한다.

## 제약과 주의점

- 세션 전환, 종료, 재시작, 다른 환경 전달은 승인된 범위에서만 실행한다. 인계 요청을 다른 세션 종료 승인으로 확대하지 않는다.
- 제품별 조작은 현재 호스트가 제공하는 수단을 확인해 사용한다. 확인되지 않은 명령이나 API를 추측하지 않는다.
- 준비 완료, 전달 완료, 실제 재개 성공을 구분한다. 기록을 읽었다는 이유만으로 원래 작업을 완료 처리하지 않는다.
- 세션 목록, 검색, 이름 변경, 삭제 기능의 전체 구현은 이 초안에 포함하지 않는다.
