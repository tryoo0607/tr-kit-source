# 실행 중 세션의 runtime 갱신

열린 Codex와 Claude의 플러그인 반영 상태, 보류 목록과 설치 후 갱신 요청에 사용한다. 기본은 조회다. 설치 버전, 갱신 입력 접수와 실제 소비 증거를 구분한다.

## 입력과 전제

대상 호스트, 설치 결과와 명시 선택한 terminal handle 및 승인 범위를 받는다. 기존 설치 근거를 재사용하고 새 설치가 필요한 경우에만 아래 native 설치 연결을 적용한다. 갱신 승인은 설치, 배포, 전체 daemon 재시작이나 다른 세션 종료 승인이 아니다.

`ORCA_PANE_KEY`와 조회 결과의 `tabId:leafId`로 실행 주체를 식별한다. cwd나 대화 ID만으로 self를 추정하지 않는다. self를 유일하게 찾지 못하면 전체 적용을 보류한다. structured chat은 terminal 수단으로 갱신하지 않는다.

## 수행 방법과 절차

1. 현재 skill 디렉터리의 `scripts/runtime_refresh.py`를 Python 3으로 실행한다. 인자 없이 또는 `inspect`로 조회한다. Orca의 기존 실행 파일 선택 계약으로 CLI를 한 번 정해 list, ps, show와 screen read를 사용하며 사용자 창에 입력하지 않는다. 출력은 host 범위, handle, incarnation, cwd, 상태, 보류 사유와 native 설치 버전 metadata를 포함한다. 로컬 `codex plugin list --json` 또는 `claude plugin list --json`을 해당 cwd에서 조회하며 native CLI 버전, 플러그인 ID, 설치 버전, 활성 상태와 scope를 정리한다. Claude project/local은 검증한 absolute projectPath의 SHA256인 projectContext를 설치 identity와 버전 key에 포함한다. 다른 cwd의 설치도 모두 snapshot에 유지하며 같은 context 중복·미확인 경로는 보류한다. enabled ID/의존성 중복은 자동 precedence를 추정하지 않고 계속 거부한다. CLI의 source, 설치·project 경로 원문, 진단 원문과 비밀 필드는 출력하지 않는다. 이 inventory는 호출자의 config 환경 기준이며 대상 runtime의 실제 소비 증거가 아니다. 원격 설치 inventory는 해당 호스트 수신자에게 위임한다. 누락 호스트와 truncated 결과를 전체 기기 조회로 해석하지 않는다.
   native 조회의 stdout은2,000,000바이트, stderr는64,000바이트로 제한하며 두 pipe를 동시에 읽는다. Codex의 정확한 `plugin list --json`만180초를 허용하고 Claude inventory·양 제품의 다른 native 명령·Orca 호출은 기존15초를 유지한다. 약60초 cold 조회와 설치26개의 기존 관측을 근거로 선택한 상한이며 모든 호스트의 최대값을 실측한 수치는 아니다. 상한 초과·timeout·비정상 종료·잘못된 UTF-8, exit0의 비어 있지 않은 stderr는 고정 사유의 미확인이다. 진단 원문을 출력하거나 경고를 무시한 부분 목록·잘라낸 JSON·local-only fallback을 허용하지 않는다. 매 native 호출은 별도 소유 process group에서 실행하며 모든 완료·실패 경로에서 그 group만 정리하고 leader 회수는 추가 최대2초다. 회수가 확인되지 않으면 보류하며 사용자의 기존 process는 정리 대상이 아니다.
   inventory 대기 중5초마다 고정 phase/provider·경과초·제한초만 stderr JSON으로 보내며 최종 stdout은 JSON 하나를 유지한다. cwd·UUID·플러그인·명령·진단 원문은 진행 출력에 없다. 진행은 best effort다. Linux FIFO/TTY는 `/proc/self/fd`로 별도 open-file description을 O_NONBLOCK으로 열어 작은 write를 한 번만 시도하며 caller descriptor의 flags를 바꾸지 않는다. full/closed/unwritable sink는 생략하고 대기·재시도·queue·thread·background process를 만들지 않는다. bounded write가 보장되지 않는 disk·임의 Python writer는 생략한다.
2. 설치 inventory가 확인된 명시 선택 idle만 `plan --target <handle> [--target <handle>] --plan <새 JSON 경로>`로 저장한다. self, busy, 초안, 승인 대기, 자식 작업과 상태 또는 identity 불명은 제외한다. 빈 idle prompt와 agent, main 상태 및 program 완료 근거를 확인해야 한다. Codex는 program 객체의 done/idle을 계속 요구한다. Claude의 programStatus가 null 또는 부재이면 aggregate와 main이 모두 done이고 실제 `tui-idle` receipt가 만족하며 identity와 자식 상태 근거가 함께 확인될 때만 허용한다. null 자체를 idle로 간주하지 않는다. UI의 `draft`와 native prompt의 입력 문자열은 초안으로 보류한다. Codex0.167.1·0.167.2·0.171.0·0.172.0의 header와 정확한 기본 placeholder 및0.171.0에서 관측한 header 없는 동일 placeholder·빈 draft 형식은 조회에 허용한다. 보이는 unknown version header와 다른 형식은 보류한다. fresh Claude331의 유한한 두 관측 placeholder·draft 키 생략을 포함한 기존 empty draft guard 조건과 지원된 native/launch 버전의 분리는 [session-restart의 단일 복구 계약](session-restart.md#접수된-claude-준비의-명시-복구)을 따른다. 자동 resume 모드는 fresh status의 Codex header에서 얻은 nativeVersion이 지원 범위일 때만 부여하며 설치된 CLI 버전도 대조한다. native Codex와 Claude의 빈 roster 생략은 aggregate와 main이 done이고 program이 done 또는 idle일 때 허용하며, Claude의 null/부재는 앞의 엄격한 완료 조건을 함께 충족해야 한다. 명시된 자식 목록이나 미확인 관측은 보류한다.
3. 승인된 대상에만 계획 생성 뒤5분 이내에 `apply --plan <JSON 경로>`를 시작한다. 이 규칙은 apply 시작 기한이며 긴 조회 뒤 후속 입력에 새 만료를 추가하지 않는다. 원격 조회는 `--environment <selector>`를 사용하되 원격 apply는 아래 session 연결로 해당 호스트 수신자에게 위임한다. 수신자는 그 호스트의 기존 가드를 적용하고 자신을 제외해 새로 조회 및 계획한다. 송신자의 self 정보를 원격 self로 대체하지 않는다.
4. 입력마다 계획에 저장한 설치 inventory와 현재 버전 및 활성 상태를 대조하고 runtime, handle, PTY, incarnation, pane, cwd, host와 현재 상태를 재조회한다. 설치 정보가 바뀌거나 조회할 수 없으면 입력 없이 중단한다. 실행 후에도 설치 inventory를 대조해 drift를 별도로 판정한다. Codex에서는 `/status`의 새 출력에서 exact UUID, cwd·권한과 제한된 resumeMode를 얻는다. 응답을 확인하는 동안은 긴 설치 조회 없이 passive runtime/identity/상태 guard를 유지한다. status 신원은 현재 frame의 최신 명령·startup 경계 안에 모두 있어야 한다. 기본은 새 stream과 현재 신원의 일치이며, Codex의 독립적인 새 화면 응답 증명은 아래 [status 응답 계약](#codex-status-응답-대기와-수신자-home)을 따른다. 과거 status 뒤 새 startup/resume·다른 명령이 보이거나 현재 신원이 없으면 미확인이다. 원래 응답 frame의 cursor/화면 hash를 유지하고 재관측에서 같음을 확인하며, 과거 delta를 나중 frame의 증거에 붙이지 않는다. 공통 resume 구성기가 기존 Full Access와 기록된 mode를 확인한 경우에만 고정 보존 옵션을 구성하고 `/exit`로 정상 종료한다. default/Custom을 현재 설정 기본값과 같다고 추정하지 않으며, 권한 보존 계약이 미확인이면 종료 전에 보류한다. /exit 직전 stream cursor 이후 새 정상 종료 안내에 같은 UUID가 있고 현재 마지막 frame이 빈 shell prompt이며 agentWait와 집계 live child가 없을 때만 shell 복귀를 인정한다. terminal show의 agentIdentity는 종료 후에도 남을 수 있으므로 그 hint 하나를 foreground 생존 근거로 삼지 않는다. 종료 안내 원문은 출력하거나 저장하지 않고 확인된 UUID와 shell cwd만 journal에 남긴다. 이 증거가 갖춰졌을 때만 같은 터미널에서 이미 Full Access인 세션에만 `codex resume <exact UUID> --dangerously-bypass-approvals-and-sandbox`를 실행한다. 일반 세션의 권한 증가나 임의 저장 flags 재생을 허용하지 않는다. `--last`, 새 대화 대체나 새 권한 우회 flag를 쓰지 않는다. 다시 `/status`를 조회해 UUID, cwd와 권한을 대조한다. shell, 메뉴, 신뢰 확인이나 권한이 불명확하면 추가 입력 없이 멈춘다.
5. Claude는 설치본의 `/reload-plugins` 지원, 누락 의존성 설치가 필요 없다는 근거와 완료 응답을 확인했을 때만 native reload를 사용한다. `--force`를 쓰지 않는다. script는 native CLI2.1.260 이상의2.1 계열, 활성 플러그인의 manifest와 의존성 설치 상태, 진단 부재를 확인한다. manifest를 읽지 못해도 조회된 설치 버전은 보존하고 reload는 보류한다. 의존성은 설치되고 활성인 유일한 ID 및 필요한 exact 버전만 허용하며 미지원 버전 범위는 보류한다. 대상 `/status`의 CLI 버전과 identity, 새 `/help`의 명령 지원, 새 `/plugin list --enabled`의 ID 집합, scope, enabled와 구체 버전을 확인한 뒤에만 `/reload-plugins`를 보낸다. 기존 `enabled` 형식은 유지하고, 정확한 괄호형 `• ID (vVERSION, scope) ✔ on`은 같은 요청의 fresh `/status`가 실제 native2.1.331을 입증했을 때만 허용한다. 설치 CLI331만으로 새 문법을 허용하지 않는다. `off`·unknown·중복·누락·다른 scope의 거부는 유지한다. 같은 ID의 목록 버전과 설치 버전이 다른 상태는 갱신 전의 정상 입력으로 허용하고 `runtimeListedVersionsBefore`, `runtimeListingMatchesInstalledBefore`로 구분한다. 목록은 소비 버전의 증명이 아니다. Claude2.1.322에서 관측한 완전한 목록 다음, 응답 구분선 직전의 오른쪽 정렬 `◐ medium · /effort` 또는 `Scroll wheel is sending arrow keys · use PgUp/PgDn to scroll` 줄 하나만 UI 표시로 구분한다. 다른 footer 문구나 미확인 effort 값은 허용하지 않는다. 추가, 누락, 중복 ID, scope 차이, 비활성, 버전 범위, unknown이나 미지원 문법은 보류하며, 설치 inventory와 exact dependency 검증은 완화하지 않는다. 명령 제출 직후 아직 새 화면이 없고 fresh stream도 미완성이면 입력 없이 같은 요청의 새 modal, 새 echo 또는 완전한 stream을 최대12회, 3초 deadline 내 재조회한다. 과거 화면과 미완성 stream을 합쳐 새 응답으로 취급하지 않는다. 새 명령 경계가 입증된 뒤 목록이나 reload 완료 요약이 미완성, 불명확하면 원래 frame의 cursor, 명령 echo 수, prefix를 보존해 같은 응답을 최대12회, 3초 deadline을 확인하며 읽는다(개별 CLI timeout은 그대로다). 이 동안도 passive idle/identity/상태 guard를 유지하고 최신 명령 경계, cursor가 바뀌거나 같은 명령 echo가 추가되면 멈춘다. 화면 prefix는 앞쪽 이력이 잘려 나간 suffix만 허용하며 stream delta는 과거 화면으로 보완하지 않는다. 명령을 재전송하지 않으며 끝내 유효한 목록이 없으면 보류한다. 새 출력의 완료 요약과 플러그인 수를 확인하고 identity 및 설치 상태를 다시 대조한다. Claude2.1.322에서 관측한 status/help 모달 형식과319의 기존 Esc-to-cancel 경로를 유지하며,329/330/331의 정확한 Settings/Status header·version·close footer만 추가로 인정한다. 새 status 모달과 직전 idle 화면의 명시 권한 근거를 확인한다. 보통 status/prepare는 원 모달 증거와 같은지 fresh 설치·상태 full guard 뒤 대조해 Esc로 닫으며, 닫힌 frame을 이전 UUID의 증거로 쓰지 않는다. 부재 복원과 중단 준비 검증은 [session-restart](session-restart.md)의 각 모달 유지·정리 계약을 사용한다. help는 알려진 모달 안에서 Right와 최대 16회의 Down 10개 단위 탐색으로 Commands 목록을 확인한 뒤 닫는다. 각 입력 전후 identity, 대기, 모달 경계를 재확인하고 미확인 화면은 중단한다. 모달 raw key는 `--enter` 없이 보내며 실제 receipt의 handle 일치, accepted=true와 입력 UTF-8 길이에 정확히 맞는 bytesWritten을 검증한다. raw receipt에는 mutation이나 prompt가 없을 수 있고 request ID를 만들어 넣지 않는다. 제공된 mutation의 requestId와 prompt의 incarnation은 검증하고 실제 접수 metadata만 journal에 기록한다. 반면 `--enter` 명령 제출은 기존 mutation.requestId를 계속 요구한다. 어느 영수증이든 불명확하면 재전송하지 않는다. stream에 UI가 없으면 새 모달 또는 새 명령 echo 뒤의 비어 있지 않은 응답 경계를 확인한다. echo 수 증가로 새 경계가 독립적으로 입증된 경우 이전과 같은 본문도 허용하지만 과거 화면이나 echo만으로 완료를 판정하지 않는다. 이 구현과 회귀 검사는 변경된 script의 실제 native 갱신 완료를 의미하지 않는다. force 요구, 오류, 의존성 추가 설치 응답과 모호한 출력은 부분 변경으로 중단한다. 확인된 수단이 없는 버전을 지원하는 것으로 보고하지 않는다.
6. 한 대상의 identity 대조와 증거 정리 후에만 다음 대상으로 진행한다. 설치된 버전과 실제 소비 버전은 별도 근거로 대조한다. script는 native resume 확인만으로 플러그인 소비 완료를 판정하지 않으며 `consumption: unverified`를 반환한다.

### Codex status 응답 대기와 수신자 home

Codex `/status`는 접수·idle 뒤 화면이 늦게 도착하거나 새 metadata가 일부만 보이면 원 cursor를 유지해 최대15초/60회, 관측 사이0.05초 간격으로 읽는다. 이 시간에는 passive guard와 coherent stream 읽기 및 최종 proof 대조도 포함한다. 개별 Orca 호출의 기존 timeout은 그대로이며 deadline 뒤 응답을 성공으로 받지 않는다. 이 동안 새 설치 조회·명령 재전송은 없고 매 관측에서 passive self/runtime/provider/terminal/idle/draft/child guard를 확인한다. 바뀐 명령 경계나 stream/current frame 신원·proof 불일치는 즉시 중단한다. 끝내 완전한 새 응답이 없으면 보류한다. Claude의 별도3초 응답·권한 확인 제한은 변경하지 않는다.

승인 계획에 기록된 Orca1.4.242 관측에서는 완료된 newline 레코드 기준 cursor와 stream delta가 TUI 카드 추가 뒤에도 그대로였다. Codex `/status`에 한해서 다음 독립 화면 증명을 지원한다. 입력 직전 idle prompt·footer를 제외한 이력이 새 marker 앞에 그대로 이어지거나, 이전 완전한 카드의 Session 줄을 포함한 연속 suffix가 유일한 위치로 남아 이전 응답 끝에 이어져야 한다. 후자는 기존 첫 일반 사용자 요청문이 함께 보존되는 형식도 허용한다. 원래 startup 표시 뒤에 있던 요청문이 잘린 화면 맨 위로 고정돼도, 그 줄이 이전 이력의 첫 일반 요청문과 정확히 같고 이전 이력에 한 번만 있으며 나머지 연속 suffix도 위 Session 조건과 유일성을 충족해야 한다. 나중 요청문·slash 명령 echo·중복 요청문을 대신 고르지 않는다. 빈 줄·idle prompt·status 표시만 있는 이력은 append 근거로 사용하지 않는다. 일반 작업 이력이 완전히 보존된 첫 status는 이전 status 카드 없이도 지원한다. 공통 prefix라는 이유로 새 일반 명령을 허용하지 않는다. 이력 순서·줄 내용·끝 경계가 달라지거나 중복 overlap·reflow·history 노출로 구별할 수 없으면 보류한다.

증명한 이력 바로 다음에는 정확한 standalone `/status` 또는 `› /status`와, 그 바로 다음 줄의 지원 버전 `>_ OpenAI Codex (v...)` header가 필요하다. 그 카드부터 다음 빈 prompt 또는 정확한 기본 placeholder까지의 UUID·cwd·권한이 모두 한 번씩 있어야 한다. 이후의 명령·startup·resume, 중복·빈 신원은 성공으로 받지 않는다. 이 경로에서도 원 cursor로 stream을 읽고 schema가 정상이어야 하며, stream에 있는 신원 필드는 화면과 모두 일치해야 한다. 불완전 stream의 누락 필드는 화면이 독립적으로 완전할 때만 허용한다. malformed stream·잘못된 신원·충돌·새 명령을 screen fallback으로 우회하지 않는다. 줄이 갈라지거나 Unicode 공백 등으로 기존 파서와 단일 줄 필드 문법이 어긋나는 신원은 누락 필드로 취급해 화면 값으로 채우지 않는다. standalone Codex 명령 경계는 기존 stream 경로에도 적용하며, 최신 `/status`가 미완성이면 이전 필드를 사용하지 않는다. 응답 전후의 화면 hash·시간·cursor 진행이나 marker 개수만으로 freshness를 인정하지 않는다.

정확한 새 카드만 파싱한 뒤 원 응답 frame의 기존 `output_proof` 두 필드(`cursor`, `screenSha256`)를 passive 재관측과 exact 비교한다. proof schema와 기존 stream/Claude 경로·설치/상태 가드·단일 입력은 유지한다. 같은 cropped 카드가 반복돼 전후 화면이 같거나 footer만 바뀐 경우, 이전 응답 suffix가 두 위치에 있어 새 append를 구별할 수 없는 경우는 계속 미확인이다. 현재 가시 화면이 잘려 충분한 이력을 얻지 못하면 추가 입력·UI 이동으로 보완하지 않는다. 줄바꿈·화면 크기·미지원 header의 모든 표현을 포괄하지 않는다. 합성 순서 fixture의 통과는 실제 native 응답 성공 근거가 아니다.

native cwd의 정확한 `~` 또는 `~/safe/path`만 수신자 프로세스의 absolute·정규화된 `Path.home()`에 연결한다. inventory의 경로로 home이나 UUID를 추측하지 않는다. `~user`, 환경변수·shell 구문, 상대경로, 빈 구간·`.`·`..`·앞뒤 공백 등 모호한 home 하위 구간은 거부한다. 확장 후에도 원 workspace 경로와 정확히 같아야 하며 mismatch는 보류다. 절대경로의 기존 비교와 stale-output 검사는 유지한다. 이 계약은 [세션 재시작 배치](session-restart.md)의 준비와 검증에서도 같은 함수를 재사용한다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| 제품 native 설치 CLI: 설치 상태 확인과 필요한 설치 작업 | 제품, 플러그인과 버전, 기존 설치 근거, 승인 범위 | 설치 버전, 확인 결과와 runtime 반영 미결 | 기존 근거 재사용. 실제 지원 명령을 확인할 수 없으면 설치와 후속 반영 보류 |
| Orca CLI: 읽기 전용 조회와 선택 대상의 순차 입력 | host 범위, runtime handle, 실행 주체 pane, 승인된 대상 | runtime 및 incarnation, agent와 program 상태, native 완료 증거와 접수 request ID | 필수. JSON 실패, 누락 상태, timeout과 불명확한 접수는 중단. 임의 RPC나 자체 세션 관리기로 대체하지 않음 |
| session: 원격 호스트의 기존 수신자에게 갱신 위임 | 호스트, 수신자, 설치 근거, 승인 범위와 선택 대상 | 해당 호스트의 가드 적용 결과, 보류 사유와 복구 좌표 | 원격 적용에 필수. [session 본문](../SKILL.md)의 위임 분기로 진입. 수신자 또는 권한 불명은 실행 보류 |

이 배포본에 별도 kit skill이 있다고 가정하지 않는다. script는 반복 조회, 제외, 순차 조작과 metadata 정리를 맡고 native 설치나 제품 동작을 대체하지 않는다.

## 제약과 주의점

다른 세션 원문 검색, 강제 종료, process 이름 전체 종료, 전체 daemon 재시작, 캐시 변경과 임의 배포를 하지 않는다. screen은 상태와 native metadata 판별에만 사용하며 prompt, preview, 대화 문장과 비밀 필드를 출력하거나 저장하지 않는다. 기존 사용자 창을 회귀 시험 대상으로 입력하거나 종료하지 않는다. 실제 시험은 새로 만든 소유 canary만 사용한다.

Orca에는 원자적 idle 확인과 종료 계약이 없다. 직전 재확인은 경합을 줄이지만 완전한 무경합을 보장하지 않는다. 두 제품의 aggregate는 추적 중인 자식 상태를 반영하지만 미추적 백그라운드 작업의 부재까지 입증하지 않는다. live Orca1.4.242/Codex0.167.1의 소유 A/B 시험에서 native text-only 입력도 `draft`로 분리되는 것을 관측했다. 기본 placeholder와 같은 문자열을 입력한 경우도 해당 필드로 차단한다. Codex0.167.2와0.171.0의 같은 기본 placeholder와 draft=null, 같은 문장을 직접 입력했을 때의 별도 draft 값도 소유 canary에서 관측했다. 후속0.171.0에서는 header 없는 동일 placeholder/빈 draft와 같은 문구 직접 입력 시 draft 문자열, 직접 지운 뒤 원상 복귀도 관측했다. 이는 조회 조건이며 fresh status의 known nativeVersion과 현재 CLI 버전 검사를 대신하지 않는다. 보이는 unknown version header는 계속 거부하고 직접 키보드 입력과 화면 폭의 모든 조합까지 입증한 것은 아니다. 조회 후 상태나 대상이 바뀌면 중단한다.

## 결과와 완료 판단

호스트 조회 범위, self와 제외 사유, 명시 선택, 대상별 before/after UUID, cwd와 권한, 설치 버전 근거, 갱신 접수 및 실제 소비 근거, 남은 대상과 보류 사유를 전달한다. 설치 버전이나 PID, PTY 변경, native resume 성공만 확인되면 적용 미확인이다. 설치 버전은 `installedVersion`과 `installationBefore/After`, 실제 소비 버전은 `consumedVersion`으로 분리한다. 현재 API는 제품별 플러그인의 실제 소비 버전을 입증하지 않으므로 `consumedVersion: null`, `consumption: unverified`를 유지한다. native reload의 완료 요약도 버전별 소비 증명으로 확장하지 않는다. 완료는 승인 대상에서 identity 보존과 새 skill 및 hook 소비를 각각 관찰했을 때만 판정한다.

## 실패와 복구

첫 실패 뒤 나머지는 중단하고 `remaining`, 실패 대상 identity와 journal 경로를 반환한다. 미해결 operation이 남아 있으면 다른 operation도 보류한다. journal은 기본 `~/.local/state/tr-kit/runtime-refresh`에 metadata와 실제 접수 request ID 또는 raw key receipt의 handle, accepted, bytesWritten을 저장한다. `--journal <경로>`로 호스트 로컬 위치를 지정할 수 있다. 원문이나 pairing secret을 넣지 않는다.

입력 전에 operation을 기록하고 호스트별 lock을 잡는다. 같은 operation의 재실행과 동시 apply는 거부한다. journal은 부모부터 symlink를 따라가지 않고 directory descriptor에 고정하며 record를 exclusive 생성한다. record 교체나 hardlink를 감지하면 쓰기와 후속 입력을 중단한다. symlink 경로, 그룹이나 다른 사용자에게 쓰기가 열린 journal 디렉터리와 해당 가드 미지원 호스트는 보류한다. timeout이나 crash 뒤 새 operation으로 재전송하지 않는다. journal의 마지막 단계, runtime 및 incarnation, native UUID와 현재 화면을 먼저 대조한다. 확인된 Orca request ID가 있으면 같은 request의 접수 상태만 조회하고 새 입력으로 대체하지 않는다. script는 자동 재전송하지 않는다.

정상 종료 후 resume 실패, identity나 권한 불일치, 메뉴와 승인 대기는 부분 변경이다. UUID와 cwd 및 권한 근거를 보존해 해당 수신자의 승인된 native 복구로 이어간다. 오래된 lock이나 journal을 지워 맹목 재실행하지 않으며 상태를 먼저 확인한다. 실패를 추가 설치나 대상 밖 세션 종료로 덮지 않는다.

설치 JSON과 reload 요약의 제품 계약은 [Claude 공식 명령 문서](https://code.claude.com/docs/en/plugins/cli-reference), 의존성 형식은 [manifest reference](https://code.claude.com/docs/en/plugins-reference#dependencies)를 근거로 한다. 현 호스트의 실제 CLI 지원과 출력이 다르면 실행을 보류한다.
