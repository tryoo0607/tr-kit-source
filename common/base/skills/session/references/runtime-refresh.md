# 실행 중 세션의 runtime 갱신

설치가 끝난 skill과 hook을 실행 중 세션에 반영할 때 사용한다. 설치나 캐시 변경이 필요하면 아래 제품 설치 수단을 먼저 확인한다.

## 수행 방법과 절차

1. 확인된 설치 결과가 있으면 재사용하고 설치 작업이 필요한 경우에만 아래 제품 설치 수단을 적용한다. 설치를 끝낸 버전과 현재 호스트의 reload 또는 재시작 수단을 확인한다. 설치와 runtime 반영을 구분한다.
2. 현재 호스트에서 확인한 세션 관계 기준으로 대상 ID와 상태를 확인한다. 현재 작업 세션, busy, 상태 불명 세션은 자동 대상에서 제외한다.
3. idle 세션 하나의 적용 방법과 영향, identity 보존 및 실패 시 복구 수단을 제시한다. 기존 승인 범위가 없으면 실행 전에 확인한다.
4. 해당 세션에만 적용하고 대화 identity 보존과 새 skill 및 hook 반영을 각각 확인한다. PID 변경만으로 pickup 성공을 판단하지 않는다.
5. 성공하면 승인된 나머지 대상을 다시 확인해 순차 적용한다. 실패하면 자동 강제 종료나 전체 세션 재시작으로 확대하지 않는다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| 제품의 native 설치 CLI: 설치 상태 확인과 필요한 설치 작업 | 제품, 대상 플러그인과 버전, 설치 근거, 승인 범위 | 설치된 버전과 확인 결과, runtime 반영 전 미결 | 확인된 설치 결과가 있으면 재사용. 설치 수단을 확인할 수 없으면 해당 설치와 후속 반영을 보류 |

이 배포본에 별도 kit skill이 있다고 가정하지 않는다. 제품 CLI의 실제 지원 명령과 설치 경로를 확인하고, 확인된 설치 결과를 재사용한다.

## 제약과 주의점

process 이름 전체를 대상으로 종료하거나 자동 SIGKILL하지 않는다. 세션 저장소의 비밀 필드를 출력하지 않는다.

## 결과와 완료 판단

완료는 승인된 대상에서 identity와 새 runtime 반영이 관찰된 상태다. 제품별 반영 수단을 확인할 수 없으면 계획과 미검증 범위를 남긴다.

## 실패와 복구

호스트 반영 수단이나 대상 정체성을 확인할 수 없으면 해당 적용을 보류한다. canary 실패 시 승인된 복구 방법만 사용하고 전체 batch를 중단한다. 설치 변경으로 원인을 덮거나 대상 밖 세션을 종료하지 않는다.
