# 세션 진단과 복구

세션 무응답, 연결 이상이나 재개 실패의 원인과 복구 방법을 확인할 때 사용한다.

## 수행 방법과 절차

1. 대상 세션과 증상, 마지막 정상 시점을 확인한다. 무응답을 context 포화나 세션 삭제로 단정하지 않는다.
2. 현재 호스트의 연결, 대기 중인 승인이나 입력, 실행 상태와 최근 오류를 필요한 범위에서 조회한다. 로그 분석이 필요하면 아래 logs 연결을 적용하고 전체 transcript나 저장소를 출력하지 않는다.
3. 확인한 원인과 후보를 구분하고 현재 작업 및 미기록 변경, 재개 좌표를 확인한다. 기록 정본의 포인터나 상태 대조가 필요하면 아래 document 연결을 적용한다. 접근 불가 정보는 추측하지 않는다.
4. 가장 작은 복구 조치와 영향, 성공 확인 방법을 제시한다. 상태 변경은 승인 범위 안에서 수행하고 종료, 재시작, clear를 진단 요청만으로 실행하지 않는다.
5. 연결뿐 아니라 대상 대화와 작업 재개 상태를 확인한다. 실패하면 새 증거를 남기고 더 강한 조치로 자동 확대하지 않는다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| logs: 관련 로그 조회와 오류 분석 | 대상 세션, 증상, 마지막 정상 시점, 확인된 로그 위치와 조회 범위 | 근거가 있는 오류와 원인 후보, 미확인 항목 | 선택. 사용할 수 없으면 확인된 호스트 조회 수단으로 해당 시간과 오류 범위만 직접 확인. 접근 수단도 없으면 로그 분석을 미결로 남김 |
| document: 작업 목록 또는 재개 기록 대조 | 확인된 기록 포인터 또는 부재, 현재 증상과 조회 범위 | 현재 기록 위치, 요구/상태 불일치와 미반영 변경, 접근 문제 | 기록 정본 대조가 필요한 경우에만 사용. 부재 시 기록 대조를 미결로 남기며 호스트 진단은 가능한 범위에서 계속함 |

필요한 대상만 현재 환경에서 확인한 식별자의 SKILL.md로 진입한다. 로그 근거와 기록 상태가 충분하거나 단순 호스트 상태 확인이면 추가 로드하지 않는다. 기록 대조는 document, 실제 세션 연결 문제는 이 지침이 소유한다. 명시 포인터가 깨졌다는 이유로 다른 기록을 자동 선택하거나 문서를 추측해 복원하지 않는다.

## 결과와 완료 판단

진단 결과와 복구 성공을 구분한다. 성공은 대상 identity와 정상 응답 또는 기대 동작을 확인한 상태다. 수단이 없으면 확인한 사실과 다음 점검을 남기며 복구 완료로 표시하지 않는다.

## 실패와 복구

원인이 불명확하면 확인한 사실과 다음 조사만 제시한다. 원격 접근 실패와 미기록 변경을 추측으로 복원하지 않는다. 반복 실패는 더 강한 상태 변경의 자동 승인이 아니다.
