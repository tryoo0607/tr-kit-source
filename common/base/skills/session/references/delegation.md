# 다른 주체에게 작업 위임

다른 세션, 에이전트 또는 사람이 맡을 작업과 전달, 결과 검증을 준비할 때 사용한다.

## 입력과 전제

수신자, 위임 범위, 기존 작업 정본과 결과 회신 위치를 확인한다. 다른 수신자에게 맡기는 일과 동일 작업을 새 세션에서 잇는 일을 구분한다.

## 수행 방법과 절차

1. 수신자와 환경, 맡길 작업을 확인하고 원래 작업과 위임 범위를 구분한다. 수신자는 원래 대화를 읽지 못한다고 가정한다.
2. 요청, 목적, 입력과 접근 경로, 허용 범위와 금지사항, 완료 조건, 결과를 돌려줄 위치를 담는다. 현재 상태를 복사하는 대신 필요한 자료와 읽는 이유를 연결한다.
3. 수신 환경에서 필수 자료에 접근 가능한지 확인한다. 자료 반출 허용과 전달 승인을 확인하며 비밀값은 인계문에 포함하지 않는다.
4. 저장할 작업 기록은 아래 document 연결을 적용한다. 설정된 전달 경로가 없으면 현재 허용된 위치에 준비하고 자동으로 원격 저장소를 만들지 않는다.
5. 승인된 수단으로 전달한다. Orca 조작이 필요하면 아래 wrapper 계약에 기존 공간과 감독 여부를 전달한다. 추가 공간도 요청되면 project의 공간 준비 결과를 먼저 받는다. 사람이 받는 문서 준비에는 wrapper를 읽지 않는다. 결과를 돌려받는 위임은 완료 조건과 증거를 대조하고 전체 인계는 전달 완료와 작업 완료를 구분한다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| [orca-cli wrapper](../../orca-cli/SKILL.md): 기존 공간의 수신자 시작 또는 전달 | 확인한 호스트/공간 ID와 경로, 수신자와 위임 내용, 감독/회신/완료 조건과 승인 범위 | 실제 수신자, launch/전달 receipt와 미결 | Orca 조작에만 필수. 부재/미지원은 해당 실행 보류 |
| document: 기존 작업 기록 갱신 | 작업 정본 포인터 또는 기록 부재, 위임 범위와 승인, 전달 상태, 검증 결과 | 기록 위치, 반영 결과와 미결 | 기존 기록 갱신에 필수. 기록이 없으면 위임 내용을 응답으로 준비하며 신규 작업 생성은 해당 작업 도구와 요청 범위를 따름. document 부재 시 저장 보류 |

document의 내부 인계 분기는 같은 기록에 접근하는 다음 LLM 세션에만 적용한다. 다른 사람이나 접근 환경에 대한 위임문 형식을 그 분기가 지원한다고 가정하지 않으며, 위임 내용과 전달 조건은 이 reference가 소유한다.

현재 환경에서 확인한 document 식별자의 SKILL.md로 진입해 해당 요청 분기를 적용한다. 내부 reference를 직접 고정하지 않는다.

## 결과와 완료 판단

준비, 전달, 수신 및 결과 검증을 각각 보고한다. 파일 작성만으로 전달 완료나 위임 작업 완료를 표시하지 않는다. 상대가 필요한 자료를 읽을 수 없으면 누락을 알리고 전달 가능한 범위만 준비한다.

## 실패와 복구

수신 자료 접근 불가, 회신 경로 부재나 승인 범위 충돌은 전달 전 미결로 알린다. 전달 실패를 원격 저장소 생성이나 공유 범위 확대만으로 해결하지 않는다.
