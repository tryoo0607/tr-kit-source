# ext-agentops-plan

## 목적과 역할 경계

- 합의된 요구를 관찰 가능한 결과와 완료 확인 방법이 있는 구현 계획으로 정리할 때 공식 AgentOps `plan`에 연결한다.
- 계획은 현재 요청의 산출물이다. 구현, 설치, 권한 변경과 별도 계획 파일 작성은 사용자가 승인한 범위를 따른다.

## 입력과 전제

- 목적, 합의한 시나리오와 제약, 조사에서 확인한 사실, 아직 남은 선택, 실제 프로젝트 위치. Ask me를 거쳤다면 합의 요약을 재사용한다.
- 현재 제품과 킷 경로를 확인하고, 이미 확인한 외부 연결 선언과 설치 근거를 재사용한다.

## 수행 방법과 절차

1. 연계와 의존의 공통 외부 연결을 따라 검수된 공식 `plan` 진입점으로 들어간다. 공식 스킬이 선택한 리소스는 실제 설치본 기준으로 해석하고 필요한 범위만 읽는다.
2. 합의와 변경 범위를 입력으로 전달한다. 계획을 막는 여러 시나리오가 다시 열리면 킷의 Ask me 흐름으로 합의를 보강한 뒤 이어간다.
3. 공식 계획과 사용자가 합의한 범위를 대조한다. 기존 요청이나 대화에 결과를 돌려주고, 파일에 반영할 권한이 있으면 지정한 위치를 사용한다.

## 연계와 의존

| 대상 | 전달 입력·필요 결과 | 필수 여부·부재 처리 |
| --- | --- | --- |
| [공통 외부 연결](../../references/external-connection.md)의 `agentops-plan` · 종류 `skill` | 위 입력을 [AgentOps의 공식 plan](https://github.com/boshu2/agentops/blob/8edfa1943dbfb28a0095069259cc72cee99d25ad/skills/plan/SKILL.md)에 전달한다. 관찰할 결과, 구현 범위, 영향을 받는 호출부와 완료를 확인할 방법을 얻는다. | Codex와 Claude 각각 검수된 공식 설치본이 필요하다. 진입점, 제품 지원 또는 선택된 절차의 필수 리소스를 확인할 수 없으면 해당 수행을 보류한다. 기본 계획과 조건부 외부 도구 사용의 의존성을 구분한다. |

## 결과와 완료 판단

- 계획으로 구현자가 무엇을 바꿀지, 검증자가 어떤 결과를 확인할지 알 수 있어야 한다. 미결과 보류 이유를 함께 전달한다.
- 설치본 검수, 공식 스킬 적용, 실제 구현과 검증을 각각 확인한다.
