# homelab-config

## 목적과 역할 경계

설정 변경을 계획하고 요청된 범위의 저장과 반영을 연결한다. 비교는 homelab-audit, 운영 사실과 미확인 후속 기록은 homelab-record가 맡는다. 단독 호출할 수 있으며 homelab 진입점을 요구하지 않는다. 새 배포 엔진이나 작업 상태 저장소를 만들지 않는다.

## 입력과 전제

대상 ID, 변경 이유와 원하는 값, 요청 범위, repo와 기존 작업 포인터를 확인한다. 연결이 없을 때만 [저장소 연결](../homelab/references/repository.md)을 읽는다. 이미 확인된 연결과 미확인 후속, 관측 결과는 재사용한다.

| 요청 범위 | 수행 경계 |
|---|---|
| 계획 | 변경안과 영향, 실행 및 검증 경로를 제시한다. 설정과 서버는 변경하지 않는다. |
| source 저장 | 승인된 설정 원본만 수정한다. 실제 적용은 별도 상태로 남긴다. |
| 실제 반영 | 승인된 대상과 변경만 확인된 기존 실행기로 반영하고 검증한다. source 저장이나 확정만으로 이 범위를 추정하지 않는다. |
| 이미 수동 반영한 변경 정리 | 실제 관측과 사용자의 의도를 대조하고 요청된 source와 기록을 정리한다. 서버를 다시 적용하지 않는다. |

범위가 불명확하면 행동에 필요한 부분만 확인한다. 기존 승인은 대상과 변경 범위가 같은 경우 재사용한다. 커밋, push와 동기화는 요청된 범위에 포함될 때만 수행한다.

## 수행 방법과 절차

1. 아래 record 연결로 기존 관련 작업과 미확인 후속을 확인한다. 받은 결과가 있으면 다시 읽지 않는다. 필요한 스킬 제공과 작업 정본 접근을 확인하며 관련 기록을 읽지 못하면 실제 적용은 보류한다. 대상이 현재 사용 중인지, 폐기 또는 보류된 구성인지와 source 및 실제 writer를 확인한다. 과거 파일의 존재를 현행 도구 선택이나 적용 승인으로 삼지 않는다.
2. README가 안내한 설정 소유 범위와 생성 경로를 읽는다. 생성 파일이면 generator나 템플릿 소유자를 확인하고, 수동 관리인지 Semaphore 등 기존 실행기가 소유하는지 구분한다. 실행 소유자가 불명확하면 해당 적용을 보류한다. 다른 실행기로 임의 대체하지 않는다.
3. 변경안에 대상, 바꿀 source와 원하는 값, 기존 실행 경로, 영향과 중단 여부, 검증 기준 및 롤백 참조를 포함한다. 실제 반영이나 사후 정리에 필요한 현 상태는 audit 연결로 확인한다. 의도와 다른 관측을 자동 채택하지 않는다. 이전 승인이 있어도 대상이나 변경 내용이 달라지면 영향과 권한 범위를 다시 판단한다.
4. source 저장이 요청됐으면 해당 호스트의 source 변경 가드를 확인하고 기존 수정과 비밀 참조를 보존해 확정된 부분만 수정한다. 저장 후 diff와 형식 검사를 수행하고 revision 또는 미커밋 범위를 남긴다. 실제 반영이 요청되지 않았으면 적용 명령을 실행하지 않고 record 연결로 저장 사실과 이번 작업의 적용 미실행을 남긴다. 기존 서버 반영 여부와 설정 변경 의도까지 확정됐는지는 별도로 구분한다.
5. 실제 반영이 요청됐으면 대상, source revision과 배포 산출물, 현재 writer, 승인 범위 및 실행 호스트의 적용 가드를 실행 직전에 대조한다. 조회나 source 변경 ALLOW를 적용 권한으로 대신하지 않는다. audit의 관측 경로와 권한, record의 기록 가능 여부 및 기존 절차가 요구하는 사전 백업과 롤백 준비를 확인하고 부족하면 적용을 보류한다. 기존 실행기나 런북의 실제 명령과 부작용을 읽고 승인된 범위만 실행한다. check 또는 dry-run이라는 이름도 무변경을 보장하지 않는다. 의도하지 않은 기존 dirty 변경을 배포에 섞지 않는다.
6. 실행 결과와 작업 ID를 audit 연결에 전달해 동일 source가 실제 반영됐는지와 실효 설정을 확인한다. source 저장, 실행 성공, 파일 일치와 서비스 검증을 구별한다. 실패하면 추가 적용을 멈추고 기존 권한과 승인에 포함된 롤백만 기존 실행기로 처리한다. 롤백도 관측과 결과 확인이 필요하며 실패나 미확인을 성공으로 닫지 않는다.
7. 이미 수동 반영한 변경이면 audit의 관측과 의도를 대조한다. 요청에서 확정되지 않은 차이만 "이 차이가 의도한 변경인지, source와 기록에 반영할지" 확인한다. 확인 전에는 관측을 정본에 덮지 않는다. 정리 승인이 있으면 source 저장과 record 연결만 진행하고 불필요한 재배포는 하지 않는다.
8. record 연결로 의도 확정, source 저장, 실제 반영 관측, 검증 결과와 기록 여부를 각각 정리한다. 미확인에는 대상과 빠진 증거, 다음 확인 조건을 기존 작업 정본에 남긴다. 관계가 바뀌면 아키텍처 후속도 함께 전달한다. 다음 관련 홈랩 작업에서 record의 재조회 절차를 적용하며 기록 여부만 불명확한 건은 재적용하지 않는다.

## 연계와 의존

| 대상 | 활용 조건과 입력 | 결과와 부재 시 동작 |
|---|---|---|
| [homelab-audit](../homelab-audit/SKILL.md) | 현재 상태, 반영 결과 또는 수동 변경 비교가 필요할 때 대상, source revision, 실제 writer, 관측 범위와 검증 기준 전달 | 일치, 불일치, 미확인과 관측 근거. 해당 비교에 필수이며 없으면 확인 결과를 만들지 않고 관련 반영 또는 사후 정리를 보류한다. 계획과 source만 저장은 해당 범위에서 계속할 수 있다. |
| [homelab-record](../homelab-record/SKILL.md) | 기존 후속 조회와 변경 결과 기록에 대상, 작업 포인터, 확정 범위, source와 실행 결과, audit 근거 및 롤백 결과 전달 | 기존 미확인과 필요한 질문, 실제 기록 위치 및 저장 결과. 조회와 기록에 필수이며 읽지 못하면 미확인이 없다고 하지 않는다. 기록이 불가하면 추가 적용을 멈추고 이미 발생한 변경과 미기록을 보고한다. |
| [session](../session/SKILL.md) | 승인된 다른 실행 주체에게 조회나 적용을 맡길 때 확인된 수신자, 대상, source revision, 승인 범위, 필요한 가드와 결과 회신 위치 전달 | 전달 receipt와 회신 근거. 해당 위임에 필수이며 없으면 전달을 보류한다. receipt만으로 적용 성공을 판정하지 않는다. |

대상의 SKILL.md에서 해당 절차와 공통 제약을 적용한다. 이미 충분한 입력이나 결과는 재사용한다. 위임하지 않는 요청에서 session을 읽지 않는다. 이 스킬이 임의로 새 세션을 만들거나 가드 거부를 다른 호스트로 우회하지 않는다.

## 제약과 주의점

- 개인 주소와 접속 정보는 연결된 private 자료에서 필요한 범위만 읽는다. 비밀 원문을 source, diff, snapshot 또는 기록에 복사하지 않는다. 기존 secret의 잠금 상태를 추정하거나 임의 변경하지 않는다.
- 사용자가 실제 운영 대상으로 지정한 구성을 우선한다. 과거 구성으로 절차를 시험했다면 그 범위와 현재 운영 대상에 대한 미검증을 밝힌다.
- 미확인 재조회와 질문은 관련 작업을 시작하거나 명시적으로 요청할 때 수행한다. 세션 밖 자동 감지나 알림을 보장하지 않는다. 취소하거나 거절한 변경은 다시 적용하거나 질문하지 않는다.

## 결과와 완료 판단

대상과 수행 범위, 의도 확정 여부, source revision 또는 미커밋 범위, 실행 여부와 근거, 검증 결과, 실제 기록 위치와 남은 미확인을 반환한다. source만 저장한 요청은 그 저장과 관련 기록으로 완료할 수 있지만 서버 적용 완료라고 하지 않는다. 적용 후 확인 실패나 미기록은 해당 단계의 미완료로 명시한다.
