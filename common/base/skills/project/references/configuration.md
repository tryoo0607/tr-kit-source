# 코드 경로 설정 연결

공간 요청에 설정 작성/변경/검증이 포함됐을 때 사용한다. 단순 설정 조회는 구조 reference의 설정 규격 자료로 충분하며 이 연결을 실행하지 않는다.

## 수행 방법과 절차

1. 확인된 공간 식별자/실제 경로와 기존 설정, 필요한 변경의 근거 및 영향을 정리한다.
2. 아래 profile-setup 연결을 적용한다. project에서 설정 필드를 자체 정의하거나 설정 파일을 직접 수정하지 않는다.
3. 반환된 유효 값을 실제 공간과 대조한다. 등록/이동/생성은 별도 공간 조작 요청으로 구분한다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| profile-setup: 코드 경로 설정 작성, 변경 또는 검증 | 호스트, 공간 식별자와 실제 경로, 기존 설정, 요청 변경과 승인 범위 | 유효 값, 변경 위치, 검증 결과와 미지원 항목 | 설정 작업에 필수. 부재이면 해당 설정 쓰기/검증 보류 |

현재 환경에서 확인한 식별자의 SKILL.md로 진입해 요청 분기와 공통 제약을 적용한다. 확인된 값과 결과는 재사용하고 내부 규격 경로를 호출 계약에 복제하지 않는다.

## 결과와 완료 판단

설정 변경과 실제 공간 조작을 구분한다. 검증된 유효 값, 공간과의 일치/충돌 및 소비 도구 미검증 범위를 전달한다.

## 실패와 복구

설정과 실제 공간이 충돌하면 조작을 멈추고 차이를 알린다. profile-setup 실패를 경로 이동이나 임의 설정 작성으로 우회하지 않는다.
