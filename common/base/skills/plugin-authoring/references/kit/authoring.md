# Kit 작성·수정

## 목적과 역할 경계

- 공통·private, 제품 adapter, 자체 skill·hook·script, 설정·배포와 검증의 전체 구성 및 연결 설계를 소유한다.
- 개별 skill·hook의 저작 규격과 검사 엔진을 이 문서에 복제하지 않는다. 해당 구성요소를 새로 작성·변경하는 경우 진입점에서 그 대상의 기준도 선택한다.
- 실제 설치·활성화·배포는 별도 담당과 승인 범위에 연결한다. kit 설계·작성 요청을 운영 적용의 포괄 승인으로 취급하지 않는다.

## 입력과 전제

- kit 목적·사용 상황·공통 원칙·기존 구조 합의·최신 정정과 현재 source·생성물·설치 상태를 구분해 확인한다.
- 기능별 담당, 실제 실행 주체, 자료의 원본·처리·저장·전송 경로, 공통/private 경계와 제품별 지원 범위를 확인한다.
- 기존 도구·공식 설치본·연결·검증 근거·선택 활성화 상태와 보존할 로컬 설정·데이터·실행 중 세션을 확인한다.
- 과거 설계·문서·구현의 존재를 최신 확정 구조로 간주하지 않는다. 충돌·대체·미결은 요구 근거와 시점으로 구분한다.
- 아래 고정 배치와 docs 규격은 현재 재구성 kit 및 같은 계약을 채택한 private에 적용한다. 다른 kit의 구조를 자동 개편하는 근거로 사용하지 않는다.

## 수행 방법과 절차

### 요구와 기능 책임 배치

- 요구별로 실제 수행 주체·담당 기능·입력·결과·의존성·실행 권한·완료 근거를 연결한다.
- 새 기능 전에 기존 외부 기능과 자체 연결을 대조한다. 재사용할 기능과 고유 정책·연결·미충족 부분을 구분한다.
- 공통/private 경계는 기기 이름이나 문구가 아니라 기능 책임·실행 범위·자료 흐름으로 판단한다.
  - 공통은 일반적인 개발·조사·자료 보관/검색·세션 연결 등의 재사용 기능을 맡는다.
  - private는 개인 인프라·개인 백업·개인 자료실 연결 등 선택적 개인 기능을 맡는다.
  - 회사·개인 자료 경계, NAS 반입·동기화·timer의 선택 여부를 기능 흐름에서 확인한다.
- 각 업무는 분석·산출물 작성·검증을 함께 소유한다. 문서라는 이유로 document를 모든 업무의 관문으로 만들지 않는다.
- 요구가 기존 기능·구조를 바꾸면 영향받는 담당·호출부·설정·시험을 함께 표시한다. 디렉토리 수나 이름부터 고정해 요구를 끼워 맞추지 않는다.

### Source와 제품별 구조

| 영역 | 소유할 책임 |
| --- | --- |
| common/base | 공통 자체 지침·skill·실행 및 검사 로직 |
| adapters/<product> | 제품 지침·도구·경로·event 입출력·등록 형식 차이 |
| 루트 scripts·tests | kit 자체 조립·검증·배포 도구와 시험 |
| docs | kit 요구·결정·구조·검증 범위의 추적 |
| 호스트 설정 | 실제 경로·역할·인증 연결·선택 활성화 값 |
| 운영·자료 저장소 | 실제 인프라 구성·실행기·원본·백업 데이터 |

- 공통과 private source는 대응하는 common/base·adapters·scripts 계층을 사용한다. 구 core/recipes 구조로 자동 회귀하지 않는다.
- private가 공통을 참조하고 공통은 private 없이 완결되게 한다. 공통 구현을 private에 복사하거나 공통이 개인 패키지의 이름·기능을 알아야 동작하게 만들지 않는다.
- 공통 의미·완료 기준은 base에 두고 제품별 호출 차이는 대응 adapter에 둔다. 같은 내용의 완성 사본을 제품별로 관리하지 않는다.
- 파일의 존재와 자동 발견·초기 주입·실제 적용을 구분한다. 공통 정책을 필수 로드 경로 밖에 두거나 제품 루트에 놓았다는 이유만으로 읽힌다고 가정하지 않는다.

### 외부 연결과 조립 계약

- 외부 기능은 공식 설치본을 사용한다. 원문·runtime을 kit 구성요소로 복제·동봉하거나 그 사본을 변형하는 기존 조립 방식을 가져오지 않는다.
- 공식 설치본 identity·사용 버전·위치 확인, 필수/선택 의존·부재·버전 차이 처리와 업데이트 영향 확인을 명시한다. 개별 skill의 연결 초안은 [skill 연결 계약](../skill/authoring.md#작성-대상의-내부외부-연결)의 계약·미확정 항목 구분을 적용한다.
- 현재 조립기·의존성 schema·변환 규칙을 구조 유지 요구의 일부로 자동 채택하지 않는다. 새 원칙과 충돌하면 재설계·미지원·미결을 구분한다.
- 자체 source와 생성물, 외부 도구가 관리하는 설치 파일의 소유권을 구분한다. 생성물을 직접 수정해 source 불일치를 해결하지 않는다.
- 조립 입력·출력·제품별 포함 범위·경로 충돌·필수 파일 누락·미해결 참조·버전/무결성의 검사 계약을 정한다.
- 충돌을 조용한 덮어쓰기·중복 정본·동명 provider 대체로 해결하지 않는다. 자동 병합을 지원한다고 가정하지 않는다.

### 설정·정책·권한 연결

- 공통·프로젝트·호스트 설정의 소유 위치와 참조 방향을 정한다. 같은 경로·정책·identity를 여러 곳에 중복 등록하지 않는다.
- 적용 범위·사용자 승인·제품 권한·호스트 역할 가드·hook 검사를 서로 대체하지 않는다. 실제로 강제되는 범위와 지침상 판단 범위를 명시한다.
- source 저작, 호스트 설정 변경, 설치, hook trust, Git guard 등록, timer 활성화, 세션 반영을 별개 상태로 다룬다.
- 실패·역할 거부를 다른 호스트·수단으로 우회하지 않는다. 원격 요청 전달·수신 확인·실제 실행·완료 회신을 구분한다.
- 기존 profile·자료 연결·원본 위치·세션을 보존한다. 자동 이관·자료 수집·개인 저장소 전송은 별도 요구와 승인 없이 수행하지 않는다.

### 변경·업데이트·검증 설계

- 구조·의존성·정책·제품 계약 변경의 영향 범위를 요구·코드·설정·시험으로 연결한다.
- 실제로 검토 가능한 source·설계 기준본과 변경 결과를 보존한다. commit이 없으면 그 상태와 파일 hash 등 확인 가능한 기준을 쓰고 가짜 revision을 만들지 않는다.
- 외부 업데이트는 이전 사용 버전·자체 연결의 의도·새 버전의 차이를 대조한다. 기계적 연결 성공과 의미·행동 보존을 구분한다.
- own source 검사, 제품별 조립, 공식 기능 연결, 호스트 설치·활성화, native 이벤트, 모델 행동·새 세션·압축 시험을 구분해 설계한다.
- 공통 단독·공통+private, 필수 의존 부재·다른 버전·미지원 제품, 정상·거부·부분 실패·복구 사례를 범위에 맞게 정한다.
- 설치·배포·복구 절차도 시험 대상으로 확인한다. 격리 fixture 결과를 실제 운영 반영·복구 성공으로 확대하지 않는다.

## 연계와 의존

- 개별 skill·hook 작성·감사는 진입점의 해당 분기와 같은 references 아래의 대상별 기준에 연결한다. 저작·감사 요청을 서로 바꾸지 않는다.
- 구조·읽기 흐름·실제 행동 시험의 적용 조건과 상세 방법은 본문·shared를 따른다. kit 전체를 설명할 때 파일 구조와 수행 흐름은 분리한다.
- 빌드·배포·호스트 관리 도구는 기존 담당과 실제 계약을 확인해 연결한다. 지침 참조를 자동 실행·별도 서비스·새 관리 시스템으로 포장하지 않는다.

## 결과와 완료 판단

- 공통 보고에 실제 기능 목록·책임·의존 방향·제품별 포함/미지원·정책/자료 경계·구조/흐름 도표를 연결한다.
- docs에는 요구·반영 위치, 구조, 결정 이유·변경 이력, 실제 검증 범위·결과·한계를 갱신한다. 상세 저작 기준을 중복 저장하지 않는다.
- 같은 폴더의 audit.md에서 확인할 전체 inventory·요구 연결·개별 감사 결과·제품/환경별 증거·미결을 연결한다. 감사 적용은 진입점 기준을 따르며, 이 자료 연결이 실호스트 전수 조회·운영 적용의 승인은 아니다.
- 작성된 source·조립물·설치·활성화·사용 가능·실제 운영 효과의 완료 상태를 분리한다. 미작성 기능·미검증 제품·부분 배포를 전체 완료로 보고하지 않는다.
