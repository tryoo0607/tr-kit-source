# Kit 감사

## 목적과 역할 경계

- kit 전체의 요구 충족·책임·의존·제품 연결·정책/자료 경계·배포 출처·검증 공백을 대조한다.
- 같은 폴더의 [작성 기준](authoring.md)을 규칙 원문으로 사용한다. 개별 skill·hook 감사를 단순 합산한 것으로 끝내지 않고 구성 사이의 관계를 확인한다.
- 공통 판정·권한·보고와 조건부 공통 시험은 진입점·shared를 따른다. 감사가 자동 수정·설치·운영 적용으로 확대되지 않게 한다.

## 입력과 전제

- 감사 대상 source·범위·제품·private 포함 여부·환경과 기준 revision 또는 파일 hash를 확인한다.
- 요구·결정·미결, 선언된 기능과 실제 파일·설정·외부 설치 의존·생성물·호스트 증거를 구분한다.
- 개별 감사 결과와 실행 증거가 현재 source·제품·설정에 유효한지 확인한다. 없으면 미실행으로 남기고 전체 통과로 집계하지 않는다.
- 실호스트 조회·원격 연결·운영 시험이 승인되지 않았다면 source와 제공된 증거 범위에서 감사한다. 미확인을 없애기 위해 권한을 확대하지 않는다.

## 수행 방법과 절차

### 전체 목록과 요구를 양방향 대조

- 선언된 skill·hook·script·제품 adapter·외부 기능·설정·문서와 실제 inventory를 대조한다.
- 요구에서 반영 지점·검사·증거를 추적하고, 각 구성에서 근거 요구와 담당을 역으로 확인한다.
- 명시된 미작성·제안·보류와, 있어야 하지만 설명 없이 누락된 구성을 구분한다. 초안의 존재를 실행 가능 기능으로 집계하지 않는다.
- 구성별 책임이 겹치거나 필요한 연결 담당이 없는지 확인한다. 범위를 제한해 감사했다면 제외 항목과 영향을 표시한다.

### 전체 구성의 감사 영역

아래 기준 절 이름은 authoring.md를 가리킨다. 규칙 본문은 그 위치에서 확인한다.

| 감사 영역 | 근거 기준 | 증거·검사 방법 |
| --- | --- | --- |
| 기능·역할 | 요구와 기능 책임 배치 | 요구·실제 owner·입력/결과 연결과 중복·누락을 대조. 같은 업무를 새 이름으로 분산하거나 문서 관문을 강제하는지 확인 |
| 공통/private | 요구와 기능 책임 배치, Source와 제품별 구조 | 공통 단독 동작·개인 기능 의존·자료 전송·백업 활성 조건을 대조. 폴더명이나 문구만으로 분리 판정하지 않음 |
| 제품 adapter | Source와 제품별 구조 | 공통 의미·완료 기준과 실제 제품 호출·경로·등록·주입 대조. 제품별 완성 사본·미지원 은폐·자동 병합 가정 확인 |
| 외부 의존 | 외부 연결과 조립 계약 | 선언한 공식 설치본·identity·버전·실제 참조와 부재 처리 대조. kit 안의 원문/runtime 사본·변형·동명 provider 대체 확인 |
| Source·생성물 | 외부 연결과 조립 계약 | 입력 revision/hash·실제 생성물·포함 파일·무결성·출처 연결 대조. 생성물 수동 수정·source와의 불일치 확인 |
| 설정·자료 | 설정·정책·권한 연결 | 소유 위치·기본값·참조 방향·실제 읽기/저장/전송 경로 대조. 개인 값 유출·회사 자료 자동 반입·중복 정본 확인 |
| 권한·승인 | 설정·정책·권한 연결 | 지침·제품 권한·호스트 가드·hook·사용자 승인 사이의 실제 경계 확인. 전달·조회 승인이 실행·변경 승인으로 확대되는지 확인 |
| 배포·활성화 | 변경·업데이트·검증 설계 | 제품별 source 출처·배포물·설치·trust·등록·세션 반영·실제 callback을 분리해 대조. 단일 단계 성공을 전체 완료로 확대하는지 확인 |
| 업데이트·변경 | 변경·업데이트·검증 설계 | 전후 요구·기능·연결·버전 차이와 영향 시험 대조. 기계적 재연결 성공만으로 의미 보존을 주장하는지 확인 |
| 기록·검증 상태 | 결과와 완료 판단 | docs의 요구·구조·결정·검증 상태와 실제 source·보고·증거 대조. 과거 결과·미확인·부분 배포·미작성을 성공으로 합치는지 확인 |

### 개별 감사와 관계 검사의 연결

- 대상 skill·hook에 개별 감사가 필요하면 진입점에서 각 기준을 선택해 순차 적용한다. 개별 체크리스트를 이 문서에 복제하지 않는다.
- 개별 감사에서 통과했더라도 실제 연결 시 입력·결과·권한·정책이 달라지는지 대조한다.
- 같은 shared·검사 엔진·설정·실행기를 여러 구성에서 사용하는 경우 결과 재사용·동시 실행·변경 영향과 책임을 확인한다.
- 전체 감사의 필수 범위가 개별 샘플 감사만으로 덮였다고 주장하지 않는다. 샘플링했으면 선택 이유와 남은 범위를 밝힌다.
- 현재 요구에 영향을 주는 모순을 발견하면 기준 자체의 충돌, 구현 결함, 증거 부재, 환경 부재를 구분한다.

## 연계와 의존

- 같은 폴더 authoring.md는 kit 구조·연결의 규칙 원문이다. 기준을 읽었다고 저작 요청으로 바꾸지 않는다.
- skill·hook 감사는 진입점의 해당 분기를 통해 적용한다. 해당 기준 부재와 실제 개별 감사 미실행을 전체 결과에 표시한다.
- 기존 빌드·무결성·보안·runtime 검증 도구와 담당 기능을 재사용한다. 도구 이름·설치 사실·전달 receipt를 실행·완료 증거로 대신하지 않는다.
- 실제 호스트·원격·배포 확인은 그 대상과 권한을 소유한 기능에 연결한다. 승인·역할 거부를 다른 수단이나 호스트로 우회하지 않는다.

## 결과와 완료 판단

- 판정 이름·도구 오류·증거 부족 처리는 공통 본문을 따른다.
- 전체 inventory와 요구별 확인 현황, 개별 감사 상태, 구성 간 발견 사항, 제품·환경별 미검증을 구분해 보고한다.
- 발견 사항에는 기준 위치·실제 증거·영향받는 구성·보완 제안·필요 재검증을 붙인다. 재현하지 못한 원인 추정은 사실과 구분한다.
- 공통 단독·private 선택·양 제품·설치/활성화 등 확인하지 못한 범위를 전체 적합으로 확대하지 않는다.
- 감사 보고 완료와 kit 구현·검증·배포 완료를 구분한다. 미해결 사항이 있으면 범위와 다음 조치를 밝히고 무조건 통과 결론을 내리지 않는다.
