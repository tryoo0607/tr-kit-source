# Hook 감사

## 목적과 역할 경계

- hook의 실제 코드·등록·활성 조합·동작 증거를 요구와 같은 폴더의 [작성 기준](authoring.md)에 대조한다.
- 작성 기준을 복제하거나 감사 중 정책·설정을 완화하지 않는다. 공통 판정·권한·보고는 진입점, 상세 공통 시험법은 shared가 소유한다.
- 개별 hook과 연결된 검사·adapter·등록을 대상으로 하며 전체 kit 감사·실서버 운영·자동 수리로 확대하지 않는다.

## 입력과 전제

- 적용 요구·금지·승인·예외·변경 조건, 실제 코드·설정·제품·버전과 감사 범위를 확인한다.
- 현재 등록 source·실행 명령·이벤트·matcher·trust·활성 상태의 근거와 관련 hook 조합을 확인한다. 실제 호스트 조회 권한이 없으면 제공된 증거와 정적 파일 범위로 한정한다.
- 전후 자료·정상/위반/비대상·오류·timeout·동시 실행 시험의 입력·결과·시점을 확인한다. 없는 증거를 성공으로 추정하지 않는다.

## 수행 방법과 절차

### 작성 기준별 증거 대조

아래 기준 절은 authoring.md를 가리킨다. 규칙 자체는 그 위치에서 읽는다.

| 기준 절 | 확인할 증거·검사 방법 |
| --- | --- |
| 목적·적용 범위 설계 | 요구와 실제 matcher·대상 판별·실행 위치 대조. 다른 cwd·저장소 지정·절대경로·비대상 입력에서 보호 대상이 달라지는지 확인 |
| 검사 결과·실패 설계 | 실제 입력별 판정과 제품에 반환한 결과·실행 여부 대조. 필수 검사 실패가 허용으로 변환되는지, 후검사가 이전 효과를 차단했다고 주장하는지 확인 |
| 실행·중복 관계 설계 | 선언·유효 등록 source·중복·동시 실행 결과 대조. 순서 의존·중복 수집·상태 충돌과 결과 상쇄 여부 확인 |
| 설정·예외·변경 권한 설계 | 실제 기본값·설정 결합·잘못된 값·누락·변경 경로 대조. 프로젝트 값이 공통 금지를 해제하거나 승인 범위를 확대하는지 확인 |
| 검증·추적 설계 | 요구에서 코드·등록·시험 증거와 역방향 근거를 추적. revision·제품·설정 차이로 무효인 결과를 재사용하는지 확인 |

### 검증 층위별 분리

| 층위 | 필요한 근거 | 이것만으로 충분하지 않은 것 |
| --- | --- | --- |
| 공통 검사 | 실제 유효 입력·경계·실패 입력의 판정과 부수효과 | 함수·파일 존재 또는 설명 |
| 제품 adapter | 확인된 payload의 입력·출력 변환과 오류 처리 | 공통 엔진 단독 통과 |
| 등록·신뢰 | 실제 유효 설정 source·버전·등록·trust 상태 | 소스 hooks.json 또는 설치 목록 |
| native 동작 | 해당 제품의 실제 이벤트에서 callback·허용·차단·오류·timeout 관측 | subprocess 직접 호출이나 합성 payload |
| 조합·비간섭 | 다른 활성 hook과 함께 대상·비대상·동시 실행 결과 | 개별 hook의 단독 성공 |

- 실제 위반을 확인한 차단과 검사 오류로 인한 보류를 구분한다. 실행 반환 코드만 보지 말고 대상 동작이 실제 실행됐는지 확인한다.
- 금지·설정·민감값 시험은 합성 fixture와 승인된 격리 대상에서 수행한다. 실비밀을 노출하거나 운영 동작을 일으켜 시험하지 않는다.
- 실제 제품 계약이 미확인이면 특정 반환 필드가 차단을 보장한다고 판정하지 않는다. 미지원·미실행·미확인을 구분한다.
- 비밀 검사·공유 로그·마스킹이 연결돼 있다면 각 단계의 실제 입력과 저장 결과를 확인한다. 한 단계의 마스킹이 다른 hook이나 원 실행 로그까지 보호했다고 확대하지 않는다.

## 연계와 의존

- 같은 폴더 authoring.md는 규칙 원문, 본문에서 선택한 shared는 검사 방법으로 읽는다. reference가 독립 실행·결과 반환 주체인 것으로 표현하지 않는다.
- 정적 등록 검사·실제 호스트 상태·독립 격리 실행 등 필요한 수단의 권한과 범위를 구분한다. native 상태를 조회할 수 없으면 결과를 그 범위로 제한한다.
- 기존 검증·보안 도구를 재사용한다. 도구 실패를 finding으로 바꾸거나 임의의 예외·대체 엔진으로 통과시키지 않는다.

## 결과와 완료 판단

- 판정 이름·도구 오류·증거 부족의 처리는 진입점의 공통 판정 기준을 따른다.
- 결과는 정책 근거, 실제 등록/활성 상태, 코드 판정, adapter 변환, native 효과, 조합·비간섭으로 나눠 기록한다.
- 미확인·미실행인 층위가 있으면 hook 전체가 안전하게 차단한다고 결론내리지 않는다. 제품 하나의 결과를 다른 제품으로 확대하지 않는다.
- 발견 사항마다 기준·실제 관측·영향 범위·보완 제안·재검증할 입력을 붙인다. 감사 요청만으로 기존 hook을 끄거나 수정하지 않는다.
- 공통 보고에 실제 검사 범위·사용한 도구·제품/버전·상태·제외 범위와 남은 증거를 연결한다.
