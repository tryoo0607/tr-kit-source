# Skill 작성·수정

## 목적과 역할 경계

- 자체 skill 신규 작성·수정의 설계·작성 규격을 소유한다. 이 기준은 plugin-authoring 자신과 작성하는 reference에도 적용한다.
- 공통 판단·승인·외부 재사용·실패 처리·완료 보고는 진입점 SKILL.md, 조건부 상세 시험법은 shared가 소유한다.
- 이 문서는 그 정책을 다시 규정하지 않고 skill의 역할·본문·분기·연결·지원 파일과 관측점을 구체화한다.

## 입력과 전제

- 사용자 업무·기대 산출물, 대표 발동 요청·가까운 비대상 요청, 기존 담당과 보존할 동작을 확인한다.
- 기존 요청·사례를 재사용한다. 작성자가 편한 사례로 대체하거나 이미 답한 내용을 고정 설문으로 반복하지 않는다.
- 수정할 때는 본문뿐 아니라 연결된 reference·script·assets·제품 metadata·호출부 중 영향받는 자료를 확인한다.
- 고정된 외부 저작 기능이 있다면 그 선택을 재사용한다. 사용 가능 여부·제품 지원을 확인하지 않고 공급자를 바꾸지 않는다.

## 수행 방법과 절차

### 역할·발동·입출력

- 같은 사용자 업무·입력·결과를 맡는 기존 기능이 있으면 보강 가능성을 대조한다. 새 이름·파일·폴더 자체를 독립 역할의 근거로 삼지 않는다.
- 같은 외부 기능을 연결하는 wrapping 스킬이 있으면 그 스킬의 재사용을 우선 검토한다. 필요한 조작을 아직 지원하지 않으면 기존 연결을 보강할 수 있는지 확인한다. 직접 호출이 필요한 경우에는 이유와 설치본 확인을 재사용하는 경로를 명시한다.
- 독립 skill이면 기존 담당과의 차이·연결·비대상 요청을 명시한다.
- description에는 실제 업무·발동 요청·혼동하기 쉬운 경계를 담는다. 이름·개념 설명과 실제 수행 요청을 구분하고 무관한 업무까지 포괄하지 않는다.
- 아래 항목이 같은 사용자 업무를 가리키도록 설계한다.

| 항목 | 정할 내용 |
| --- | --- |
| 입력 | 필수·선택 자료, 재사용할 기존 입력, 누락 입력 확인 시점 |
| 수행 | 필요한 판단·지침 읽기·도구 실행·위임 및 실제로 필요한 순서 |
| 결과 | 생성·변경할 산출물과 반환 정보 |
| 의존 | 대상·필수 여부·전달 입력·필요한 결과 |
| 실패 | 부재·오류·부분 변경에서 멈출 지점과 복구 조건 |
| 완료 | 관측할 동작·산출물·근거, 미검증으로 남길 범위 |

### 공통 목차와 항목 확장

- SKILL.md와 자체 reference에서 아래 절 중 필요한 것만 표의 순서로 사용한다. 빈 절을 만들지 않는다.
- 이 목차 규격은 kit의 자체 저작 지침에 적용한다. 외부 공식 설치본의 형식을 맞추기 위해 원문을 변경하는 근거로 사용하지 않는다.
- 소제목으로 내부 내용을 나눌 수 있지만, 새 공통 절의 채택을 우회하는 용도로 사용하지 않는다.

| 절 이름 | 포함할 조건 |
| --- | --- |
| 목적과 역할 경계 | 맡을 업무와 다른 담당의 경계를 설명해야 함 |
| 입력과 전제 | 대상·환경·자료·기존 상태가 수행에 필요함 |
| 수행 방법과 절차 | 고유한 판단·방법·수행 순서가 있음 |
| 요청별 분기 | 요청·조건에 따라 선택할 절차나 자료가 다름 |
| 연계와 의존 | 다른 skill·도구와의 실제 연결 계약이 필요함 |
| 제약과 주의점 | 누락 시 잘못 처리하기 쉬운 금지·경계·주의가 있음 |
| 분량과 읽기 범위 | 산출 분량·필수 읽기·추가 읽기를 정할 필요가 있음 |
| 결과와 완료 판단 | 제공할 결과·관측 근거·완료 상태를 정해야 함 |
| 출력 형식 | 형식이 산출물의 사용 계약에 해당함 |
| 실패와 복구 | 중단·재시도·대체·부분 적용·복구를 구분해야 함 |
| 예시 | 구체 사례가 판단이나 형식의 모호함을 줄임 |

- 새 공통 절이 필요하면 이름·의미·사용 조건·이유·기존 절과의 차이·순서를 제안하고 사용자가 채택한 뒤 기준을 갱신한다.
- 예시 작성 허가를 새 절 채택으로 간주하거나 기존 문서를 일괄 개편하지 않는다.

### 요청별 분기 작성

- 요청별 대안 분기는 `요청 | 선택 조건 | 읽을 reference` 표로 작성한다. 필요하면 수행 시점·필요한 결과를 추가하되 선택 조건을 생략하지 않는다.
- 같은 요청의 대안 행은 위에서부터 평가하고 처음 일치하는 하나만 선택하도록 작성한다.
- 별도 요청이 함께 있으면 요청별로 선택한다. 서로 다른 요청의 행 전체를 하나의 배타적 선택으로 묶지 않는다.
- 대안이 없는 요청은 해당 요청 포함 여부를 선택 조건으로 적는다.
- 공통 필수 제약과 조건부 추가 절차는 대안 분기와 구분한다. 추가 조건이 성립하면 이미 대안을 선택했어도 그 절차를 적용하게 연결한다.
- 조건부 추가 절차 표에는 적용 조건·읽을 자료·수행 시점을 명시한다. 이 표는 첫 일치에서 멈추지 않고 성립하는 조건을 각각 적용하도록 작성한다.
- `그 외`는 같은 요청의 마지막 대안에서 앞선 조건이 성립하지 않을 때만 사용한다.
- 사용 가능 여부로 분기하면 본문에는 대상 식별자·확인 위치·선택 조건을 둔다. 판정은 진입점의 공통 기준을 따르고 실제 실행 성공과 구분한다.
- 선택하지 않은 자료를 기본으로 읽게 하지 않는다. 실행 실패를 `그 외`의 자동 성립이나 대체 경로 실행 승인으로 취급하지 않는다.

### 본문·reference·지원 파일 배치

- 본문에는 해당 skill 사용 시 필요한 역할 경계·공통 판단·분기·필수 제약·완료 판단을 둔다.
- reference 첫머리에 담당 범위를 밝히고, 선택된 요청의 상세만 담는다.
  - 읽을 조건·얻을 내용·수행 시점을 실제 진입 담당에서 연결한다.
  - 일부 절만 필요하면 유효한 절 제목과 경로를 지정한다. 필수 제약에 도달하지 못하는 부분 읽기로 만들지 않는다.
  - 본문과 선택한 자료만으로 해당 요청의 절차를 수행할 수 있는지 확인한다. 관련 없는 자료를 일괄 로드하거나 깊은 참조 사슬로 핵심 조건을 숨기지 않는다.
  - 여러 요청이 공유하는 상세 절차는 한 곳에서 소유한다. 발동 조건·계약·절차를 다른 파일에서 각각 갱신하지 않는다.
- 지원 자료는 실제 역할에 따라 둔다.
  - scripts: 반복 실행이나 결정적 처리가 필요한 로직
  - assets: 산출물에 사용하는 템플릿·이미지·출력용 자료
  - references: 조건부로 읽을 지침·규격·사례
- 지침 읽기를 별도 실행 프로그램·격리 세션·자동 반환으로 표현하지 않는다.
- 디렉토리 수나 분류를 맞추기 위한 빈 폴더·파일·별도 안내서를 자동 생성하지 않는다.

### 수정 시 보존과 제품별 대응

- 삭제·분리·이동 전에 기존 호출부와 지원 자료의 사용 목적을 확인한다.
- 보존할 동작·선택 설정·외부 연결·지원 파일을 새 배치와 대조한다. 초기화·metadata 생성으로 기존 설정을 덮어쓰지 않는다.
- 공통 판단·완료 기준은 base, 제품의 경로·호출·metadata 차이는 대응 adapter에 둔다. 같은 책임은 대응하는 상대 계층에서 관리한다.
- 차이가 없는 완성 본문을 제품별로 복제하지 않는다. 대응 계층이라는 이유로 자동 병합·덮어쓰기를 가정하지 않는다.
- 공통 정의와 adapter 정의가 겹치거나 필요한 구현이 없으면 확인된 조립·연결 계약에 따라 충돌·누락을 드러낸다. 새 병합 규칙을 임의로 만들지 않는다.

### 형식·metadata·실행 자료

- **wrapping 스킬**은 특정 외부 스킬이나 도구에 수행을 맡기고 킷의 사용 조건·입출력·제약을 연결한다. 폴더 이름과 SKILL.md의 `name`에 `ext-<기능명>`을 사용한다.
- **kit 자체스킬**은 킷이 업무 절차와 완료 판단을 소유하는 스킬이다. 업무 이름을 사용하며 필요한 단계에서 wrapping 스킬을 호출할 수 있다. 예를 들어 `project`는 코드 공간의 배치를 판단하고, worktree 조작이 필요할 때 `ext-worktrunk`를 호출한다.
- 분류할 때는 호출 전에 누가 작업의 방향과 범위를 정하고, 호출 뒤에 누가 원래 업무의 완료 조건을 판단하는지 확인한다. 외부 기능에 업무 수행을 맡기고 반환값을 대조해 전달하는 역할은 wrapping 스킬에 해당한다. kit 자체스킬은 부분 조작을 맡기더라도 전체 업무의 판단을 이어간다.
- 킷의 외부 기능 연결을 설명할 때 한국어로는 `외부 연결`, 영어 이름으로는 `external`을 사용한다. 공식 외부 기능 ID와 기존 설정·CLI의 호환성 식별자는 실제 값을 그대로 표기한다.
- 이름·폴더·frontmatter와 선택 metadata는 공식 저작 기능·제품 계약의 확인된 규격을 따른다. 제품 하나의 선택 필드를 모든 제품에 강제하지 않는다.
- validator가 지원하지 않는 필드를 검사 통과만을 위해 삭제·변형하지 않는다. 확인된 호환 수단·수동 대조·도구 미실행을 구분한다.
- 설명·이유는 문단, 개별 조건은 항목, 실제 순서는 번호, 비교·분기는 표를 사용한다.
- 항목화하면서 조건·예외·금지·의존 관계를 삭제하거나 구체적 문구를 넓은 말로 바꾸지 않는다. 계층은 실제 관계를 나타낸다.
- 새로 작성·수정한 실행 코드는 의미 있는 입력·출력과 실패 사례로 실행 검증한다. skill 형식 검사로 script 동작 검증을 대신하지 않는다.

## 연계와 의존

### 공식 저작 기능

- 일반 skill 저작에서 공식 skill-creator를 선택하면 [공통 외부 연결](../../../../references/external-connection.md)의 `skill-creator` (종류 `skill`)를 검수하고 반환된 공식 SKILL.md에 진입한다. 설치본 또는 검수 근거가 없으면 외부 수행을 보류한다.
- 대상 지침으로 진입한 뒤 그 기능이 선택한 절차·지원 도구를 적용한다. 호출자가 외부 내부 reference를 임의 고정하거나 진입을 생략하지 않는다.
- 이미 선택한 기능을 쓸 수 없으면 미충족 부분을 밝히고 관련 절차를 보류한다. 공급자나 자체 절차로 조용히 바꾸지 않는다.

| 요청 | 전달 입력 | 필요한 결과 |
| --- | --- | --- |
| 신규 skill 작성 | 목적·발동·비대상·산출물·대상 경로·환경·사용자 제약 | 저작 결과, 지원 도구·검사 범위, 미충족 부분 |
| 기존 skill 수정 | 위 입력과 기존 파일·보존 동작·변경 범위 | 수정 결과, 보존·변경 내용, 검사 결과·미결 |

- 초기화·metadata 생성·validator 사용 여부는 대상 기능 지침과 실제 필요로 정한다. 기존 파일 보존은 위 '수정 시 보존과 제품별 대응' 기준을 적용한다.

### 작성 대상의 내부·외부 연결

- 실제 사용하는 쪽의 `연계와 의존`에서 대상·선택 조건·입력·결과·필수 여부·부재 시 동작을 한 번만 소유한다.
- 수행 단계는 해당 계약을 지목해 적용 시점을 밝힌다. 본문·다른 reference에 계약을 복사하지 않는다.
- 외부 연결 초안에서도 전달 입력·필요 결과·제품별 지원/차이를 각각 구분해 남긴다. provider/API가 미확정이면 지금 요구에서 정할 수 있는 입력·결과와 아직 확인할 수 없는 상세를 분리한다. `입출력 미결` 한 줄로 대체하거나 세 항목을 생략하지 않으며, 새 API·제품 지원 여부를 추정해 채우지 않는다.
- 대상 식별은 현재 환경의 실제 식별자·확인 위치로 연결한다. 지침 읽기·도구 실행·독립 세션을 구분한다.
- 직접 CLI 호출은 확인된 명령·실행 위치·입력·결과 확인을 작성한다. CLI라는 이유만으로 불필요한 연결 관리 계층을 추가하지 않는다.

## 분량과 읽기 범위

- 최초 필수 읽기와 조건부 추가 읽기를 구분한다. 오류·조회에서 변경으로의 전환 등으로 추가 제약이 필요해지면 해당 행동 전에 읽게 한다.
- 실행 시 저작 기준을 다시 읽어야만 동작하는 skill로 만들지 않는다. 작성한 skill 자체의 본문·선택 자료에서 수행할 수 있어야 한다.
- 읽기량의 측정·비교 방법과 보고 한계는 같은 references 아래의 [읽기·호출 흐름 검사](../shared/reading-flow.md)가 소유한다. 여기서는 대표 요청의 분기·본문·reference·외부 연결을 측정 대상으로 연결한다.
- 위 링크는 읽기 검사의 새 발동 조건이 아니다. 실제 적용 여부는 진입점 SKILL.md의 조건부 공통 절차를 따른다.
- 줄·문자·토큰 수 목표를 맞추기 위해 요구·예외·실패 대응을 제거하지 않는다. 추가 축약은 실제 중복·실패·재조회 부담에 근거한다.
- 상위 지침과 중복을 제거할 때는 해당 상위 지침이 실행 환경에 실제 제공되는지 확인한다.

## 결과와 완료 판단

- 공통 검증 조건·시험법은 본문·shared를 따른다. skill에서는 다음 관측점을 요구와 대조한다.
  - description과 대상·비대상 요청의 실제 선택
  - 분기 선택·reference 읽기와 필수 제약 도달
  - 외부 기능·도구의 실제 입력과 반환 결과
  - 산출물 내용·형식·변경 범위와 보존 동작
  - 입력·의존성 부재, 실패·부분 변경에서의 질문·보류·복구

  - 요구·보존 조건·변경 범위·대상 파일
