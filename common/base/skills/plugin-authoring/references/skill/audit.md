# Skill 감사

## 목적과 역할 경계

- 작성된 자체 skill의 요구 충족·구조·분기·연결·검증 근거를 대조하고 발견 사항과 미검증 범위를 판정한다.
- 같은 폴더의 [작성·수정 기준](authoring.md)을 규범 근거로 사용한다. 그 기준 본문을 여기서 복제하거나, 기준을 읽는 행위를 작성 요청으로 바꿔 저작 절차를 재실행하지 않는다.
- 공통 승인·외부 기능 선택·실패 처리·완료 보고는 진입점 SKILL.md, 조건부 상세 시험법은 shared가 소유한다. 이 문서는 skill 감사에서 확인할 증거·검사 방법·판정을 소유한다.
- 개별 skill과 관련 파일을 감사한다. kit 전체 감사나 hook 감사로 자동 확대하지 않는다. 다른 구성과의 관계에서 발견한 문제는 근거와 영향받는 담당을 표시한다.

## 입력과 전제

- 대상 skill의 실제 루트·본문·관련 reference·script·assets·제품 adapter와 감사 범위를 확인한다.
- 요구 원문 근거·채택한 결정·보존 조건·대상 및 비대상 요청·완료 기준을 확인한다. 해석·제안·미결은 확정 기준과 구분한다.
- 수정 감사라면 변경 전후 파일·revision·diff와 영향받는 호출부·자료를 확인한다. 기준본이 없으면 보존 여부를 확인했다고 판정하지 않는다.
- 제출된 형식·실행·모델 행동·제품별 시험 결과의 대상·버전·설정·시점을 확인한다. 재사용 가능성은 공통 본문에 따라 판단한다.
- 대상별로 적용할 작성 기준의 절을 선택한다. 관련 없는 기능·모든 외부 자료를 무조건 읽지 않는다. 범위 제한 때문에 제외한 항목은 결과에 남긴다.

## 수행 방법과 절차

### 기준과 관측을 연결

- 요구와 적용 작성 기준의 위치를 먼저 연결하고, 실제 파일·동작·시험 증거를 대조한다.
- 아래 표의 기준 절 이름은 authoring.md의 해당 절을 가리킨다. 상세 규칙은 그 위치에서 확인하며 이 표를 새 규칙 원문으로 사용하지 않는다.
- 문서가 존재함, 문서가 지시함, 실제로 읽힘, 실제 동작함을 구분한다.

| 검사 영역 | 근거로 읽을 작성 기준 | 확인할 증거와 검사 방법 |
| --- | --- | --- |
| 요구·역할·발동 | 역할·발동·입출력 | 요구와 description·대표 요청·비대상 요청·산출물을 대조. 독립 역할의 근거와 기존 담당과의 경계 확인 |
| 입력·수행·결과 | 역할·발동·입출력 | 입력 누락·정상·부분 실패 사례에서 필요한 판단과 결과가 이어지는지 추적. 산출물 내용·형식·범위와 요구 대조 |
| 목차·계층 | 공통 목차와 항목 확장 | 실제 제목·순서·절 내용과 포함 조건 대조. 빈 절, 소제목을 통한 새 공통 절 우회, 채택 근거 없는 항목 추가 확인 |
| 대안 분기 | 요청별 분기 작성 | 행별 조건·자료를 확인하고 경계 사례를 대입. 누락·중첩·우선순위와 그 외 처리 확인. 정적 대입과 실제 모델 선택은 구분 |
| 복수 요청·추가 절차 | 요청별 분기 작성 | 혼합 요청에서 요청별 대안과 성립하는 추가 조건이 모두 처리되는지 추적. 첫 일치로 전체 처리가 끝나거나 같은 자료를 불필요하게 반복하는지 확인 |
| 의존성 선택·실패 | 요청별 분기 작성, 공식 저작 기능 | 대상 식별·확인 위치·판정 근거와 실행 결과 대조. 선택 판정에 불필요한 실행이 섞이거나 실행 실패가 무승인 대체로 이어지는지 확인 |
| 본문·reference 분담 | 본문·reference·지원 파일 배치 | 항상 필요한 제약의 도달 여부와 조건부 자료의 선택 경로 확인. 같은 기준의 복수 정본·깊은 참조·불필요한 일괄 읽기 확인 |
| 연결 계약 | 작성 대상의 내부·외부 연결 | 계약 소유 위치와 실제 호출 지점을 연결. 대상·입력·기대 결과·의존·부재 동작을 실제 도구·지침 사용과 대조 |
| 지원 자료 | 본문·reference·지원 파일 배치 | scripts·assets·references의 실제 용도와 소비자 확인. 미사용·빈 자료, 출력용 자료를 지침으로 읽는 혼동 확인 |
| 수정 보존·제품 차이 | 수정 시 보존과 제품별 대응 | 전후 동작·설정·호출부·자료와 양 제품 연결 대조. 삭제·이동의 영향, 공통 사본·충돌·누락·임의 병합 확인 |
| 형식·metadata | 형식·metadata·실행 자료 | 적용 규격과 실제 파일·공식 검사 결과 대조. 미지원 필드를 삭제해 통과했는지, 제품 전용 필드를 일괄 요구하는지 확인 |
| 실행 코드 | 형식·metadata·실행 자료 | 변경한 script의 실제 정상·실패 입력과 출력·부수효과 증거 확인. 형식 검사만 있으면 실행 성공으로 판정하지 않음 |
| 읽기 범위·분량 | 분량과 읽기 범위 | 선언한 최초·추가 읽기 경로와 실제 관측을 구분해 대조. 비교의 누락 자료·중복·측정 한계와 의미 보존 확인 |
| 실제 행동·보존 | 결과와 완료 판단 | 대상·비대상·모호함·실패에서 실제 선택·행동·산출물 대조. 새 세션·압축·제품별 결과의 증거 범위 확인 |
| 감사 인계·완료 주장 | 결과와 완료 판단 | 작성 결과·시험·미결이 감사 입력에 연결되는지 확인. 기초 형식 통과·과거 결과·미실행을 전체 완료로 확대하는지 대조 |

### 공통 정책과 시험 방법 연결

- wrapping·승인 범위·감사와 수정의 경계는 공통 본문을 기준으로 대상의 실제 변경·연결과 대조한다. 이 문서에서 금지나 승인 예외를 새로 정하지 않는다.
- 구성 설명·읽기 흐름·행동 시험이 필요한지는 진입점의 조건부 공통 절차를 따른다. 해당 shared를 적용해 결과를 위 검사 항목에 연결한다.
- 재사용 가능한 검증 도구나 전문 감사 기능이 있으면 공통 선택 기준에 따라 적용한다. 기존 검사를 다시 구현하거나 같은 결과를 중복 생산하지 않는다.
- 감사 중 발견한 문제가 기준 자체의 모순인지 대상 구현의 위반인지 구분한다. 통과시키기 위해 기준을 고치거나, 감사 요청을 대상 수정으로 바꾸지 않는다.

## 연계와 의존

| 대상 | 활용 목적·전달 입력 | 필요한 결과·부재 처리 |
| --- | --- | --- |
| 같은 폴더의 authoring.md | 적용 작성 기준 확인. 감사 대상·요구·변경 범위로 관련 절 선택 | 규칙의 근거 위치. 필요한 기준이 없으면 추측하지 않고 해당 항목을 미확인으로 남김 |
| 진입점에서 선택한 shared reference | 감사 수행자가 해당 검사 방법을 읽고 현재 대상·요구·증거에 적용 | 수행자가 확인한 근거와 한계. shared가 별도 감사 주체나 결과 반환 도구인 것은 아님. 파일 선택은 진입점이 소유 |
| 현재 환경에서 선택한 공식 검증·전문 감사 도구 | 실제 대상 파일·적용 제품·확인할 항목 전달 | 검사 결과·도구 오류·검사 범위. 사용 불가와 위반 발견을 구분하고 무승인 설치·대체를 하지 않음 |

- 위 연결은 기준·방법을 읽거나 확인한 도구를 적용하는 계약이다. 독립 검수자·별도 세션의 실행을 자동으로 뜻하지 않는다.
- 적용 기준이 독립 검수를 요구하면 실제 검수자·대상·회신 증거를 확인한다. 동일 작성자의 대조나 대기 호출만으로 독립 검수 완료로 판정하지 않는다.

## 결과와 완료 판단

### 항목별 판정

- 판정 이름과 도구 오류·증거 부족 처리는 진입점 SKILL.md의 공통 판정 기준을 따른다.


- 정적 문서 판정과 실제 동작 판정은 분리한다. 정적 통과를 모델 행동·native 실행 통과로 합치지 않는다.
- 감사 범위의 항목을 모두 분류했는지와 대상이 실제로 요구를 충족하는지를 구분한다. 보고서를 작성했다는 이유만으로 대상을 적합으로 결론내리지 않는다.
- 필요한 증거가 남아 있으면 확인 범위와 공백을 명시한다. 미확인·미실행·미지원을 통과 수에 합치지 않는다.
- 전체 적합 결론을 제시한다면 근거가 충족된 대상·revision·제품·검사 범위에 한정한다. 개별 skill 결과를 kit 전체의 적합으로 확대하지 않는다.

## 출력 형식

- 공통 완료 보고에 아래 감사 결과를 연결한다.

| 항목 | 보고할 내용 |
| --- | --- |
| 대상·범위 | 실제 파일·revision·제품·설정·검사한 범위와 제외 범위 |
| 적용 기준 | 요구·작성 기준의 위치, 이번에 확인한 버전 |
| 판정 | 검사 항목별 상태와 근거. 미확인·미실행·미지원 포함 |
| 발견 사항 | 기준·관측 증거·불일치·영향·보완 제안. 사실과 추론 구분 |
| 시험·검수 방식 | 사용한 도구, 정적/실행/모델 시험, 동일 작성자/독립 검수 여부 |
| 남은 작업 | 추가 증거·시험·결정이 필요한 부분과 담당 범위 |

- 상세 로그·원문 증거와 docs의 검증 요약은 공통 기록 기준에 따라 구분한다. 요약에 없는 증거를 확인했다고 쓰지 않는다.
- 보완 제안은 수정 실행과 구분한다. 이후 수정이 승인돼 수행되면 변경된 항목과 의존 검증의 재판정 결과를 연결한다.
