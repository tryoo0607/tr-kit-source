# 변경 전후 구성 도표

## 목적과 역할 경계

- 적용 여부는 진입점 SKILL.md의 '조건부 공통 절차'에서 정한다. 이 파일에서는 발동 조건을 별도로 변경하지 않는다.

## 수행 방법과 절차

- 작성·수정에서는 실행 전에 예정 구성을 보여주고, 변경 후 실제 구성을 계획과 대조한다.
- 감사에서는 구성 설명과 실제 배치·연결을 대조한다.
- 구성이 바뀌지 않는 변경에서는 역할·연결이 동일하다고 밝힌다. 전체 도표를 불필요하게 반복하지 않는다.

### 표시할 내용

- 터미널에서 읽을 수 있는 도표를 제공한다.
- 변경 부분만 고립시키지 않고 그것이 연결되는 기존 구성을 함께 표시한다.

### 파일 구조와 읽기·실행 흐름 분리

- 구성의 배치와 연결을 설명할 때 다음 두 도표를 구분해서 제공한다. 한 도표의 계층에 파일 포함 관계·참조 관계·처리 결과를 섞지 않는다.
  - 파일 구조: 디렉토리와 그 안의 실제 파일을 트리로 표시한다. 예정 파일은 예정 상태를 명시한다.
  - 읽기·실행 흐름: 요청에서 자료 선택·지침 읽기·실제 실행·판정·보고로 이어지는 관계를 표시한다.
- 파일 트리의 자식은 해당 디렉토리에 포함된 파일·디렉토리만 의미한다.
  - 다른 위치의 참조 파일을 읽는다는 이유로 하위 파일처럼 배치하지 않는다.
  - 감사 결과·보고·판정 같은 행위를 파일·디렉토리처럼 넣지 않는다.
  - 결과가 실제 파일로 저장되는 경우에만 확인한 저장 경로를 파일 구조에 표시한다. 새 파일 생성이 합의되지 않았다면 결과라는 이름의 파일을 임의로 추가하지 않는다.
- 흐름 도표에는 관계의 종류와 조건을 명시한다.
  - 참조·읽기: 수행자가 어떤 지침을 읽는가
  - 실행·호출: 수행자가 어떤 도구·프로세스·세션을 실제 실행하는가
  - 판정·보고: 확인한 증거로 무엇을 판단하고 누구에게 보고하는가
  - 조건부 관계: 어떤 조건에서 해당 단계로 진입하는가
- 먼저 설명 대상의 범위를 밝힌다. 완성된 구성요소의 runtime 흐름과, 그것을 작성·감사하는 도구의 작업 절차를 섞지 않는다.
  - 실행 코드가 대상이면 실제 이벤트·입력에서 adapter·공통 판단·결과 처리로 이어지는 흐름을 보여준다.
  - agent 지침과 reference가 대상의 실제 구성에 포함되면 누가 어떤 지침을 읽고 수행하는지도 표시한다.
  - 대상 runtime에 존재하지 않는 저작 도구의 지침 읽기를 runtime 단계로 추가하지 않는다. 저작 과정 설명이 별도로 필요하면 명확히 이름 붙인 별도 흐름으로 보여준다.
- reference 파일이 스스로 작업을 실행하거나 결과를 반환하는 주체처럼 표현하지 않는다. 별도 프로세스·세션이 실제 존재하면 그 실행 주체와 지침 참조를 구분한다.

| 항목 | 확인할 내용 |
| --- | --- |
| 배치·변화 | 어떤 영역에 어떤 skill·hook·script·reference가 추가·변경·제거되는가 |
| 역할 | 새 구성과 기존 구성의 책임이 어떻게 나뉘는가 |
| 연결 | 무엇이 무엇을 참조·호출·실행하는가. 지침 읽기와 실제 실행은 구분 |
| 발동·적용 범위 | 어떤 요청·이벤트에서 작동하고 어느 범위에 영향을 주는가 |
| 기존 대비 | 기존 연결을 교체하는지, 새 연결을 추가하는지, 함께 동작하는지 |

- 파일 구조와 흐름 도표를 나란히 대조해, 흐름에서 참조·실행하는 대상의 실제 위치와 관계가 일치하는지 확인한다.
- 예정 연결을 실제 작동하는 연결처럼 표시하지 않는다.

## 결과와 완료 판단

- 변경 후에는 계획과 실제 결과의 차이·미구현·미결을 표시한다.
- 감사에서는 설명과 실제 구성의 불일치 및 미확인 연결을 구분한다.
- 도표 제공을 모든 명령의 재승인 절차로 바꾸지 않는다. 기존 승인 범위는 유지한다.
