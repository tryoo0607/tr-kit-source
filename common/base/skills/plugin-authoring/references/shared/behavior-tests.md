# 새 세션·압축·제품별 실제 행동 시험

## 목적과 역할 경계

- 적용 여부와 압축·재개 시험의 필요성은 진입점 SKILL.md의 '조건부 공통 절차'에서 판단한다. 이 파일은 선택된 시험의 상세 방법을 소유하며 발동 조건을 별도로 변경하지 않는다.
- 조건에 해당하는 시험을 편의를 이유로 생략하거나 기초 형식 검사로 대체하지 않는다.

## 수행 방법과 절차

### 사례와 범위 설계

- 변경 영향에 맞춰 다음 사례와 반복 범위를 정한다.
  - 의도한 대상 요청
  - 가까운 비대상 요청
  - 의미·범위가 모호한 요청
  - 대상·입력·환경 부재와 실패 상황
- 단일 성공으로 전체 사례의 성공을 일반화하지 않는다.
- Codex·Claude의 검사 항목은 공통으로 관리한다.
- 실행·관측 방법과 제품별 전제는 각각 확인한다.

### 새 세션 시험

- 주변 대화와 작성자의 설명을 모르는 새 세션에서 실제 요청을 수행하게 한다.
- 요청·검사할 지침·필요한 원자료와 허용된 작업 범위를 제공한다.
- 평가자에게 의도한 답이나 기존 결론을 미리 알려주지 않는다.
- 실제 행동·산출물을 요구와 대조한다.
- 지침을 올바르게 설명했다는 결과만으로 실제 준수 성공을 판정하지 않는다.

### 압축·재개 시험

- 실제 컨텍스트 압축·재개 후 보존 대상 요구·금지·용어·승인 범위가 유지되는지 확인한다.
- 새 세션 시험, 실제 압축·재개 시험, 합성 요약 시험을 구분한다.
- 한 종류의 시험을 다른 시험의 성공으로 대신하지 않는다.
- 시험 과정에서 원래 승인 범위를 확대하거나 평가 대상의 실제 사용자 세션을 임의로 중단하지 않는다.

## 결과와 완료 판단

- 다음 검증 층위를 구분한다.
  - 공통 판단·형식·참조 링크
  - script 직접 실행
  - 제품 native 이벤트와 실제 hook 실행
  - 모델의 선택·해석·행동·산출물
- 한 제품 또는 한 단계의 통과를 다른 제품·단계로 확대하지 않는다.
- 시험한 revision·제품·버전·설정·사례·실제 결과를 남긴다.
- 실행 권한·환경·필수 자료가 없으면 해당 항목을 미실행·미지원·미확인으로 구분해 남긴다.
- 통과·실패·미실행·미지원과 제한 범위를 분리해 보고한다.
