# plugin-authoring

## 목적과 역할 경계

- kit·skill·hook의 작성·수정과 개별·전체 감사를 담당한다.
  - 작성·수정: 승인된 대상을 변경하고 관련 검증·감사를 수행한다.
  - 감사: 요구와 기준을 실제 구성·동작에 대조해 발견 사항을 보고한다. 감사 요청을 자동 수정 승인으로 취급하지 않는다.
- 설치·활성화·배포는 이 skill의 직접 실행 역할이 아니다.
  - 해당 절차·구성·시험과 결과는 작성·감사의 대상이다.
  - 실제 실행이 필요하면 담당 기능과 승인 범위를 확인해 연결한다.
- 이 본문의 공통 기준은 이 skill을 사용하는 동안 적용한다. 모든 세션에 상시 주입되는 전역 지침이라는 뜻은 아니다.
- 조건부 절차는 아래 적용 조건을 충족할 때 수행한다. reference로 분리됐다는 이유로 필수 절차를 생략하지 않는다.

## 입력과 전제

- 사용자 입력과 명시한 요구 자료에서 작업 대상·허용/제외 범위를 먼저 확인한다. 자료 경로가 제공됐으면 해당 요구를 읽기 전에 편의상 실호스트 설정·profile 탐색부터 시작하지 않는다.
- 지정된 fixture·임시 저장소 안의 작성·설명으로 충분한 작업은 그 범위에서 수행한다. 경로·자료·공유 정책 판단에 실제로 필요하지 않은 호스트 설정 조회를 추가하지 않는다.
- 사용자가 조회를 제외한 원문 설정·자료는 읽지 않는다. 필수 호스트 역할 가드 등 안전 정책은 유지하며, 실제 필수 조건과 요청 범위가 충돌하면 영향받는 부분을 보류하고 확인한다. 안전 검사를 끄거나 우회하는 근거로 사용하지 않는다.
- 현재 작업에 필요한 범위에서 다음을 확인한다.
  - 요청 대상·동작·실제 작업 위치와 적용 제품
  - 사용자 요구·금지·결정·미결, 원문 근거와 적용 범위
  - 보존할 행동·제약, 변경할 부분, 이번 작업 밖의 부분
  - 기존 구성·외부 기능과 실제 검증 증거
- 이미 확인한 자료와 승인은 재사용한다. 모든 요청에 전체 자료 재조사를 강제하지 않는다.
- 명시적 사용자 요구, 채택한 결정, 에이전트 제안과 미결을 구분한다.
  - 기존 구현이나 문서의 존재를 사용자 승인 증거로 간주하지 않는다.
  - 지침·요구가 현재 작업에만 적용되는지, 프로젝트 또는 이후 세션에도 보존할 대상인지 확인한다.
  - 의미를 바꾸는 모호함을 임의 해석하지 않는다.
- 중요한 의미·권한·범위 차이가 있으면 영향을 설명하고 확인한다.
  - 영향받는 부분만 보류한다.
  - 독립적으로 진행 가능한 기존 승인 범위의 작업은 계속한다.

## 수행 방법과 절차

### 공통 판단과 진행

- 기존 외부 저작·감사 기능과 전문 도구의 재사용 가능성을 먼저 확인한다.
  - 선택한 기능의 공식 설치본, 실제 식별자·버전·사용 가능 여부를 확인한다.
  - 선택 단계의 사용 가능 여부는 대상 지침의 존재·접근 가능·사용 허용으로 판정한다. 대상 본문을 미리 전부 읽거나 도구를 실행해 선택 여부를 판정하지 않는다. 실제 동작 검증과 구분한다.
  - 전달할 입력과 필요한 결과를 확인하고 대상 지침으로 진입해 적용한다.
  - 선택·적용한 절차·도구와 미충족 부분을 밝힌다.
  - 이름 언급이나 validator 실행만으로 저작 절차 전체를 적용했다고 판단하지 않는다.
- 외부 원문을 kit 구성요소로 복제·동봉하거나 원문·사본을 변형하지 않는다.
  - 공식 설치본 연결이 불가능하면 차이·미지원·미결을 보고한다.
  - 연결 작성 승인을 설치·업데이트 승인으로 확대하지 않는다.
- 기준과 구성의 책임을 구분한다.
  - 같은 규칙의 본문은 한 곳에서 관리하고 필요한 위치에서 연결한다.
  - 공통 의미·판단과 제품별 이벤트·도구·입출력 차이를 분리한다.
  - 적용 범위를 파일 위치나 hook 등록 위치만으로 단정하지 않는다.
- 작성·수정 요청에서는 다음을 수행한다.
  - 원래 요구와 실제 변경을 대조해 누락·범위 밖 추가·의미 변경을 확인한다.
  - 대상별 감사 기준을 적용한다. 승인 범위 안의 발견 사항을 보완하고 영향받는 검증을 다시 수행한다.
  - 승인 밖 추가 변경은 실행 전에 확인한다.
- 감사 요청에서는 발견 사항·근거·미결을 보고하고 승인되지 않은 수정을 실행하지 않는다.
- 기존 전문 도구와 외부 절차가 소유한 검사를 복제하지 않는다.
- 검사 자체의 오류, 정책 위반, 환경 부재를 구분한다.
  - 통과시키기 위해 기준을 낮추거나 다른 검사로 조용히 대체하지 않는다.

## 요청별 분기

- 요청을 대상·동작별로 구분하고 각 요청에서 아래 대안 행을 위에서부터 평가해 처음 일치하는 하나를 선택한다.
- 별도 대상·동작이 함께 요청되면 각각 선택한다. 대상별 대안 선택과 아래 조건부 공통 절차의 추가 적용을 혼동하지 않는다.
- 이 본문에 적힌 reference 경로는 이 SKILL.md가 있는 디렉토리를 기준으로 해석한다. reference 내부의 상대경로는 해당 reference 파일 위치를 기준으로 해석한다.
- 여러 대상이면 필요한 기준을 순차 적용한다.
- 개별 작성·수정에 전체 감사를 자동 강제하지 않는다.
- 이미 적용한 공통 지침과 수행 결과는 재사용하며 같은 작업을 중복 수행하지 않는다.

| skill 감사 | 해당 대상·동작이 요청에 포함됨 | [skill 감사](references/skill/audit.md) |

- 선택한 필수 reference의 존재·접근 가능 여부를 확인한다.
  - 필요한 기준이 없거나 접근할 수 없으면 그 기준에 의존하는 절차를 보류하고 미완료를 밝힌다.
  - 기준을 추측하거나 적용했다고 보고하지 않는다.
  - 독립적으로 가능한 승인 범위의 작업은 계속한다.

### 조건부 공통 절차

- 대상별 reference와 별개로 아래 조건을 대조한다.
- 조건에 해당하면 지정 자료를 해당 시점에 읽고 수행한다.
- 여러 조건이 성립하면 각각 적용하되 같은 자료·유효한 결과는 재사용한다.

| 적용 조건 | 읽을 reference | 수행 시점 |
| --- | --- | --- |
| 구성에 영향을 주는 작성·수정, 또는 구성 설명과 실제 연결을 대조하는 감사 | [구성 도표](references/shared/structure-view.md) | 변경 전 예정 구성, 변경 후 실제 구성. 감사에서는 설명과 실제 구성을 대조할 때 |
| 본문·reference 선택·읽기 범위·호출 흐름의 작성·변경 또는 해당 흐름 감사 | [읽기·호출 흐름 검사](references/shared/reading-flow.md) | 변경 전후 대조 또는 흐름 감사 시 |
| 지침 신규 작성, 의미·발동·선택·연결 변경 또는 관련 행동 검증 | [실제 행동 시험](references/shared/behavior-tests.md) | 검증 사례 설계 시 읽고, 결과 판정 전에 시험·미실행 상태 확인 |
| 보존 대상 요구·금지·용어·승인 범위의 전달·유지 방식을 작성·변경하거나 그 보존을 검증 | [실제 행동 시험](references/shared/behavior-tests.md)의 '사례와 범위 설계'·'압축·재개 시험'·'결과와 완료 판단' | 공통 사례·증거 기준을 포함해 읽고 새 세션 시험과 구분해 실제 압축·재개 검증 시 |

## 결과와 완료 판단

### 공통 판정

| 상태 | 판정 근거 |
| --- | --- |
| 통과 | 적용 기준을 확인하고 해당 관측 범위에서 충족하는 증거가 있음 |
| 위반 확인 | 적용 기준과 실제 파일·관측 결과가 어긋남을 확인 |
| 미확인 | 필요한 기준·원문·대상 상태·증거가 부족해 충족 여부를 판단할 수 없음 |
| 미실행 | 필요한 실행 검사를 수행하지 않음 |
| 미지원 | 해당 제품·환경에서 필요한 검사를 지원하지 않는 근거가 있음 |
| 비대상 | 적용 조건이 성립하지 않음. 제외 근거를 명시 |

- 검사 도구 오류는 위반 발견과 별도로 기록한다. 오류 때문에 판정할 수 없는 항목은 미확인·미실행으로 남긴다.

### 기록과 보고

- 현재 kit에서는 다음 위치를 사용한다.
  - docs/requirements.md: 요구·근거·상태·반영 위치
  - docs/architecture.md: 실제 구조·역할·연결
  - docs/decisions/: 결정 이유·변경 이력
  - docs/verification.md: 대상·버전·검증 범위·결과·미검증·한계
- 상세 작성·감사 기준 본문을 docs에도 복제하지 않는다.
- 상세 로그·원본 출력·민감한 실행 증거는 로컬 작업 기록과 구분한다.
- 다른 프로젝트를 다룬다는 이유로 위 문서 구성을 자동 생성하거나 기존 정본을 복제하지 않는다.
- 기존 증거를 재사용하기 전에 대상 revision·제품·설정·시험 범위와 이후 변경의 영향을 확인한다.
  - 현재 결과로 유효한지 확인하지 못한 증거는 과거 결과로 구분한다.
- 완료 보고에는 다음을 포함한다.
  - 변경 요지와 계획과의 차이, 구성 도표의 적용 조건에 해당하면 실제 구성 도표
  - 요구별 반영 위치 또는 감사 발견 사항
  - 적용한 외부 기능·기준과 실제 수행한 검증·감사
  - 통과·실패·미실행·미지원, 남은 미결과 한계
- 구현·기록·시험·감사의 완료 상태를 분리한다.
- 접근·적용하지 못한 기준이나 실행하지 않은 시험을 완료로 보고하지 않는다.
