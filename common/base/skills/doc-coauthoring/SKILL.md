# doc-coauthoring

## 목적과 역할 경계

- 기존 업무 skill이 PRD·설계 결정 등의 분석·산출 형식·검증을 소유하면 그 담당을 유지하고 필요한 공동 작성 과정만 연결한다. 별도 담당이 없는 문서 공동 작성은 이 연결이 맡는다.
- README는 github-readme-generator, 자료 보관·검색은 document, 계정 전용 게시는 artifact-publish의 별도 업무다. 문서 형식만 보고 모든 요청을 여기로 모으지 않는다.

## 입력과 전제

- 기존 정본·사용자 직접 수정, 독자·문서 목적·설명 깊이·형식, 실제 근거·중요 요구/금지·미결과 승인 범위를 재사용한다. 기존 초안으로 미확인 요구를 대체하지 않는다.
- 공식 설치와 개별 사용 조건 확인 근거가 필요하다. 과거 고정 revision에서 이 skill의 개별 조건은 미확인이었으므로 저장소 전체 조건을 임의로 적용하거나 wrapping만으로 허용됐다고 단정하지 않는다. 확인이 없으면 해당 외부 수행을 보류한다.

## 수행 방법과 절차

1. 아래 공통 연결로 공식 doc-coauthoring SKILL.md에 진입하고 실제 요청에 맞는 원본의 절차를 적용한다. 역할·입력 전달은 원문 append·사본 치환과 다르다.
2. 원문이 요구하는 workflow 선택·질문·독자 검토·단계 전환을 임의로 삭제하지 않는다. 이미 제공한 답·선택과 사용자가 요청한 생략을 전달하되 원문이 실제로 지원하는 경로인지 확인한다. 충돌이 남으면 해당 동작만 보류·보고하고 가능한 입력 정리·자료 확인은 계속한다. 원문을 고친 뒤 같은 기능이라고 부르지 않는다.
3. 요청한 정본과 실제 사용자 편집을 보존한다. 원본의 artifact 생성·별도 파일/외부 전달이 이번 저장·공유 승인과 충돌하면 자동 실행하지 않는다. 로컬 초안 요청은 게시 승인이 아니다.
4. 요청된 내용·형식·근거와 결과를 대조한다. 독자 이해도·모호함 검사는 사실 검증을 대체하지 않는다. 실제 독립 검수의 입력·수행·회신이 없으면 통과로 보고하지 않는다.
