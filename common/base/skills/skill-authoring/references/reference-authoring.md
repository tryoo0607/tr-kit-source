# Reference 작성

reference를 추가, 수정, 검토하거나 본문과의 분리 구조를 검토할 때 사용한다. 공통 목차, 항목 확장과 분량 조정은 [자체 저작 기준](local-rules.md)을 적용한다. 일반 자료 배치는 연결된 OpenAI 원본을 따르며 여기서 재정의하지 않는다.

## 수행 방법과 절차

1. 첫머리에 대상, 사용 조건을 밝히고 해당 분기의 상세만 담는다.
2. 이 파일을 읽을 조건, 얻을 내용, 필요한 절과 상대경로를 직접 연결한다. 절을 지정하면 제목과 링크가 유효하고 공통 제약을 빠뜨리지 않는지 확인한다. 일괄 로드와 깊은 참조 사슬을 피한다.
3. 공통 판단은 본문에, 분기 상세는 reference에 한 번만 둔다. 본문과 선택한 자료만으로 요청을 수행할 수 있는지 확인한다.
   선택용 식별자와 조건은 본문의 분기표, 상세 호출 계약은 실제 사용하는 reference의 연계와 의존에 둔다. 기본 수행 reference에는 외부 대상 식별이나 fallback 선택을 복제하지 않는다.
4. 문서 작성과 관리 지침은 아래 두 묶음으로 구분한다. 다른 종류의 skill에 이 분류를 일괄 강제하지 않는다. 필요한 지침만 파일로 만들고 빈 분류 폴더나 지침은 만들지 않는다.

| 묶음 | 배치 기준 | 문서 skill의 위치 |
|---|---|---|
| 문서 종류별 작성과 관리 규칙 | 작업 기록, 인계, 지식 등 종류별 목적, 필수 정보, 연결, 갱신, 조회 규칙. 도구나 형식이 바뀌어도 유지할 내용 | references/types/ |
| 저장과 표현 구현 | 특정 저장 수단, 형식, 도구에 따른 경로, 메타데이터, 문법, 실행 절차 | references/implementations/ |

먼저 문서 종류에 맞는 지침을 선택하고, 실제 구현에 필요한 자료만 추가로 연결한다. 같은 규칙을 두 묶음에 복제하지 않는다. 종류별 지침에 작성법과 관리 방식을 함께 담으며, 도구와 형식도 무조건 쪼개지 않는다. 여러 문서 종류에서 독립적으로 재사용할 필요가 확인되면 분리를 검토한다.

## 결과와 완료 판단

읽을 조건과 대상 범위가 일치하고 참조 경로가 유효한지 확인한다. 공통 항목 준수, 본문과의 중복, 수행에 필요한 내용의 누락을 점검한다. 검토 이력, 미결 토론은 실행 지침 밖에 둔다.

LLM Wiki는 독립 문서 종류가 아니라 지식 문서의 관리 방식으로 다룬다. 근거 보존, 지식 종합, 문서 연결, 충돌 처리는 지식 종류의 지침에 둔다. 로컬 폴더 구조, Markdown 메타데이터와 링크 문법, 검색 도구 실행법은 저장과 표현 구현에 둔다. 로컬 Markdown과 Confluence의 구현은 필요한 것만 선택해 읽는다.
