# 자체 저작 기준

OpenAI 원본에 추가하는 로컬 규칙이다. wrapper 자신과 생성/수정하는 SKILL.md 및 reference에 적용한다. 일반 저작 절차와 공통 파일 규격은 원본을 따르고 여기서 복제하지 않는다.

## 입력과 전제

최신 합의, 대체된 결정과 미채택 제안을 구분한다. 예시 이름이나 경로를 필수 규격으로 굳히지 않는다. 실제 절차와 자료를 근거로 삼고 추론을 사실이나 사용자 동의로 기록하지 않는다.

공통 작업 원칙의 외부 재사용 우선을 저작 대상 선정에도 적용한다. 기존 연결과 확인한 후보부터 대조하고 요구가 달라졌거나 자료가 부족할 때만 외부 후보를 추가 조사한다. 후보의 요구 충족 범위, 원본/버전, 실행 환경과 의존성, 기존 역할과 충돌, 유지 비용을 비교한다. 재사용할 기능과 자체로 남길 차이, 대체하지 못하는 이유를 구분한 뒤 작성 범위를 정한다. 이미 선정된 외부 기능의 설치와 배포 포함은 별도 계약과 승인 범위로 판단한다.

## 수행 방법과 절차

### 공통 목차

필요한 항목만 아래 이름과 순서로 사용하고 빈 섹션은 만들지 않는다. 소제목은 항목 내부를 나누는 데 사용하며 임의의 새 공통 항목을 만드는 우회로 쓰지 않는다. 비교/매핑은 표, 실행 순서는 수행 방법과 절차의 번호 목록, 설명은 문단으로 쓴다.

| 항목 | 포함할 조건 |
|---|---|
| 목적과 역할 경계 | description만으로 작업 범위나 다른 skill과의 구분이 부족함 |
| 입력과 전제 | 대상, 환경, 자료가 수행에 필요함 |
| 수행 방법과 절차 | 모델에게 필요한 고유 방법, 순서, 도구 사용법이 있음 |
| 요청별 분기 | 요청별 절차나 읽을 자료가 다름 |
| 연계와 의존 | 다른 skill/도구의 활용 조건과 필요한 결과를 밝혀야 함 |
| 제약과 주의점 | 빠뜨리면 잘못 처리하기 쉬운 규칙이나 함정이 있음 |
| 분량과 읽기 범위 | 산출 분량이나 실행 시 조회 범위를 정할 필요가 있음 |
| 결과와 완료 판단 | 제공/확인할 결과와 완료 조건이 필요함 |
| 출력 형식 | 형식이 결과 사용 계약의 일부임 |
| 실패와 복구 | 중단, 재시도, 대체를 구분해야 함 |
| 예시 | 판단이나 형식의 모호함을 줄일 수 있음 |

공통 항목을 추가하려면 이름, 의미, 사용 조건, 이유, 기존 항목과의 차이 및 순서를 제안하고 사용자 채택 후 이 표를 갱신한다. 예시 작성 허가는 항목 채택이 아니다. 다른 문서를 일괄 개편하지 않고 미채택 제안은 작업 기록에 둔다.

### 연계와 wrapping

같은 업무 판단이나 도구 선정 정책의 정본을 한곳에 둔다. 요청을 판별하는 본문, 실제 연결 계약과 도구 조작 상세를 구분하되 이 구분만을 위해 파일이나 skill을 늘리지 않는다. skill은 업무 지침이고 실제 읽기, 판단과 실행 주체는 에이전트다. 도구 이름 언급이나 화살표만으로 연결을 대신하지 않는다.

요청별 분기는 `요청 | 선택 조건 | 읽을 reference` 표로 작성한다. 같은 요청의 행은 위에서부터 평가해 처음 일치하는 하나만 읽는다. 별도 추가 요청이 함께 있으면 각 요청별로 선택한다. 대안이 없는 분기는 해당 요청 포함 여부를 조건으로 쓴다. 모든 경로에 필요한 자체 제약은 공통 조회로 별도 명시한다.

외부 또는 내부 skill의 사용 가능 여부로 분기하면 본문에는 대상 식별자와 확인 위치, 선택 조건만 둔다. 사용 가능은 대상 SKILL.md의 존재, 접근 가능, 사용 허용이며 대상 본문을 읽거나 실행해 판정하지 않는다. 미확인 조건은 필요한 범위에서 확인하고 금지된 경로는 조회하지 않는다. `그 외`는 같은 요청의 마지막 행에만 두고 앞선 조건이 성립하지 않을 때 선택한다. 선택하지 않은 reference는 읽지 않는다. 실행 중 실패는 자동 fallback 조건이 아니며 기존 변경과 원인을 확인한다.

연결 설명은 사용하는 쪽의 연계와 의존에 모은다. 대상, 활용 조건, 필요한 결과, 필수/선택 여부와 부재 시 동작을 밝힌다. 필수 대상이 없으면 해당 분기를 보류하고 선택 대상이면 구체적인 대체 경로를 둔다. 이름 언급을 실행 연결로 취급하지 않으며 이미 충분한 결과를 받았다면 다시 로드하지 않는다.

내부와 외부 skill에 같은 연결 규칙을 적용한다. 대상은 현재 환경에서 확인한 skill 식별자로 명시하고 요청 동작, 필요한 입력과 결과를 밝힌다. 대상의 SKILL.md에서 해당 요청의 분기와 공통 제약을 확인한 뒤 지정된 자료를 적용한다. 호출자가 대상 skill의 내부 reference 경로를 고정하거나 본문 진입을 생략하지 않는다. 외부 대상에 분기표가 없으면 확인한 원본 절차를 따르며 필요한 요청 변환은 adapter가 소유한다. 지침 적용을 별도 실행, 격리 또는 자동 반환으로 가정하지 않는다.

SKILL.md는 요청을 판별하고 필요한 reference를 안내한다. 연결 계약은 실제 호출을 수행하는 reference의 `연계와 의존`에 한 번만 둔다. 수행 단계는 그 항목을 지목해 적용 시점을 밝히고 본문이나 다른 reference에 계약을 복사하지 않는다. 여러 요청이 같은 호출 계약을 사용하면 그 계약을 소유한 reference로 안내한다. 사용하지 않는 외부 연결과 대체 절차를 기본 로드하지 않는다. 대상 식별, 필수 지침이나 분기가 확인되지 않으면 해당 실행을 보류하고 알리며 임의의 skill로 대체하지 않는다.

외부 wrapping은 원본 식별자/검증 버전, 연결 방법, 입력/결과, 자체 차이, 맡을 요청과 원본 부재 시 동작을 남긴다. 원본 절차를 복제하지 않고 상대경로, 지원 파일과 제품별 의존을 보존한다. 원본을 제외해 필요한 호출까지 막지 않는다. 실제 설치/제외 적용은 kit의 책임이다.

CLI 조작은 명령, 실행 위치, 필요한 입력과 결과 확인을 지시하면 된다. CLI를 쓴다는 이유로 연결 관리 skill이나 새 wrapper를 경유하지 않는다. script는 고정해야 하는 반복 조작에만 사용하고 단순 지침 연결을 실행 프로그램으로 표현하지 않는다. 여러 지침이 같은 작업 공간 생성이나 기록 갱신을 요구하면 실제 수행 담당을 하나로 정하고 확인된 결과를 재사용한다.

### 공통과 제품별 차이

metadata의 tr-role은 자체 정책/업무 판단이면 policy, 외부 조작 진입점이면 external-wrapper로 표시할 수 있다. 분류는 자동 호출이나 권한 변경 기능이 아니며 실제 소유 책임은 본문에 명시한다.

common/base와 adapters/<product>는 같은 책임을 같은 상대 계층으로 대응시킨다. 공통 업무 판단과 완료 기준은 base, 호스트 호출과 경로 차이는 대응 adapter가 소유한다. 차이가 없는 파일을 세 벌 만들거나 adapter에 완성된 공통 본문 사본을 두지 않는다. 이 원칙이 특정 Markdown 파일을 필수로 만들거나 모든 동명 파일의 자동 병합을 뜻하지 않는다.

제품별 표현과 외부 skill 경로 변환은 확인된 조립 계약으로 처리한다. 외부 원본과 revision은 의존성 선언을 정본으로 하고 업무 지침에는 runtime 사용 조건과 연결 계약을 둔다. 공통 본문에서 이미 확인한 CLI를 직접 사용하는 경우 제품 차이가 없으면 adapter를 만들지 않는다. 일반 업무 중에는 조립이나 연결 관리를 위한 skill을 거치지 않는다.

### 분량과 조회 설계

요청별 최초 필수 자료/절과 조건부 추가 조회를 구분한다. 오류나 조회에서 변경으로의 전환은 행동 전에 관련 지침을 추가한다. 같은 파일의 일부로 충분하면 절을 지정하고 파일부터 늘리지 않는다. 실행 중 이 저작 기준을 다시 읽어야만 작동하는 skill을 만들지 않는다.

전체 지침과 대표 요청의 읽을 절 합계를 전후 측정한다. 외부 원본, 템플릿, 작업 데이터와 환경 주입의 포함 범위를 밝히고 문자 수를 토큰이나 비용 절감률로 보고하지 않는다. 매번 읽는 자료를 reference로 옮긴 것을 절감으로 취급하지 않는다.

같은 판단과 일반론을 줄이되 합의, 예외, 역할 경계, 실패 대응과 참조는 유지한다. 특정 줄/토큰 수를 목표로 강제하지 않는다. 한 차례 정리 후 추가 축약은 실제 실패나 재조회 부담을 근거로 한다. 상위 지침 중복을 제거할 때는 실제 제공되는 환경인지 확인한다.

## 제약과 주의점

문서 본문, 제목, 표와 목록에 이모티콘, 가운데점, 장식용 화살표, 긴 대시와 꾸민 따옴표를 쓰지 않는다. 일반 Markdown 문법은 허용한다.

저작 권한은 설치, 배포, 외부 전송 허가가 아니다. 보류한 파일과 요청 밖 설정을 유지한다. 유효한 방법이 여럿이면 재량을 남기고 미구현 도구나 연결을 작동하는 것으로 기술하지 않는다.

## 결과와 완료 판단

대표 요청, 가까운 비대상 요청, 필요한 실패 사례를 대조한다. 공통 목차와 표기, 연계, 필수 제약, 완료 기준과 참조 연결을 확인한다. validator가 확인한 범위를 넘어 품질이나 자동 선택 성공을 주장하지 않는다. 검토는 차이와 보완점을 전달하고, 작성/수정은 발견한 문제를 고친 뒤 관련 검사를 다시 수행한다.

각 대표 요청에서 실제 읽을 지침, 사용할 도구, 전달할 입력과 결과를 순서대로 따라간다. 중복된 수행과 담당 없는 단계를 확인하고 동일 계층의 adapter에서 필요한 차이를 해결할 수 있는지 대조한다. source 내부 링크, 조립 후에만 생기는 외부 skill 링크, 복사 후 유효해지는 템플릿 링크를 구분해 각각 실제 사용 위치에서 검사한다.
