# document

## 목적과 역할 경계

작업 상태, 작업 경험, 재사용 지식을 연결한다. BMAD의 계획과 검증, Claude-Mem의 관측과 검색, LLM Wiki의 자료 수집과 지식 정리를 재사용하고 자체 기록 스키마나 별도 진행 상태를 만들지 않는다.

현재 작업 상태는 해당 작업의 정본에서 확인한다. 경험 검색 결과를 최신 요구나 승인으로 취급하지 않으며, Wiki 설명을 고쳤다는 이유로 작업 계획을 바꾸지 않는다. 기존 state/exec 등의 기록은 자동 이관하거나 삭제하지 않는다.

## 입력과 전제

요청 목적, 대상 작업이나 주제, 기존 기록 위치와 보관 범위를 확인한다. 위치나 공유 범위가 불명확하거나 바뀔 때만 [위치와 보관 정책](references/implementations/local-markdown.md)을 읽는다.

외부 도구는 실제 사용 가능한 식별자와 지원 기능을 확인한다. 아래 reference는 연결 지침이며 설치나 자동 연동 구현이 아니다. 조회만 요청받으면 저장하지 않는다.

## 요청별 분기

각 요청은 위에서부터 처음 일치하는 행을 선택한다. 별도 요청이 함께 있으면 해당 분기도 적용한다. 선택한 reference만 읽고, 쓰기나 다른 목적이 추가되면 행동 전에 그 분기를 읽는다.

| 요청 | 선택 조건 | 읽을 reference |
|---|---|---|
| 인계받은 작업 재개, 내부 인계 준비와 갱신 | 해당 요청이 포함됨 | [handoff.md](references/types/handoff.md) |
| 작업 목록과 상태, 작업 경험 조회, 기존 작업 기록 갱신 | 해당 요청이 포함됨 | [history.md](references/types/history.md) |
| 공부 메모와 조사 자료 저장, 지식 정리와 조회, 갱신과 점검 | 해당 요청이 포함됨 | [knowledge.md](references/types/knowledge.md) |
| 프로젝트 안내나 세션 분석 조회, 작성과 갱신 | 해당 요청이 포함됨 | [context.md](references/types/context.md) |

종류별 reference는 연결 판단만 소유한다. 외부 대상에 실제 요청할 때는 [도구 연결](references/implementations/tool-connections.md)의 해당 절과 공통 입력/실패 기준을 추가 적용한다. 설치, 버전 변경, hook 등록은 제품 설치 관리의 범위이며 이 skill이 수행하지 않는다.

## 제약과 주의점

- 사용자 요구와 승인, 관측 사실, 해석과 미확인을 구분한다. 원문을 읽지 못했으면 확인한 것처럼 정리하지 않는다.
- 소속과 주제가 같아도 공유 권한은 별도다. 내부 자료를 개인 Wiki나 다른 호스트로 자동 전달하지 않는다.
- 동일 내용을 세 도구에 역복제하거나 전체 기록을 기본 로드하지 않는다. 조회한 근거의 식별자와 위치, 시점, 적용 범위를 보존하고 기존 정본을 연결한다.
- 자동 수집과 초기 주입은 별도 호스트 연결이다. 이 skill을 읽은 것만으로 수집되거나 다음 세션에 전달됐다고 보고하지 않는다.

## 결과와 완료 판단

조회는 근거와 확인 범위를, 변경은 실제 반영 위치와 미반영 내용을 전달한다. 저장 결과를 다시 조회하거나 도구의 확인 가능한 결과와 대조한다. 작업 기록 정리, 지식 반영, 인계 준비와 실제 작업 완료를 구분한다.
