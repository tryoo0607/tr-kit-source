# 참고 원본 보관과 활용

PDF·이미지·문서 같은 실제 원본을 보관·정리하거나 현재 작업에서 찾아 쓸 때 읽는다. 세션 정보 저장이나 작업 상태 관리는 이 분기의 대상이 아니다.

## 입력과 전제

원본 위치, 소속과 요청 동작을 확인한다. 기존 원본은 로컬 보존을 기본으로 하며 원격 보관은 선택한 대상만 별도로 다룬다. 소속·경로가 불명확하거나 바뀔 때는 [위치와 보관 정책](../implementations/local-markdown.md)을 적용한다. 이미 받은 소속/경로 결과는 재사용한다.

## 수행 방법과 절차

1. 기존 경로가 있으면 유지한다. 새 보관이 필요하면 확인된 소속의 assets 위치를 사용한다. 그룹 공통 자료와 repo별 자료를 구분하되 코드 폴더나 worktree마다 원본을 복제하지 않는다. repo 이름이나 그룹 표시 이름으로 소속을 추정하지 않는다.
2. 찾기 요청은 알려진 원본 위치 또는 아래 Wiki 연결에서 후보를 좁힌다. 등록되지 않은 파일은 확인된 보관 폴더에서 이름·유형으로 제한해 탐색한다. PDF 내용 검색은 텍스트 추출이 필요하며 일반 텍스트 검색만으로 내용을 확인했다고 하지 않는다.
3. 소수 파일은 일반 파일 도구로 처리한다. 반복 분류·중복 탐지가 필요하고 organize CLI가 사용 가능하면 아래 절을 적용한다. 원본 삭제·이동을 보관 요청에 자동 포함하지 않는다. 같은 이름의 파일은 내용/hash를 비교해 동일하면 재사용하고 다르면 둘 다 보존한 채 버전명 또는 목적지를 확정한다. skip만으로 갱신본 보관이 끝났다고 하지 않는다.
4. 내용 수집/지식화, 지속적인 목록 추적이 요청됐을 때만 아래 Wiki 연결을 적용한다. 모든 파일에 기록을 강제하지 않고 이미 있는 자료 기록을 재사용한다. 원본 경로, 소속과 필요한 설명을 전달하며 새 자체 카탈로그를 만들지 않는다.
5. 작업 활용은 후보의 실제 파일을 열어 필요한 범위와 출처를 작업 스킬에 전달한다. 전체 원본이나 Wiki를 세션에 상시 주입하지 않는다. 원본 이동 요청이면 기존 참조를 확인하고 접근 가능한 연결을 갱신한다. 자동 링크 갱신을 보장하지 않는다.
6. 선택 외부 보관은 원본·추출문·요약 각각의 범위와 목적지를 확인해 실제 Git/전송 도구로 처리한다. 경로 설정만으로 assets가 백업됐다고 하지 않는다. 회사 자료를 개인 Wiki나 원격에 자동 반영하지 않는다.

### organize 실행

검증 기준은 organize-tool 3.3.0이다. 공식 [설정](https://tfeldmann.github.io/organize/configuration/), [동작](https://tfeldmann.github.io/organize/actions/)과 설치 CLI 도움말을 사용한다. 별도 앱/MCP는 필요하지 않으며 설치는 이 절의 실행에 포함하지 않는다.

- `organize --version`과 실제 실행 경로를 확인하고 명시한 YAML과 작업 경로로 `organize check <config>`, `organize sim <config>`, 승인된 `organize run <config>`를 사용한다. shell/Python 실행 규칙은 sim에서도 부작용이 가능하므로 검토 없이 실행하지 않는다.
- 보관 규칙은 복사와 비파괴적 충돌 처리부터 선택한다. copy의 기본 rename_new는 재실행 중복 방지를 보장하지 않는다. skip은 기존 보관본과 다른 내용의 갱신본을 구별하지 않으므로 위 충돌 절차를 생략하지 않는다.
- 3.3.0은 `pdftotext`가 없을 때 PDF fallback에 실패할 수 있다. PDF 내용 기반 규칙은 추출 도구와 샘플 추출을 확인하고, 미지원이면 해당 규칙을 보류한다. OCR은 별도다.
- 종료 코드만 보지 말고 예상 대상 수, 실제 경로와 원본/결과 hash를 대조한다. 처리 0건을 성공적인 분류로 보고하지 않는다. CLI 부재 시 자동 설치나 다른 분류 엔진으로 전환하지 않고 반복 실행만 보류한다. 가능한 원본 조회·소수 파일 처리는 계속한다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| project: 소속/코드 공간 확인 | 대상 repo/호스트/실제 checkout | 등록 식별자, 확인된 그룹 관계와 경로 | 소속이 부족할 때 선택. 부재 시 명시된 자료 소속만 사용하고 추정 배치하지 않음 |
| Wiki: 자료 조회/수집/추적 | 주제와 원본 경로, 요청 동작, 소속·공유 범위 | 실제 raw/기록 경로 또는 후보와 원본 참조 | Wiki 조회/쓰기에 필수. [도구 연결](../implementations/tool-connections.md)의 Wiki 절과 대상 SKILL.md 적용. query/ingest/inventory 중 필요한 절차만 사용하며 inbox 처리에는 원본 보존 조건을 명시. 부재 시 원본 직접 조회·로컬 보관만 수행하고 미등록 표시 |

## 결과와 완료 판단

실제 원본/보관 위치, 수행 동작, 보존 확인과 등록/활용 결과를 구분한다. 등록했다면 경로를 다시 찾아 원본을 열 수 있어야 한다. 미처리 충돌·추출 실패·미등록·외부 보관 미실행은 남긴다. 원본 보관, Wiki 내용 수집과 실제 작업 완료는 별개다.
