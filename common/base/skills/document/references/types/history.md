# 작업 상태와 경험 연결

작업 목록과 상태, 과거 시도와 결정 이유를 찾거나 기존 작업 기록에 결과를 반영할 때 읽는다. 새 작업의 계획과 상태 체계는 작업 담당이 소유한다.

## 입력과 전제

대상 프로젝트와 작업 포인터, 조회 질문 또는 반영할 결과를 확인한다. BMAD 계획, 기존 state/exec 등 현재 작업이 사용하는 정본을 먼저 식별한다. 최신 날짜만으로 다른 작업을 선택하지 않는다.

## 수행 방법과 절차

1. 현재 상태나 남은 일을 물으면 작업 정본을, 과거 시도나 이유를 물으면 관련 경험을 조회한다. 도구 요청은 tool-connections의 해당 연결을 적용한다. 목록 조회는 제목, 상태와 다음 행동부터 확인하고 모든 본문을 읽지 않는다.
2. 경험은 후보를 검색한 뒤 필요한 상세와 원래 파일, 코드나 검증 결과를 확인한다. 과거의 시도와 실제 성공, 당시 결정과 현재 요구를 구분한다. 결과가 없다는 것과 검색이 불완전한 것을 구별한다.
3. 갱신 요청이면 확인한 수행, 검증, 미완료와 사용자 정정을 작업 정본의 기존 형식에 반영한다. 작업 기록과 기억 DB에 같은 상태를 독립 관리하지 않는다. BMAD 계획 변경이 필요하면 해당 연결의 기록 갱신 요청만 적용하고 구현을 시작하지 않는다.
4. 지식으로 남기는 요청은 knowledge 분기로 넘긴다. 이번 작업의 진행 상태를 재사용 지식으로 복제하지 않는다.

## 결과와 완료 판단

현재 상태의 정본과 경험의 출처, 충족과 미검증을 구분한다. 갱신했으면 해당 항목과 결과를 확인한다. 관측 저장을 작업 완료나 사용자 승인으로 표시하지 않는다.
