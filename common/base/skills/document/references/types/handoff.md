# 내부 인계와 재개 준비

같은 작업을 다음 LLM 세션에서 이어가기 위한 자료 확인과 갱신에 사용한다. 실제 세션 생성, clear, 전환과 전송은 session 담당이 소유한다.

## 입력과 전제

작업 정본 포인터, 현재 요구와 미반영 정정, 수신 환경을 확인한다. 기존 기록은 현재 위치와 형식을 유지한다. 새 session/round 폴더나 자체 인계 상태 규격을 만들지 않는다.

## 수행 방법과 절차

### 저장과 갱신

1. 작업 정본의 목표, 유효 요구와 제한, 전체 미완료, 검증 결과와 다음 행동을 확인한다. 미반영 변경은 도구 연결의 작업 기록 갱신으로 반영한다. 기억에만 있는 결정을 사용자 승인으로 간주하지 않는다.
2. 작업 위치와 실제 파일 상태를 대조한다. Git이면 branch, revision과 미커밋 범위를 확인하고 기록과 다른 부분을 밝힌다. 확인 시각만으로 최신성을 보증하지 않는다.
3. 첫 행동에 필요한 Wiki 지식과 경험을 찾고 기존 정본에 접근 위치와 읽을 이유를 연결한다. 전체 이력을 복사하지 않으며, 관련 자료가 없어도 확인된 작업 정본으로 준비할 수 있다.
4. 세션 맥락 보존도 요청되면 도구 연결의 Wiki 세션 기록을 적용한다. 이는 작업 상태 갱신의 대체가 아니다. 저장한 포인터와 미결을 확인하고 실제 전달 담당에 첫 행동과 함께 반환한다.

### 포인터 전달과 재개

1. 수신 환경에서 지정된 작업 정본에 접근한다. 포인터가 깨졌으면 다른 작업으로 대체하지 않는다. 후보가 여러 개면 식별을 확인한다.
2. 현재 요구와 전체 미완료, 관련 검증과 첫 행동을 읽는다. 부족한 과거 맥락에만 Wiki 세션 복구 또는 Claude-Mem 검색을 적용하고 오래된 기억보다 최신의 확인된 작업 요구를 우선한다.
3. 실제 checkout과 적용 정책을 대조해 첫 행동을 정한다. 기록이 충돌하거나 접근이 부족하면 영향받는 실행을 보류하고 확인 범위를 반환한다. 작업 실행과 호스트에서의 재개 성공 확인은 session 담당에 맡긴다.

## 결과와 완료 판단

준비한 정본 포인터, 유효 요구와 미결, 첫 행동과 필수 접근 상태를 제공한다. 준비 완료, 전달 완료, 실제 재개 성공과 전체 작업 완료를 구분한다. 준비 후 요구나 파일이 바뀌면 다시 대조한다.

## 실패와 복구

누락과 저장 실패는 원본을 보존하고 미반영으로 알린다. 일부만 저장됐으면 실제 반영 위치를 확인해 남은 부분만 처리한다. 인계 요약이나 기억 검색으로 없는 요구와 이력을 복원하지 않는다.
