# 위치와 보관 정책

자료 소속, 정본 위치나 공유 범위가 불명확하거나 변경될 때 읽는다. 외부 도구의 폴더, ID와 저장 형식을 재정의하지 않는다.

## 입력과 전제

현재 작업의 포인터와 도구 설정을 먼저 확인한다. tr-kit 경로 설정을 사용하는 자료는 [설정 규격](../../../profile-setup/references/config-schema.md)을 조회한다. 외부 도구가 이미 관리하는 위치를 이 설정에 맞춰 자동 이동하지 않는다.

## 수행 방법과 절차

1. 개인 지식, project/group 자료와 프로젝트 밖 운영 자료의 소속을 확인한다. 개인 knowledge를 common으로 대신 저장하지 않고 group의 공통성을 폴더 이름으로 추정하지 않는다.
2. 기존 정본과 실제 저장 경로, symlink 대상, 보관/공유 정책을 확인한다. BMAD의 repo 내부 기록도 선택한 기존 위치로 존중한다. 도구가 다른 위치를 쓴다는 이유로 자체 sessions/wiki 구조를 만들지 않는다.
3. 새 저장 위치가 필요할 때만 허용된 위치를 정한다. 대용량 원본은 확인된 assets나 기존 원본을 연결하고 보존/백업 여부를 구분한다. 설정 변경은 아래 연계에 맡긴다.
4. 실제 쓰기 범위를 확인한다. 자료 수집, 지식 반영이나 인계 요청을 원격 동기화 승인으로 해석하지 않는다. 접근이나 정책이 미확인이면 해당 쓰기만 보류하고 가능한 조회는 계속한다.

## 연계와 의존

| 대상과 요청 | 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| project: 소속과 공간 확인 | 후보 project/group과 경로, 부족한 정보 | 확인된 소속과 실제 경로 | 선택. 기존 입력으로 충분하면 생략, 부재 시 로컬 근거와 설정으로 확인 가능한 범위만 제공 |
| profile-setup: 경로와 공유 정책 설정 | 기존 설정과 요청 변경 | 실제 적용값과 검증 결과 | 설정 변경에 필수. 부재 시 변경 보류, 조회는 계속 |

필요할 때 현재 환경에서 확인한 대상 SKILL.md에 진입한다. 단순 설정 조회에는 profile-setup을 로드하지 않는다.

## 결과와 완료 판단

자료의 정본 위치, 소속과 보관 범위가 일치하는지 확인한다. 로컬 저장과 동기화, 파일 분리와 백업을 같은 완료로 보고하지 않는다.
