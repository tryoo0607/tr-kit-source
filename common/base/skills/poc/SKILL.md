# 기술 PoC

## 목적과 역할 경계

- 기술을 현재 프로젝트에 적용할 수 있는지 조사와 관측으로 확인하고 채택 판단에 필요한 결과를 정리한다.
- 실험은 합의된 대상과 범위에서 한다. 채택 승인, 운영 적용 및 구현은 각 요청의 승인 범위를 따른다.

## 입력과 전제

- 대상 기술과 프로젝트, 확인할 질문, 제약, 가능한 실험 환경, 기존 결과와 보고서 위치를 확인한다. 대화와 기존 기록을 재사용한다. 대상이 없으면 먼저 묻는다.

## 수행 방법과 절차

1. 현재 코드, 프로젝트 요구와 대상 버전의 공식 자료를 조회한다. 기존 근거를 대조해 실측으로 판단할 질문, 예상 결과, 성립 여부를 가를 기준을 정한다. 필요한 선택은 Ask me로 연결한다.
2. 합의 범위의 가장 작은 실험을 실행한다. 환경과 버전, 입력, 측정 결과와 한계를 남긴다. 실험이 준비되지 않았거나 권한 밖이면 확인한 사실과 실측하지 못한 범위를 보고한다. 대조가 필요한 대안은 같은 조건에서 비교한다.
3. 관측한 결과와 추천을 구분해 보고서 작성으로 넘긴다. 기존 PoC 문서가 있으면 그 문서의 근거와 버전을 재사용한다. 새 결과가 기존 판단을 바꾸면 달라진 판단과 이유를 남긴다.

| --- | --- | --- |
| [기술 문서 조회](../ext-find-docs/SKILL.md) · [BMAD 조사](../ext-bmad-deep-recon/SKILL.md) | 대상 버전·확인 질문 또는 비교할 여러 기술과 프로젝트 제약. 출처가 붙은 근거를 얻는다. | 버전별 공식 기능 확인 또는 넓은 기술 조사가 필요한 경우 각각 사용한다. |
| [Ask me](../../references/ask-me.md) · [BMAD 기술 설계](../ext-bmad-architecture/SKILL.md) | 사용자가 정할 실험 조건 또는 기술 선택과 프로젝트 구조. 필요한 합의나 설계 판단을 얻는다. | 사용자 선택 또는 구조에 영향을 주는 기술 비교가 필요할 때 사용한다. |

## 결과와 완료 판단

- 검증한 질문마다 조사 근거, 실제 관측, 미확인 범위와 채택·추가 검증·보류 권고를 대조한다. 실측과 보고서 작성 상태, 갱신한 문서 위치를 전달한다.
