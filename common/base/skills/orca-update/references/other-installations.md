# 기타 설치 방식

AppImage와 systemd 조합이 아닌 것으로 확인됐을 때만 읽는다. 대상별 공식 수단을 선택하며 Linux AppImage 절차를 다른 설치 형태에 적용하지 않는다.

## 수행 방법과 절차

1. 실행 중인 제품과 설치 출처를 확인한다. runtime이 제공하는 remoteUpdateSupport와 현재 공식 문서의 지원 여부를 대조한다. 지원 표시만으로 업데이트 요청 API나 CLI 이름을 추측하지 않는다.
2. 아래 조건에 맞는 실제 설치 관리 수단을 선택한다. 대상에서 조회한 정확한 패키지, 채널과 제품만 변경한다.

| 설치 형태 | 사용할 수단과 확인할 조건 |
|---|---|
| 공식 원격 updater | 현재 runtime과 버전 일치 guide에서 실행 및 결과 조회 수단이 확인될 때 재사용 |
| Debian 또는 RPM 패키지 | 공식 release 패키지와 기존 apt/dnf 등의 패키지 관리 수단. 종료 필요 여부와 권한 확인 |
| macOS Homebrew cask | 기존 설치가 해당 cask인 경우 공식 cask upgrade. 다른 설치를 새 cask로 전환하지 않음 |
| macOS 또는 Windows 설치 앱 | 공식 업데이트 흐름과 지원되는 관리 수단. CLI에서 지원하지 않으면 GUI나 사용자 조작이 필요한 범위를 명시 |
| source checkout 또는 사용자 제작 launcher | 기존 저장소의 설치 및 운영 지침. git pull이나 의존성 전체 갱신을 추측해 실행하지 않음 |

3. 해당 설치 방식에서 재시작을 견딜 실행 및 결과 회수 경로, 기존 파일 보존과 호환성을 확보한 뒤 실행한다. 제품이 공식으로 소유한 updater를 재구현하지 않는다. 확인된 수단이 없으면 업데이트 불가로 보고하고 다른 서버 작업과 구분한다.
4. 설치 명령 성공 뒤 본문의 실제 runtime 버전, 재접속, workspace와 terminal 동작 검증을 모두 수행한다. 자동으로 새 로그인을 하거나 계정과 profile을 재설정하지 않는다.

## 결과와 완료 판단

지원되는 업데이트 수단, 실행과 검증 결과를 반환한다. GUI 또는 권한 의존으로 미실행이면 사용자가 해야 하는 구체적인 조작과 아직 검증하지 못한 항목을 남긴다. 목록에 표시된다는 이유만으로 자동 업데이트 지원 대상으로 보고하지 않는다.
