# Orca 업데이트

## 목적과 역할 경계

대상 선택, 설치 방식에 맞는 업데이트와 완료 검증을 소유한다. 호스트와 터미널 접근은 기존 orca-cli, 설치와 재시작은 대상에서 확인한 제품 및 OS 관리 수단을 재사용한다. 서버 목록, 주소, 계정과 인증정보를 스킬에 내장하지 않는다.

## 입력과 전제

사용자가 지정한 대상, 버전 또는 채널과 실행 범위를 확인한다. 대상이 없으면 호스트 목록을 보여주고 선택을 받은 뒤 변경한다. 이미 지정한 대상과 승인 범위는 다시 묻지 않는다. 버전 지정 없는 업데이트는 공식 최신 stable을 선택하고 draft와 prerelease는 제외한다. 목록 등록, 현재 연결 가능, 업데이트 지원 여부는 서로 다른 상태다.

## 수행 방법과 절차

1. 아래 연계 계약에 따라 orca-cli를 적용해 실행 파일과 현재 버전의 guide를 확인한다. `host list --json`에서 이름과 실제 selector를 얻고, 지정하지 않은 경우 로컬을 포함한 목록을 제시한다. 저장된 원격 호스트를 오프라인이라는 이유로 목록에서 빼지 않는다. 선택한 대상만 status로 조회하며 pairing URL과 토큰은 출력하지 않는다.
2. 선택한 각 대상의 현재 runtime 버전, 설치 방식, 실제 실행 파일과 서비스, CPU architecture, 실행 중 작업, 필요한 호스트 가드와 권한을 확인한다. 대상 CLI와 현재 배포의 공식 문서로 지원 명령을 확인한다. 설치 방식이나 서비스 이름을 다른 서버에서 복사하지 않는다. 실행 중 작업을 끊어야 하는데 중단 승인이 없으면 해당 대상만 대기한다.
3. 목표 release와 정확한 asset, 교체 범위, 중단 영향, 기존 실행 파일 보존, 실패 시 접근 및 복구 수단을 구체화한다. 최신 버전 요청은 이번 실행에서 release를 한 번 확정해 기록한다. RC, downgrade, 프로필 변경과 전체 OS 패키지 업그레이드를 임의 추가하지 않는다.
4. 설치 방식별로 아래 분기를 적용한다. 원격 업데이트 기능은 실제 runtime 지원과 현재 공식 절차가 확인될 때만 사용한다. 단순한 terminal send 수락은 업데이트 완료가 아니다. 여러 대상은 하나씩 실행하고 아래 완료 검증이 통과해야 다음 대상으로 진행한다.
5. 재시작 후 기존 연결로 다시 status를 조회해 runtime ready/reachable, graph ready와 목표 appVersion을 확인한다. 저장된 host selector로 다시 찾으며 재시작 전 terminal handle을 재사용하지 않는다. 실행 파일만 교체됐거나 다른 중복 runtime이 응답한 상태를 성공으로 판단하지 않는다. 서비스 MainPID와 연결 endpoint의 실제 프로세스를 대조한다.
6. 기존 프로젝트와 workspace를 조회해 사전 식별자와 경로가 유지됐는지 대조한다. 확인된 대상의 검증용 shell에서 예측 불가능한 이번 실행 marker를 출력하는 무해한 명령을 실행하고, 새 terminal handle로 읽은 독립된 출력행이 marker와 정확히 일치하는지 확인한다. 명령 입력 에코나 과거 scrollback의 문자열 일치는 성공 근거가 아니다. 이 probe를 위해 에이전트, 새 Git checkout, repo 등록이나 pairing 재생성을 하지 않는다. 만든 검증용 shell만 사용 종료하고 기존 탭은 유지한다.
7. 서비스 재시작 횟수와 최근 로그를 확인해 간격을 둔 두 번 이상의 관측에서 재시작 반복이나 시작 오류가 없는지 대조한다. 설치, 재시작, 재접속, 버전, workspace와 실제 probe 결과를 대상별로 보고한다. 관측하지 못한 항목은 미검증으로 남긴다.

## 연계와 의존

| 대상 | 적용 조건과 입력 | 필요한 결과 | 의존과 부재 시 동작 |
|---|---|---|---|
| [orca-cli](../orca-cli/SKILL.md) | 호스트 목록, status, 기존 workspace와 shell 접근. 요청 조작, 실제 host selector, workspace/terminal 식별자와 승인 범위를 전달한다 | 호스트 식별, 버전 일치 guide, 읽기 결과, 명령 수락 receipt와 실제 완료 출력 | 필수. 부재나 미지원은 해당 접근을 보류하며 임의 API나 내부 DB 조작으로 대체하지 않는다 |
| 제품과 OS의 기존 업데이트 수단 | 대상에서 확인한 설치 형태와 공식 release, 실행 권한과 업데이트 범위 | 교체 결과, 서비스 상태와 복구 가능한 이전 파일 | 변경에 필수. 권한 거부나 지원 절차 부재는 해당 대상 중단. 다른 호스트의 sudo 설정이나 연결 정책을 바꾸지 않는다 |

## 실패와 복구

연결 끊김이나 timeout이면 같은 작업의 unit, 실행 기록과 파일 상태를 먼저 확인한다. 확인 없이 설치를 재전송하거나 동시에 두 업데이트를 시작하지 않는다. 실패 대상 뒤의 서버들은 미실행으로 보고한다. 재접속 실패 시 사전 확보한 기존 관리 경로만 사용하며 ACL이나 인증을 변경하지 않는다.

이전 실행 파일 보존은 데이터 형식 호환성을 보증하지 않는다. 자동 downgrade나 프로필 DB 복원을 하지 않으며, 복구가 필요하면 확인된 호환성과 승인 범위 안에서 수행한다. 업데이트 요청을 다른 세션 강제 종료, 데이터 삭제나 자동 로그인 승인으로 확대하지 않는다.

## 결과와 완료 판단

대상별 변경 전후 버전, 목표 release, 실제 교체 파일, 서비스, 재접속, workspace 대조, terminal probe와 잔여 오류를 제시한다. 모든 필수 검증을 통과한 대상만 완료로 표시한다. 이미 목표 버전이면 변경 없이 현재 동작을 확인했다고 보고한다. 소스의 스킬 작성과 실제 설치, 실제 서버 업데이트는 별도로 보고한다.
